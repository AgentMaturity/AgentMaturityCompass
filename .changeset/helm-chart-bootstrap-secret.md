Deployment pack hardening (P0-14, slices S1 and S2). Breaking for Helm chart users: chart `deploy/helm/amc` is now 0.2.0 (its appVersion follows the package version).

- The chart renders no Secret by default. Create the `amc-bootstrap` Secret before `helm install`, or the Studio pod cannot start. Chart 0.1.0 always rendered that Secret with published `change-me-*` values. With `bootstrap.createSecret=true` the chart renders it from `bootstrap.values`: all five values are required, a value that starts with `change-me` (any case) is refused by the template and by `values.schema.json`, and the Secret carries `helm.sh/resource-policy: keep`.
- `replicaCount` other than 1 is refused (the workspace has a single writer), and the rollout strategy is `Recreate`. `image.digest` renders `repository@digest`; `image.requireDigest=true` refuses to render without a digest.
- The chart ConfigMap sets `AMC_CORS_ALLOWED_ORIGINS` to the chart's own Service origin followed by `env.AMC_CORS_ALLOWED_ORIGINS`. The Studio pod, the `helm test` pod and the raw `deploy/k8s` Deployment no longer automount the service-account token, which collided with the read-only `/run/secrets` mount.
- `helm test` claims a one-time LAN pairing code from the optional Secret `<release>-amc-test-pairing` (key `code`, minted with `amc pair create` in the Studio pod), logs in as the bootstrap owner, runs one stub-provider native task and asks Studio to verify it. The chart passes `env.AMC_EXPECTED_MONITOR_FINGERPRINT` (the operator pins the monitor key after the first bootstrap) and rolls the pod when its ConfigMap changes. The probe exits 0 on `externally-anchored` (status `verified`) or `anchored-prefix` (status `verified-prefix`) and fails on anything else.
- The deploy-pack scripts (`governed-turn-probe.mjs`, `deploy-verify.mjs`, the rollback drill and check, `deploy-pack-check.mjs`, `validate-assets.mjs`, `credentials-presence-check.mjs`) run when started through a symlink, as the Helm test's ConfigMap mount starts the probe (a guard on the unresolved path would exit 0 without probing). The probe takes `--pairing-code-file` and waits for `/healthz` inside `--ready-timeout-ms`; the rollback drill mints a pairing code inside each container.
- Upgrading from 0.1.0: annotate the existing `amc-bootstrap` Secret with `helm.sh/resource-policy=keep` first, or Helm deletes it. A workspace bootstrapped by chart 0.1.0 used a published vault passphrase. AMC has no command that changes a vault passphrase, and this release does not repair such a workspace.
- New npm scripts: `check:deploy-pack` (offline checks, plus helm and kubeconform when installed), `deploy:rollback-drill` (container A to B to A drill), `deploy:verify` (one leased gateway turn whose receipt is checked against a pinned monitor key) and `check:credentials-presence` (prints only whether each release credential is present).
- `railway.json` and `vercel.json` stay documented but unqualified: they serve only the standalone API and cannot pass `deploy:verify`.
- Studio's native-task verify works in a running deployment. The gateway Studio runs keeps its ledger session open, so the complete-ledger check could never pass. Studio now returns the new state `anchored-prefix` (with `verificationScope`) when the task's session is closed and sealed, every recorded row and sealed session verifies, the monitor key is pinned, and the only unfinalized sessions are named unended legacy sessions. It is never `externally-anchored`; `verifyAgentRun` reports it as `prefixVerified` with `ok: false`, and `amc agent-loop verify` keeps the complete-ledger verdict. Any error or unexpected verifier result is `failed`.
- Nine maintenance scripts (`check-citations`, `check-regulatory-currency`, `human-first-use-capture`, `human-first-use-intake`, `human-first-use-observer`, `package-lint`, `per-file-coverage`, `qualify-platform`, `source-quality`) now run when started through a symlink.
