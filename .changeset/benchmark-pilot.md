Benchmark example only, no runtime or CLI change: the 20-task benchmark pilot (P1-47) in `examples/harness-comparison/pilot/`. It adds a plan committed before any trial, 17 new tasks (5 coding, 6 regulated-document on fictitious records, 6 fin-ops on P1-19's synthetic payment provider) beside the 3 existing coding tasks, and independent oracles that import nothing from AMC. Fin-ops oracles verify the provider's hash-chained transaction log against the head the adapter recorded. They fail when an agent reports a payment the log does not hold, and when one idempotency key or reference has two effects. The target adapter runs `amc-native` on the host and runs Pi 1.0.4 only inside a container: read-only root, no capabilities, non-root, and an internal network whose only peer is a relay for the trial's services. A Pi target runs with or without AMC's Pi extension, in the documented default or the tuned setup fixed in the plan. The pilot also adds the container's escape checks, a scripted overhead micro-benchmark and `analyze.mjs`, which reads only `report.json` files, keeps failed attempts in cost, leaves missing usage unknown and produces no ranking. Scripted runs debug the bindings and are never results. Real-model lanes need Sid's credentials, spend cap and model choice, and were not run. See docs/BENCHMARK_PILOT.md. The existing three-harness coding workflow is contained the same way. `codingOracle.mjs` runs the model-written solution only in a pinned container (no network, read-only root, the nobody user, no mounts). `codingAdapter.mjs` runs Pi only in a container. Without a container runtime both refuse with "not measured: containment unavailable" and never run on the host. The oracle's command line takes a third argument, the containment file. `codingMaterialize.mjs` requires a `containment` block in the reviewed configuration and passes it.
