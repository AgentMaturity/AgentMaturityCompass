A4 project records gain published verification rules, an export format and a bundle slice (P1-63). A4 stays behind `AMC_A4_PREVIEW=1`.

- `spec/ACCEPTANCE_RULES.md` has an "A4 project record" section: the chain, audit-row (with the stored-row hash pre-image), envelope, side-row, gate-binding, intent and bound-item rules, the published superseding set, the separation-of-duties, quorum and self-approval rules, and a statement that AMC's canonical form is not RFC 8785. A new contract `amc.a4-record/v1` (`spec/schemas/v1/a4-record.schema.json`) carries one project's rows exactly as stored. Seven normative fixtures with their expected verdicts are in `tests/fixtures/contracts/a4-record/`.
- With `AMC_A4_PREVIEW=1`, `amc bundle export` (and so `amc certify`'s internal bundle) adds each A4 project of the run's agent as an `amc.a4-record/v1` file, `a4/<projectId>.json`, and `a4/index.json`, which names each project's head and `containsSyntheticExamples`; the signed manifest lists them with every other file. A project is the agent's by the receipt signed for its first audit row, never by the head row's editable `agent_id`. Each project's chain is verified whole before it is exported. A project that does not verify, has lost its head row or names two agents refuses the export (and certification) with `A4_INTEGRITY_FAILED`; a project no signed receipt attributes is verified as well. The bundle's ledger is unchanged, and so is a bundle exported without the flag or for an agent with no A4 project. A certificate copies none of the A4 records.
- A gate is consumed only while the commit's own `ts` is before its expiry, the instant a verifier counts the quorum at.
- `verifyA4Chain`, and so `GET /api/v1/a4/projects/:id/verify` and `amc verify all`, now also recompute each gate's intent from the rows it binds (`A4_INTENT_MISMATCH`), and require a gate's bound item set to be exactly the stage's `A4_BOUND_ITEMS` (`A4_BOUND_ITEMS`). The verify route refuses a request body (400); it already refused any query parameter, `?trustList=` included (400 `QUERY_INVALID`).
- Library functions with no command or route yet: `verifyA4Bundle` checks an `.amcbundle` A4 slice or an `amc.a4-record/v1` file under the caller's trust only, and is anchored only when every record's carried monitor key is admitted (its CLI entry point is `amc a4 verify --trust-list`, P1-65). `buildA4BinderSlice` writes a project's A4 binder slice under `.amc/audit/binders/exports/` (no route serves it yet; absent without `AMC_A4_PREVIEW=1`). The binder slice holds digests, statuses, hashed principals and hashed non-ledger ref ids (ledger row ids are kept as they are), never specification text, comment bodies or decision reasons; it must pass the binder PII scan and a key-material scan, and it is signed as the new artifact kind `a4-binder` and recorded in the transparency log under the new kind `a4-binder`.
- Docs: `docs/A4_FORGE.md` (journey, glossary, claims per stage, what each record proves, the single-user rule, the deployment boundary, erasure and the API header recipe, whose CSRF token comes from `GET /auth/me`) and `docs/adr/013-a4-forge-spine.md`.
