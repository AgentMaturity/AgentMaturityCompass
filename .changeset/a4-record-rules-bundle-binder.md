A4 project records can be checked offline (P1-63). A4 stays behind `AMC_A4_PREVIEW=1`.

- `spec/ACCEPTANCE_RULES.md` has an "A4 project record" section: the chain, audit-row, envelope, side-row, gate-binding, intent and bound-item rules, the published superseding set, the separation-of-duties and self-approval rules, and a statement that AMC's canonical form is not RFC 8785. A new contract `amc.a4-record/v1` (`spec/schemas/v1/a4-record.schema.json`) carries one project's rows exactly as stored. Seven normative fixtures with their expected verdicts are in `tests/fixtures/contracts/a4-record/`.
- `amc bundle export` adds the A4 slice of the run's agent to the `.amcbundle`: every A4 project of that agent, its rows as stored and the ledger rows they name. The bundle's ledger is extended to stay one unbroken prefix. The signed manifest lists the slice under `a4` (each project's exported head and `containsSyntheticExamples`). A bundle whose agent has no A4 project is unchanged.
- `verifyA4Bundle` checks an `.amcbundle` A4 slice or an `amc.a4-record/v1` file, under the caller's trust only. It reads the file once and recomputes every digest from the exported bytes without a key. It reports scope, freshness (a decision not bound to its gate's request digest), completeness (missing side rows, dangling `ledger_event` refs) and satisfaction (separation of duties, quorum). A self-approved decision gives `not-evaluated` `SINGLE_USER_WORKSPACE`, and a gate that binds a `synthetic_example` ref gives `not-evaluated` `SYNTHETIC_VALUES`. With no trust list it reports integrity only.
- `verifyA4Chain`, and so `GET /api/v1/a4/projects/:id/verify` and `amc verify all`, now also recompute each gate's intent from the rows it binds (`A4_INTENT_MISMATCH`). They refuse a bound item set that holds a gate-derived item or an environment fact (`A4_BOUND_ITEMS`). The verify route refuses a request body (400); it already refused any query parameter, `?trustList=` included (400 `QUERY_INVALID`).
- `buildA4BinderSlice` writes a project's A4 binder slice only under `.amc/audit/binders/exports/`: digests, statuses and hashed principals, never specification text, comment bodies or decision reasons. The slice must pass the binder PII scan and a key-material scan. It is signed as the new artifact kind `a4-binder` and recorded in the transparency log under the new kind `a4-binder`.
- Docs: `docs/A4_FORGE.md` (journey, glossary, claims per stage, what each record proves, the single-user rule, the deployment boundary, erasure and the API header recipe) and `docs/adr/013-a4-forge-spine.md`.
