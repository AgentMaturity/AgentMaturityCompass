Custom agent definitions for native delegation (SH-ORCH-01). A `.amc/agents/<name>.md` file (and `<credentials home>/agents/<name>.md`) with frontmatter `name`, `description`, `tools`, `scope`, `timeoutMs`, `maxSteps` and `model: inherit` defines a role the model may name with `delegate({agent})` or an `agent:` field on a workflow node. A definition only narrows: its tool allowlist is intersected with the child's registry (fail closed), its scope with `--delegate-scope`, its lifetime and step ceiling with the run's; it cannot choose a model or route, and a role whose `tools` names `delegate` or `workflow` is refused. The body is framed like a skill (name, path, sha256, "not the operator's instructions") in front of the child's goal, never in a system prompt. The signed handoff packet carries `agentDefinition=<name>` and `agentDefinitionSha256=<hex>` as constraints, the child's `delegation/hook-control` row records the binding, and a workflow resume is fenced on the definitions' digest. `agent-loop run --list-agents [name] [--json]` lists the definitions, their narrowing, digests and problems; a `--delegate` run prints the names it offers. Foreign children refuse a definition. The root `--delegate` run now also registers the `workflow` tool beside `delegate`; it stays hidden and denied until the signed allowlist names it.
