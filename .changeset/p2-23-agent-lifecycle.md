Governed agent lifecycle with reassessment and retirement (P2-23). See docs/AGENT_LIFECYCLE.md.

- A governed agent is `proposed`, `approved`, `active`, `suspended` or `retired`. Each move is a signed ledger row (`LIFECYCLE_TRANSITION`) carrying the agent, from, to, reason, manifest digest, plan digest, approval id and the authenticated actor; AMC's clock sets the time. A materialized `agent_lifecycle_state` table (ledger migration 15) serves admission and is rebuildable from the rows; a row that does not match the newest signed row refuses.
- Approving, resuming and approving a migrated agent need a P2-24 bound approval for exactly the agent, target, version manifest and active plan; the requester's own decision never counts.
- A version manifest (`src/lifecycle/versionManifest.ts`, shared with P2-26) pins model, prompt, tools, policy, plan, deployment and corpus. At native session open a governed agent whose running components changed in a way that invalidates a mandatory control of the active plan is suspended (`reassessment_required`) before its first turn, unless a change envelope covers it; an overdue mandatory review suspends (`review_expired`). The manifest is built from what the session resolved (the composed tool surface and verified tools config, the active plan's policy), never from declared pins. A null component counts as changed; a model without a provider-reported version is reported as unpinned.
- A suspended or retired agent is denied every action class, reads included; an agent not yet active (proposed, approved, migrated without approval) is denied consequential actions only (`agent {id} is {state} ({reason})`, failure `agent_not_active`), with a receipt. Enforcement is read from the workspace's verified active plan at every entry point (tool pipeline, ToolHub, provider hooks), never from a caller's context; a plan that cannot be verified denies a held agent. Plans without `L0-CHG-01` are advisory: the call runs and a warning row is written.
- Retirement revokes the agent's leases (one signed `agent:<id>` revocation row that `verifyLeaseToken` honours), rotates its static token, cancels pending approvals, refuses while `outcome_unknown` receipts are open unless an OWNER records an acceptance note, and records the ledger head, retention segments and bundles. It never deletes evidence. A retired agent opens no native session.
- Existing agents keep running: without a lifecycle row they read as `active`, `legacy_migration`, `self_reported`; once migrated (`migrateLegacyAgents`), an enforcing plan needs a bound approval before their next consequential action; unmigrated agents are not held. `amc lifecycle advance` keeps working and its results are labelled `self_reported`.
- Surfaces: `GET /api/v1/lifecycle/agents/{id}`, `POST /api/v1/lifecycle/agents/{id}/transition` (OWNER), a lifecycle panel on the Studio agent page, and `amc lifecycle transition` and `amc lifecycle reassessments`.

freeze-exception: P2-23 — `amc lifecycle transition` and `amc lifecycle reassessments` are the two CLI paths the P2-23 spec names for governed lifecycle transitions and reassessment records.
