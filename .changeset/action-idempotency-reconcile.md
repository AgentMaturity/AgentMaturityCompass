Consequential actions get idempotency keys, and an operator can clear a blocked agent: `reconcile()` asks the system of record what happened, and `amc action resolve` records an operator's dual-control resolution (P1-04).

- Every authorization record now carries an idempotency key AMC mints before dispatch (`amc1_` and 26 Crockford base32 characters, 128 random bits). The same key is on the journal row, the intent and every action receipt, including the signed `v: 2` receipt's `idempotencyKey`; a key used twice in a workspace is refused. The intent also records the bound facts (amount, recipient, destination, resource).
- The signed tools config accepts an optional `effects` declaration per tool: `repeatable`, `idempotency` (`http-header` or `argument` carrier and its name) and `reconcile` (`adapterId`). With the header carrier, tool bodies receive `idempotencyKey` and `idempotencyHeader`, and `http.fetch` sends the key on that header, replacing any value passed. With the argument carrier, AMC overwrites the named argument with the key, keeps a model-supplied value as agent-supplied metadata, and leaves the argument out of the arguments digest; it may not be a binding field.
- A consequential call with the same tool and arguments as an execution that is `outcome_unknown`, from any agent in the workspace, is denied `possible_duplicate_of:<executionId>`. A block's denial reason now names the command that settles it.
- `reconcile(executionId, { workspace, adapters })` settles an `outcome_unknown` execution, or a completed one with incomplete evidence, from the adapter the tool's signed `effects.reconcile` names. It never calls the tool body. `applied` with the bound facts settles `completed`/`applied`; `applied` with other facts settles `completed`/`applied` with the evidence still incomplete, records a signed incident and keeps the agent blocked; `not_applied` settles `completed`/`not_applied`; `unknown`, an adapter error, a 30 s timeout or a `not_applied` past the adapter's retention window changes nothing and backs off from 1 minute to 1 hour in that process. An adapter's answer is labelled observed.
- `amc action resolve <executionId> --effect applied|not_applied --operator <id> --note <text> [--external-ref <ref>]` files an approval request for the exact receipt and statement under the execution's action class and its quorum; once someone other than the operator approves it, the same command with `--approval <id>` writes a `completed` receipt with `resolution: "operator"` on a `SELF_REPORTED` evidence row, consumes the approval and unblocks the agent. The resolution is self-reported: AMC did not observe the effect. It cannot contradict an effect the tool declared. The TypeScript API is `requestManualResolution` and `resolveManually`, exported with `reconcile` and `mintIdempotencyKey`.
- `resolveManually`, `requestManualResolution` and `reconcile` refuse agent mode. Action receipts gain `resolution` (`adapter`, `operator` or null) and `idempotencyKey`; only a reconciliation leaves `outcome_unknown` or marks a completed execution's evidence complete again, and its `v: 2` receipt's `reconciliation.fromReceiptId` must name the receipt it follows. `actionEvidenceCoverage` reports operator-resolved calls as `operatorResolved`, never as linked.
- The in-memory `IdempotencyStore` in `src/enforce/idempotency.ts` is deprecated.

AMC never promises exactly-once delivery. Receipt signatures are checked against the workspace's own monitor keys: a local audit trail, not a portable verdict.
