A4 Adapt runs AMC's own producers for the compiled plan, behind the A4 preview (`AMC_A4_PREVIEW=1`). Adapt asks 20 questions: `markets` and `stations`, carried from Aspire by Understand and marked `CARRIED_STALE:<id>` when they no longer equal Aspire's; `audiences` and `languages` (required); `workflows`, `preferences`, `accessibility`; the compiler's facts `jurisdictions` (depends on `markets`; left empty it uses the carried markets), `primaryStation`, `domains` and `useCases` (depend on `stations`), `roles` and `riskClass` (depend on `jurisdictions`), `entityTypes` (depends on `jurisdictions` and `stations`) and `dataClasses`; `excludedUses`, `dataResidency`, `dataRetention`, `processors` and `deploymentNeeds`. A fact answer is a list of catalog terms (or one term); an empty or `unknown` answer stays unknown (null). Understand builds the deployment profile (every fact `provenance: asserted`, source `a4:<projectId>@r<revision>`) and compiles it with `compilePlan`, recording the applicability per requirement with reasons and missing facts, each citation's `appliesWhen`, the register entries of the stations with `verified` as recorded, the reporting-clock candidates (all `NEEDS_CLASSIFICATION`, with `CLOCK_REVIEW_STATUS`), the signed configs' states and the active plan's head; a profile or catalog the compiler refuses is recorded by its code. Explain quotes the catalog's notice verbatim (D-08). Propose freezes the profile, the plan, the diff against the project's previous proposal, the operating scope and the declared data handling (`enforcement: none`, P2-01, P2-02).

Build signs the proposed plan with `signPlan` (`CONTROL_PLAN`, checked against this workspace's keys) and refuses a plan weaker than the plan this project put in force (`POLICY_WIDENING_REFUSED`). Review evaluates every requirement with `evaluateControl` over the admitted evidence (none is loaded yet, so each control is `not_evaluated` with `NO_EVIDENCE_LOADER`), writes the set signed with `writeSignedControlResults` to `a4-projects/<projectId>/control-results/<sha256>.json`, reads it back verified, and records the counts (`pass`, `fail`, `not_evaluated`, `not_applicable`, `unresolved`; never a percentage). A set that does not verify locally is `not_evaluated` (`CONTROL_RESULTS_NOT_VERIFIED_LOCALLY`), and Review fails with the signing error's code when the set cannot be signed (agent mode, a locked vault). Review also records the `amc.a4-conformance-statement/v1` built from the stored, verified results (`src/a4/a4Conformance.ts`; its claim is the weakest of the envelopes rebuilt from those results, and an unverified set gives a not-evaluated one); an owner's out-of-scope acknowledgement of `plan_unresolved` lists the requirements in `ownerOutOfScope` while they stay in `counts.unresolved`, and readiness and the card read that acknowledgement live.

Completing Adapt in a regulated project runs the new effect `a4.adapt.activate_plan` (`catalog.plan.activate`, `SECURITY`): an owner opens it once the completion gate has its quorum, `signPlan` files the plan review (with the two-distinct-key floor when regulated), project approvers decide it from the A4 card, `complete` verifies the grant and re-checks membership and separation of duties without consuming it, and `activateControlPlan` consumes it as `activate-<digest32>`, which `EFFECT_FINISHED` records. A workspace has one active plan for every agent, so activation replaces it and refuses a plan weaker than it; `plan_activated` names an active plan of another profile (`REPLACES_ACTIVE_PLAN`). A non-regulated project completes with the plan signed and not activated (`PLAN_SIGNED_NOT_ACTIVATED`); an owner may still open the effect. An A4 effect can now be `optional`: `complete` runs it only when an owner opened it on the gate. Every revision now binds `plan.journalEntrySha256` (the active plan journal's head) and `plan.lockDigest` (the shipped catalog's lock): any activation makes an open gate `RESOURCE_DRIFTED`, and a revision recorded before this release binds both as null, so its open gates read `RESOURCE_DRIFTED` once until a new revision is recorded.

Adapt's readiness items: `ask_complete`, `understanding_confirmed`, `profile_facts_complete`, `plan_proposed`, `plan_compiled`, `plan_no_missing_facts`, `plan_conflicts_resolved`, `plan_unresolved` (WAITING while a mandatory requirement is unresolved; owner-acknowledgeable, then `OWNER_OUT_OF_SCOPE`, never READY), `plan_lock_drift`, `plan_signed`, `conformance_statement`, the integrity item `adapt.control_results_signature`, `plan_review_quorum`, `plan_activated`, `adapt.plan.nativeSessionsAllowed` (Studio native tasks with workspace tools started after activation run under a P1-67 lease; tasks started before it, CLI agent sessions and delegated children are denied), `configs_trusted`, `clocks_classified`, `required_entries_satisfied` (each entry's kind; a role vote is an acknowledgement, never a review), `regulatory_sources_status` (always WAITING with `EXPERT_REVIEW_PENDING` and `KEY:D-08`; informational), `data_handling_declared` and `lifecycle_bridge`, which lists Adapt's `testing → staging` bridge rows (`integration_tests_passing`, `security_review_signed`, `deployment_plan_approved`) for the A4 lifecycle wrapper. Studio's Adapt view adds Applicability, Plan diff, Blockers (grouped by blocker kind), Plan activation and Conformance statement cards.
