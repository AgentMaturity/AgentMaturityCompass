Workflow `verify` nodes and a headless workflow run (SH-ORCH-03). A plan may contain `{kind: "verify", id, runAs, goal, of, agent?}`: a delegate reviews the output of leaf `of` (which must be in an earlier stage of an enclosing pipeline; forward, sibling and composite references are refused as data) and the plan continues only on a verdict line `VERDICT-<token>: pass` as the last non-empty line, where the token is minted per dispatch so the reviewed text cannot pass itself. A missing, repeated or contradictory verdict fails the node, recorded as `failed` in the signed `workflow/progress` rows; on pass the reviewed output carries forward. `amc agent-loop run --delegate --tools workspace --workflow-plan <file> [--workflow-run-id <id> --session <id>]` runs a reviewed plan file (a regular file inside the workspace, at most 256 KiB) headless as in-process children with no model turn, under the same admission as `--goal-rounds`, reports the result as `workflow` in the run summary, fails when the plan did not succeed, and resumes a run left unsealed by `--keep-open` without dispatching succeeded nodes again. Documented in docs/NATIVE_WORKFLOWS.md.
