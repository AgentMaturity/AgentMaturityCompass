Casebook and experiment results are now bound to the evidence they came from, and the experiment gate no longer passes on missing, unverified or insufficient evidence (GAP WP03, WP05, WP07).

- Casebooks: a case with no execution evidence, no tool action to verify, or no readable correlation ratio is `unavailable`, never a pass; a missing correlation ratio no longer reads as 1. Named tool requirements match the recorded tool name exactly (new default cases list none). Every tool action receipt is verified with the ledger's receipt verifier. Usage is read with `measuredUsage`, so totals, components and aliases count once and partial usage stays unknown; a legacy window no longer divides its tokens equally across cases. Bound runs (`trial`) count only signed rows stamped with the case execution identity (`caseExecution`: casebook, case, case file digest, trial, configuration digest).
- Experiments: an empty casebook, or no case determinate on both sides, is refused instead of sealed as a zero report. A same-agent legacy baseline window now ends where the candidate window starts. Reports are schema v2: casebook digest, side identities and ranges, paired/excluded counts, tokens as the cost unit, cost per success `null` with no success or incomplete usage, a paired bootstrap interval (or `insufficient`), the raw `meanDifference`, and `effectSize` as the standardized paired effect. `effectSizeDifference` is deprecated in favour of `meanDifference`. Legacy reports stay readable.
- Gate: `amc experiment gate` and the bundle gate's `requireExperimentPass` use one evaluator (`evaluateExperimentGate`) returning pass, fail or inconclusive; legacy unbound reports, fewer than `minPairedCases` (default 3) paired cases, an insufficient interval and unknown cost are inconclusive, and a zero baseline cost no longer skips the cost check. `gateExperiment` verifies the report seal, the casebook and the currently admitted candidate before deciding `promote-candidate`, `keep-baseline` or `abstain`. The bundle gate also accepts `denyIfRegression`, `candidateConfigDigest` and `minPairedCases`.
- Governed optimizer: the unchanged baseline stays eligible; a run with no positive estimated gain or a tied top keeps the baseline (`selection: "baseline"`) instead of forcing a winner.
