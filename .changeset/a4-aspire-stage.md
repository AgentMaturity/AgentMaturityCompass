A4 Aspire runs AMC's own producers, behind the A4 preview (`AMC_A4_PREVIEW=1`), offline and with no provider key. Aspire asks 14 questions (`agent`, `problem`, `audience`, `currentWorkflow`, `expertise`, `goals`, `successMetrics`, `constraints`, `forbiddenActions`, `riskTier`, `markets`, `stations`, `governance`, `archetypeInterest`); `stations` depends on `markets`, and `governance` on `riskTier` and `markets`, so changing the markets answer marks only those two answers for confirming (readiness `ask_complete` lists them as `ANSWER_STALE:<id>`) and Propose refuses with `A4_NOT_READY` until they are confirmed. `governance: regulated` with a `low` or `med` risk tier, and a station that is not one of the seven, are `ANSWER_INVALID:<id>`; markets are not checked against a vocabulary yet. Understand runs the existing detectors (framework and instruction-source file scans, the agent's context graph and config, the workspace's agents, station classification with its packs, matching archetypes by shared words, register entries with their `verified` flags as recorded) and records each as a self-reported stage output (implementation lane for workspace facts, recommendation lane for classifications), plus a reflection of the answers with assumptions and unknowns; it pre-fills unanswered questions from the existing agent config, context graph and project profile as `source: "inferred"` answers for the member to confirm. Explain renders the same facts at the novice, practitioner or expert level and keeps all three. Propose builds the brief from the answers: a context graph that `validateContextGraph` accepts, a misuse and failure-modes section, a typed multi-agent graph sketch, PMF hypotheses that stay `proposed` with `verdict: null` (each id is derived from the hypothesis's content, never its position), at least two alternatives (archetype alternatives carry `previewArchetypeApply`'s context diff when the agent already has a context graph), a learning plan, a quality specification whose targets default to `measure: "not instrumented"`, and a value contract draft (not applied). Members may edit the hypotheses (ids must be unique), learning plan, quality specification and misuse section; any other changed part is refused with `INPUT_INVALID`. A quality target with a blank evidence source counts as unmeasured. Propose records the agent's risk tier before the brief (`brief.priorRiskTier`, the higher of its config's and its context graph's); a brief tier below it makes the project regulated, so a lowering is decided under the rules of the tier it lowers. Every Aspire output is `self_reported` with `result: not_evaluated`, its claim boundary reads "A brief is a statement of intent; no outcome is claimed.", and no Aspire output names a maturity level.

After the direction gate is consumed, Build writes `context-graph.json` with the same writer `initWorkspace` uses, scaffolds an agent that has none of its files (a `local_openai` placeholder upstream with no key) or re-saves an existing agent's signed config (a placeholder one when it has a context graph or target profile but no config, as the root default agent of `amc init` has) and re-signs its own default target profile with the new `contextGraphHash` and its existing mapping, initialises the outcome contract when there is none and writes the Enforce resource manifest; each write is a self-reported implementation ref with its file's sha256, and a kept outcome contract is labelled kept. Build is an owner action: `POST …/stages/aspire/build` takes a workspace OWNER (readiness `allowed.build` says so at Aspire), and it is refused in agent mode as `agent add`, `target set` and `snapshot` are (403 `AGENT_MODE`). Before any write it needs the signing key (423 while the vault is locked) and refuses with 409, writing nothing, when the agent's existing config does not verify over the bytes it parses (`AGENT_CONFIG_UNTRUSTED`), is signed but does not parse (`AGENT_CONFIG_INVALID`), or when its own target profile does not parse (`TARGET_PROFILE_INVALID`) or verify (`TARGET_PROFILE_UNTRUSTED`); it never reads the workspace root's target profile for another agent. Starting a project for an agent whose config, context graph or target profile exists takes a workspace OWNER. The typed graph stays a draft in the specification: Enforce's manifest writer refuses every workspace that holds `.amc/fleet/typed-graphs/latest.json`, so Build does not create that file. A manifest Enforce refuses is recorded by its error code only and shows `manifest_active` BLOCKED (`ENFORCE_MANIFEST_REFUSED`). Review checks that the written context graph validates, matches the build and equals the `contextGraphHash` of the agent's own target profile once that profile's signature verifies (otherwise `context_graph_written` is BLOCKED with `CONTEXT_GRAPH_INVALID`, `CONTEXT_GRAPH_MISMATCH` or `TARGET_PROFILE_MISMATCH` and the profile's state), runs the doctor's checks with their first-run fixes, checks the brief is complete, records the agent config's signature check as an integrity self-check (`SELF_CHECK`, `UNANCHORED`), and marks the review `not_evaluated` with `NO_RUNTIME_OBSERVATION_AT_ASPIRE`. Aspire readiness gains `understanding_confirmed`, `ask_complete`, `alternatives_present`, `hypotheses_present`, `learning_plan_present`, `quality_spec_complete`, `risk_section_present`, `brief_valid`, `context_graph_written`, `agent_config_signed` and `manifest_active`, plus one optional `hypothesis.<id>` item per hypothesis: an observation counts only for the hypothesis content it was recorded against (`POST …/hypotheses/:id/observe` now stores the hypothesis digest, the row's own `value` as `observedOutcome` and the verdict's username), and only while its ref still resolves in the observed lane (`HYPOTHESIS_REF_UNRESOLVED` or `HYPOTHESIS_OBSERVATION_DOWNGRADED` otherwise). Hypotheses live only in the revision, never in the decision-receipt files a full score run marks observed. Every revision now binds the agent's `brief.contextGraphSha256` and `brief.agentConfigSha256` as they are when it is recorded, so a context graph or agent config edited outside A4 after a gate is requested is refused at decide and complete with `RESOURCE_DRIFTED`; one that cannot be read or is not JSON refuses the step with 409 `RESOURCE_UNREADABLE`. A preview project whose head revision was recorded before this change binds those two slots as null and reads `RESOURCE_DRIFTED` for an agent that has the files; save an answer (a new revision) before deciding its gate.

The stage routes take `content` as optional where a stage has producers: `understand`, `explain`, `build` and `review` run AMC's producer, and any `content` sent is recorded beside it as the member's own statement; Studio sends it only when written. A stage without producers still requires `content` (400 `INPUT_INVALID`). A stage step refuses a stale `expectedHeadSeq` (409 `A4_STALE_HEAD`) before any producer writes workspace files, a producer's specification is secret-scanned as sent specifications are (400 `SECRET_IN_INPUT`), and a review whose producer names no reason records `NO_OBSERVED_REF`. A completion gate now also bars, as approvers, the authors of every revision of the stage since the one its direction gate approved, so the author of the approved brief cannot approve completion after another member's Build. Studio's Aspire view adds Brief, Solution sketch, Hypotheses (not observed), Learning plan, Quality specification and Alternatives cards, lists the answers to confirm, and shows what AMC understood and the explanation at each level. The brief's free text (problem, workflow, audience, hypothesis statements, the reflection) stays inline in the revision, as the answers it is built from do; it is not sealed in the project's blob store. The completion effect that would apply the value contract and the quality-spec outcome targets is not part of this change. The ten-minute keyless first run has not been measured.
