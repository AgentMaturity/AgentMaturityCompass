A4 Aspire runs AMC's own producers, behind the A4 preview (`AMC_A4_PREVIEW=1`), offline and with no provider key. Aspire asks 14 questions (`agent`, `problem`, `audience`, `currentWorkflow`, `expertise`, `goals`, `successMetrics`, `constraints`, `forbiddenActions`, `riskTier`, `markets`, `stations`, `governance`, `archetypeInterest`); `stations` depends on `markets`, and `governance` on `riskTier` and `markets`, so changing the markets answer marks only those two answers for confirming (readiness `ask_complete` lists them as `ANSWER_STALE:<id>`) and Propose refuses with `A4_NOT_READY` until they are confirmed. `governance: regulated` with a `low` or `med` risk tier, and a station that is not one of the seven, are `ANSWER_INVALID:<id>`; markets are not checked against a vocabulary yet. Understand runs the existing detectors (framework and instruction-source file scans, the agent's context graph and config, the workspace's agents, station classification with its packs, matching archetypes by shared words, register entries with their `verified` flags as recorded) and records each as a self-reported stage output (implementation lane for workspace facts, recommendation lane for classifications), plus a reflection of the answers with assumptions and unknowns; it pre-fills unanswered questions from the existing agent config, context graph and project profile as `source: "inferred"` answers for the member to confirm. Explain renders the same facts at the novice, practitioner or expert level and keeps all three. Propose builds the brief from the answers: a context graph that `validateContextGraph` accepts, a misuse and failure-modes section, a typed multi-agent graph sketch, PMF hypotheses that stay `proposed` with `verdict: null` and `observedOutcome: null` (each id is derived from the hypothesis's content, never its position; `confidence` is the member's own statement and null when none was stated, since AMC states none; the window field is `window`, the A4 row schema's name for the issue's `falsificationWindow`), at least two alternatives (archetype alternatives carry `previewArchetypeApply`'s context diff when the agent already has a context graph), a learning plan, a quality specification whose targets default to `measure: "not instrumented"`, a value contract draft and an outcome contract draft (one metric per quality target that has an evidence source: that source as its signal, the member's target at every level, a category from the dimension). Members may edit the hypotheses, learning plan, quality specification and misuse section; any other changed part is refused with `INPUT_INVALID`. Edited hypothesis ids must be unique and match `[A-Za-z0-9_.-]{1,128}` (the observe route's pattern), and a hypothesis that is new or changed in an edit must have a window that starts at or after the server's time and ends after it starts (400 `INPUT_INVALID`). A quality target with a blank evidence source counts as unmeasured. Propose records the agent's risk tier before the brief (`brief.priorRiskTier`): the higher of its config's tier, read only when the config's detached signature verifies over the bytes read, and its context graph's tier, read only when the agent's own target profile verifies and signs that graph's hash; any other file counts as unreadable, which ranks as high. A re-proposal keeps the higher of that and the previous proposal's `priorRiskTier`, so the stage's own Build cannot lower the bar. A brief tier below it makes the project regulated, so a lowering is decided under the rules of the tier it lowers. Every Aspire output is `self_reported` with `result: not_evaluated`, its claim boundary reads "A brief is a statement of intent; no outcome is claimed.", and no Aspire output names a maturity level.

After the direction gate is consumed, Build writes `context-graph.json` with the same writer `initWorkspace` uses, scaffolds an agent that has none of its files (a `local_openai` placeholder upstream with no key) or re-saves an existing agent's signed config (a placeholder one when it has a context graph or target profile but no config, as the root default agent of `amc init` has) and re-signs its own default target profile with the new `contextGraphHash` and its existing mapping, initialises the outcome contract when there is none (merging the outcome contract draft's metrics into it, signed), writes the typed multi-agent graph (`.amc/fleet/typed-graphs/a4-<agentId>.json`; the writer also replaces the fleet's `latest.json`, which every agent's Enforce manifest records, so another agent that has a manifest reads `DRIFTED` in Enforce's status until it is snapshotted again, and that agent's A4 project reads `RESOURCE_DRIFTED`, as below) and writes the Enforce resource manifest; each write is a self-reported implementation ref with its file's sha256, and a kept outcome contract is labelled kept. Build is an owner action: `POST …/stages/aspire/build` takes a workspace OWNER (readiness `allowed.build` says so at Aspire), and it is refused in agent mode as `agent add`, `target set` and `snapshot` are (403 `AGENT_MODE`). Before any write it needs the signing key (423 while the vault is locked) and refuses with 409, writing nothing, when an existing value contract does not verify (`VALUE_CONTRACT_UNTRUSTED`), when the quality specification states outcome metrics and an existing outcome contract does not verify (`OUTCOME_CONTRACT_UNTRUSTED`; the completion effect would otherwise fail only after the completion gate is consumed), when the agent's existing config does not verify over the bytes it parses (`AGENT_CONFIG_UNTRUSTED`), is signed but does not parse (`AGENT_CONFIG_INVALID`), or when its own target profile does not parse (`TARGET_PROFILE_INVALID`) or verify (`TARGET_PROFILE_UNTRUSTED`); it never reads the workspace root's target profile for another agent. It also refuses, before any write, with 409 `RESOURCE_DRIFTED` naming the slots when a resource the approved revision bound (the signed configs, the brief's context graph and agent config, the typed graph, the agent's Enforce resources) has changed since; propose again. A typed graph sketch that does not parse is 409 `A4_NOT_READY` (`TYPED_GRAPH_INVALID`). Starting a project for an agent whose config, context graph or target profile exists takes a workspace OWNER. A manifest Enforce refuses is recorded by its error code only and shows `manifest_active` BLOCKED (`ENFORCE_MANIFEST_REFUSED`), and so does a manifest published without its signatures (`MANIFEST_UNSIGNED`). Review's context-graph error and Understand's agent config and context graph errors are recorded as codes (an errno, a YAML or validation code, `NOT_JSON` or `INVALID`), never as messages naming paths. Review checks that the written context graph validates, matches the build and equals the `contextGraphHash` of the agent's own target profile once that profile's signature verifies (otherwise `context_graph_written` is BLOCKED with `CONTEXT_GRAPH_INVALID`, `CONTEXT_GRAPH_MISMATCH` or `TARGET_PROFILE_MISMATCH` and the profile's state), runs the doctor's checks with their first-run fixes, checks the brief is complete, records the agent config's signature check as an integrity self-check (`SELF_CHECK`, `UNANCHORED`) with a closed reason code (`AGENT_CONFIG_MISSING`, `SIGNATURE_MISSING`, `DIGEST_MISMATCH`, `SIGNATURE_VERIFY_FAILED`, `SIGNATURE_PAYLOAD_INVALID` or `SIGNATURE_INVALID`), never the verifier's free-text reason, and marks the review `not_evaluated` with `NO_RUNTIME_OBSERVATION_AT_ASPIRE`. Aspire readiness gains `understanding_confirmed`, `ask_complete`, `alternatives_present`, `hypotheses_present`, `learning_plan_present`, `quality_spec_complete`, `risk_section_present`, `brief_valid`, `context_graph_written`, `agent_config_signed` and `manifest_active`, plus one optional `hypothesis.<id>` item per hypothesis: an observation counts only for the hypothesis content it was recorded against (`POST …/hypotheses/:id/observe` now stores the hypothesis digest, the row's own `value` as `observedOutcome` and the verdict's username), and only while its ref still resolves in the observed lane (`HYPOTHESIS_REF_UNRESOLVED` or `HYPOTHESIS_OBSERVATION_DOWNGRADED` otherwise). The observe route refuses while the project is at Aspire (409 `A4_STEP_ORDER`: nothing in Aspire is observed, and a review never counts a hypothesis observation as its own), and refuses a row written before the first revision that carried that hypothesis (409 `HYPOTHESIS_OUTSIDE_WINDOW`), and an observed item carries the row's value as `OBSERVED_VALUE:<value>`, which the Hypotheses card prints. Hypotheses live only in the revision, never in the decision-receipt files a full score run marks observed. Every revision now binds the agent's `brief.contextGraphSha256`, `brief.agentConfigSha256`, `graph.typedGraphDigest` and `enforce.resourcesSha256` (the sha256 of the agent's live Enforce resource set, its config and the config's `.sig` among them, once it has a manifest) as they are when it is recorded, so a context graph or agent config edited outside A4 after a gate is requested, the config's `.sig` removed or replaced, or another agent's Build replacing the fleet's `latest.json`, is refused at decide, complete and the effect preamble with `RESOURCE_DRIFTED`, and `manifest_active` reads BLOCKED (`MANIFEST_DRIFTED`) while the built revision is the head; the slot hashes every Enforce candidate on each readiness read; one that cannot be read or is not JSON refuses the step with 409 `RESOURCE_UNREADABLE`. A preview project whose head revision was recorded before this change binds those slots as null and reads `RESOURCE_DRIFTED` for an agent that has the files; save an answer (a new revision) before deciding its gate.

The stage routes take `content` as optional where a stage has producers: `understand`, `explain`, `build` and `review` run AMC's producer, and any `content` sent is recorded beside it as the member's own statement; Studio sends it only when written. A stage without producers still requires `content` (400 `INPUT_INVALID`). A stage step refuses a stale `expectedHeadSeq` (409 `A4_STALE_HEAD`) before any producer writes workspace files, a producer's specification is secret-scanned as sent specifications are (400 `SECRET_IN_INPUT`), and a review whose producer names no reason records `NO_OBSERVED_REF`. A completion gate now also bars, as approvers, the authors of every revision of the stage since the one its direction gate approved, so the author of the approved brief cannot approve completion after another member's Build. Studio's Aspire view adds Brief, Solution sketch, Hypotheses (not observed), Learning plan, Quality specification and Alternatives cards, lists the answers to confirm, and shows what AMC understood and the explanation at each level. The brief's free text (problem, workflow, audience, hypothesis statements, the reflection) stays inline in the revision, as the answers it is built from do; it is not sealed in the project's blob store. Completing Aspire runs the effect `a4.aspire.apply_contracts`: it first runs every refusal (the signing key, an existing value contract that does not verify, an outcome contract that does not verify when metrics are stated), then applies the value contract draft when the agent has none, merges the outcome contract draft's metrics into the outcome contract, and records a signed receipt naming both files by sha256; a value contract found present is recorded with `matchesApprovedDraft` (labelled "present, identical to the approved draft" or "kept (differs from the approved draft)"), never as kept without verifying it. A failure is recorded by its code, and readiness `effects.failed` names it (`EFFECT_ERROR:<code>`), the failed attempt (`ATTEMPT:<id>`) and the route `POST …/stages/aspire/effects/a4.aspire.apply_contracts/retry`; Studio shows a Retry button for it, enabled for owners, and a retry is refused while signing is unavailable, so it does not spend the stage's last attempt. It runs on the completion gate's own quorum: A4 effects gain `consumes: "gate"`, which journals the effect with the gate's consumption and needs no effect gate or second engine approval (an effect gate's engine approval excludes the completing caller and every builder, so a single-user workspace could never complete a stage that needed one). Studio no longer labels an Understand or Explain receipt as the member's statement when the member sent none. The ten-minute keyless first run has not been measured.
