Studio's `/auth/login`, the host router's `/host/api/login` and the workspace `/w/<id>/login` now throttle failed logins per account and client address (LIVE-RUNTIME-04). Ten failures for one username from one address within 15 minutes refuse that pair with 429 `too many failed logins for this account from this address` and a `Retry-After` header, and the first refusal is audited as `HUMAN_LOGIN_THROTTLED`. The same account from another address is not refused, so a co-tenant cannot lock an owner out of their own address. Thirty failures for one username from any addresses add a 2 second delay to every attempt for that username until the window passes; that is never a refusal. The throttle is in memory: a restart clears it, and replicas do not share it. Behind a reverse proxy the client address comes from `X-Forwarded-For` only on a request a proxy named in `AMC_TRUSTED_PROXY_CIDRS` forwarded (SR-1). When `AMC_TRUSTED_PROXY_HOPS` is set but a request did not come through such a proxy, its address may stand for many clients (SR-2): ten failures from that address only add the 2 second delay, so nobody can lock out everyone behind a shared address. Instead, thirty failures for the username from such addresses refuse further attempts from them with 429 `too many failed logins for this account`. That count holds only failures from such addresses (SR-11): failures a trusted proxy forwards never feed it, so an attacker behind the proxy cannot lock the account for everyone else. Loopback is the exception: behind a same-host reverse proxy that AMC does not trust, every outside client arrives from loopback, so loopback always keeps the ten-failure refusal, as one address (127.0.0.1 and ::1 share it), whether or not proxy hops are set; it stays out of the thirty-failure count of other addresses, so a flood from elsewhere does not refuse the local console. The thirty-failure username count over all addresses stays a delay everywhere.

Every login failure now answers 401 with exactly `{"error":"invalid credentials"}`, including a revoked or disabled account and a users file that fails to load (LIVE-RUNTIME-06). The reason goes to the audit record and the server log. Policy refusals keep their text: 403 for an invalid users signature or for local password login disabled by identity policy, and 429 from the limiters.

The in-memory request limiters now hold at most 50,000 client keys: expired buckets are pruned as new keys arrive, and a map full of live buckets drops its oldest one. A new key is never refused because the map is full, so a client that rotates keys cannot lock other clients, or the health and readiness probes, out.
