A4 and the action journal now run on a Postgres ledger backend (P2-36). On a workspace pinned to the Postgres session store, every A4 commit and every action-journal transition writes the rows of the project or execution it touched through to Postgres, inside its SQLite transaction and committed first: a Postgres write that cannot commit rolls the transition back (503 `LEDGER_MIRROR_UNAVAILABLE`). Each write is logged in a hash-chained `amc_ledger_mirror_log` whose head the workspace signs with the monitor key (`.amc/postgres-ledger-mirror-head.json`). Writes, A4 project reads, `amc a4 verify`, `amc verify` and A4 readiness check the Postgres rows against the log, the SQLite rows and the signed head, and refuse divergence, rows changed outside AMC and a truncated log with `LEDGER_MIRROR_DIVERGED`; a project Postgres has never held fails verification as `LEDGER_MIRROR_BEHIND` until its next write copies it. The `a4_*` and `action_*` tables are declared in `POSTGRES_MIRROR_TABLES`, so `amc evidence-stores migrate --to postgres` copies them and compares them row by row; `LEDGER_BACKEND_INCOMPLETE` now refuses only an `a4_*` or `action_*` table the mirror does not declare. WORM exports carry a signed ledger side-table segment with every A4 and action-journal row, so a WORM restore covers A4 state; `worm-verify` checks it and reports an older export without one as not covering A4. Postgres grants need `INSERT` on `amc_ledger_mirror_log` and `INSERT, UPDATE` on the side tables. Behaviour against a real Postgres is the pending drill in docs/runbooks/POSTGRES_FAILOVER.md. No new CLI command (freeze key P2-36 not needed).
