Aborted assurance runs are sealed as aborted; unsigned assurance runs use a separate store; budget-evidence integrity failures are no longer reported as quota; evidence export --agent includes the agent's native sessions and reports what it excluded.

- An assurance scan that fails after it starts (for example `amc assurance run` exiting 2 because no agent under test is reachable, or `amc assurance patch --apply` failing to record its audit row) now appends an `ASSURANCE_RUN_ABORTED` audit row naming the error class and seals its ledger session, so later `amc verify` and `amc agent-loop verify` runs no longer fail with "missing seal" for that session. The original error is still raised and no assurance run is recorded. Sessions left unsealed by aborted runs before this release stay unsealed and are still reported.
- An assurance run under `AMC_NO_SIGN=1` (`amc assurance run --no-sign` sets it) writes its ledger session to `.amc/unsigned/evidence.sqlite` instead of `.amc/evidence.sqlite`, is reported `UNSIGNED` even when the caller did not pass `noSign`, records `evidenceStore` in its report, and the CLI prints `Evidence store: .amc/unsigned/evidence.sqlite`. Signed readers never open that store, so `amc assurance history` lists signed runs only. The unsigned store is refused unless `AMC_NO_SIGN=1`.
- When the workspace ledger fails verification during native budget admission, the native turn now fails with code `AMC_EVIDENCE_INTEGRITY` (cause `budget_evidence_invalid`) and guidance to run `amc verify` and `amc budgets verify`, instead of `QUOTA`, whose guidance claimed the provider reported exhausted quota. The message names the first offending row or session and says when its signature is the literal `unsigned` that `AMC_NO_SIGN=1` writes. Real budget refusals are unchanged.
- The control checkpoint root check is segment-aware: `AMC_CONTROL_CHECKPOINT_DIR=<workspace>/..cache/...` is now refused as inside the workspace, and the refusal names the checkpoint root, the workspace and `AMC_CONTROL_CHECKPOINT_DIR`.

Breaking for evidence-export consumers: `amc evidence export --agent <id>` (and `collectVerifierEvidence`, the audit packet and `GET /api/v1/evidence/export`) now also include every row of the native sessions whose `session/open` row names the agent, never the shared `system` session. The dataset `schemaVersion` is 2, and `agentFilter` changes from the bare agent id to `{ agentId, mode: "row-meta-or-owned-session", sessionsIncluded, rowsExcluded }` (`null` without a filter); `exportVerifierEvidence` returns the same `agentFilter`. The CLI prints `sessions=` and `excluded=` beside `events=`. New exports hash differently; existing version 1 exports are unchanged.
