A4 Adapt adds the agent's context, memory and permissions to the compiled plan, behind the A4 preview (`AMC_A4_PREVIEW=1`). Build now also writes the members' audience, market, sector, language, accessibility, data-handling and regulatory-note answers as one attributed context plugin (`# A4 context: <section>`, source `a4:<projectId>@r<revision>`, order 160, the catalog's notice quoted) to `<agent>/a4/context-plugin.json`, and an advisory memory policy (`amc.a4-memory-policy/v1`: privacy class, consumers, retention tag, expiry and review days, compaction, spill cap; four new optional questions, each empty answer taking a stated default labelled `default`) to `<agent>/memory/policy.json`, then re-writes the signed Enforce manifest. Build is refused in agent mode, on a memory answer the policy does not accept (`ANSWER_INVALID`), with 413 `INPUT_TOO_LARGE` or 400 `SECRET_IN_INPUT` when the record it would make does not pass the router's own size and credential checks (Propose also refuses a proposal that leaves Build no room under the 256 KiB limit), and with 409 `ENFORCE_DRIFTED` when the agent's resources do not match its signed Enforce manifest before it writes or when its writes moved more than the agent's memory directory, all before it writes; when a write fails, or the step is not recorded after Build returned (the head moved, the transition was refused, a replay answered), Build's memory policy, context plugin and Enforce manifest and signature are put back as they were; Review is refused with 409 `RESOURCE_DRIFTED` when the memory policy, the context plugin or the agent's Enforce resources moved since Build. A memory policy whose bytes changed after Build reads BLOCKED even when it parses. The memory policy limits nothing yet: the reasoning-memory writer does not read it.

The new route `POST /api/v1/a4/projects/:id/stages/adapt/probe` (after Build; owner, as Build is; owner mode) runs one in-process turn on the stub provider with the plugin as an extra context and writes nothing of A4's into that session (no tools, no effective-policy receipt: the runtime writes one only before a governed tool call, and this turn makes none). It checks that the run's signed `user/message` row carries the plugin's exact text, reads the turn's signed `turn/end` reason, and records the session's signed `session/open` row as a `ledger_event` ref, `self_reported` (A4 ran the turn, so it is never observed). Whoever runs the probe counts as a builder, so they cannot approve the Adapt completion gate or the activation. New readiness items: `context_reaches_runtime_frame` (READY, in the implementation section, on AMC's own check: the `user/message` row with the text, named `SNAPSHOT:<row>`, found by the probe and again by Review, behind the probe's resolved self-reported ref, with `PROBE_SELF_REPORTED` and `NO_EFFECTIVE_POLICY_RECEIPT`; `PROBE_DENIED` for a turn that did not end `complete`, `CONTEXT_NOT_IN_FRAME`, `PROBE_REF_UNRESOLVED`, or the `FRAME_ROW_*` code Review found otherwise; mandatory once built, so a regulated plan is activated only after the probe), `model_delivery` (not evaluated on the stub provider), `context.native_delivery` (not evaluated: nothing loads the plugin into a Studio native task or a deployed agent, P2-37), `prompts_attributed`, `memory_policy_present` (also WAITING when Build wrote no signed Enforce manifest), `profile_no_widening` and the integrity item `adapt.prompt_pack_signature`. A workspace whose session store is JSONL cannot record the probe (`PROBE_NOT_RECORDED`).

Understand now builds the primary station's operating profile in memory and compares it with the current verified configs through `planActivationWidenings`, a new read-only export of the operating-profile activation module (it returns the widenings and the sha256 of each config activation would write, and no write closure; `planActivation` stays private), writing and signing nothing: `profile_no_widening` lists each widening as `scope_changed` (`POLICY_WIDENING_REFUSED`) until a project owner's revision answers the new `acceptWidenings` question with exactly their digest. A4 never passes `allowWidening` and never signs or activates a profile; an owner signs a reviewed profile with `amc domain apply --sign-profile` and activates it with `--activate-profile`. The effect `a4.adapt.activate_profile`, the per-agent `gatePolicy.json` and lease-cap proposal and the prompt-pack build are not built (`KEY:A4_PROFILE_EFFECT`). Understand and Review also record whether the agent's latest prompt pack verifies under this workspace's keys, over exactly the bytes they hashed; the pack is a Score resource the runtime does not load. `activeControlPlan` (the verified active plan) is now exported from the compiled-plan activation module.

Revisions now bind `context.contextPluginSha256`, `context.memoryPolicySha256`, `context.promptPackSha256`, `operatingProfile.sha256` and `operatingProfile.activationSha256` (the operating-profile slots read only regular files under real directories: a link, a FIFO or an oversized file is `RESOURCE_UNREADABLE`); an open gate recorded before this release in a workspace that already has a prompt pack or an operating-profile activation record reads `RESOURCE_DRIFTED` once until a new revision is recorded. Under an active plan, `adapt.plan.nativeSessionsAllowed` reads WAITING (`LEASE_NOT_ISSUED`, `VAULT_LOCKED`) while the vault that holds the lease key is locked. `GET /api/v1/a4/projects/:id/conformance` and the `amc_a4_conformance` MCP tool now return the stage's `amc.a4-conformance-statement/v1` (Adapt's from its newest Review; every other stage says not evaluated) instead of `NO_PRODUCER_REGISTERED`. Studio's Adapt view adds the Context plugin and probe, Memory policy, Permissions, Reporting clocks and Data handling cards, states the lockout on the activation card, and its blocker inbox no longer reads as clear when Studio returned no readiness evaluation.
