A4 Adapt adds the agent's context, memory and permissions to the compiled plan, behind the A4 preview (`AMC_A4_PREVIEW=1`). Build now also writes the members' audience, market, sector, language, accessibility, data-handling and regulatory-note answers as one attributed context plugin (`# A4 context: <section>`, source `a4:<projectId>@r<revision>`, order 160, the catalog's notice quoted) to `<agent>/a4/context-plugin.json`, and an advisory memory policy (`amc.a4-memory-policy/v1`: privacy class, consumers, retention tag, expiry and review days, compaction, spill cap; four new optional questions, each empty answer taking a stated default labelled `default`) to `<agent>/memory/policy.json`, then re-writes the signed Enforce manifest; Build is refused in agent mode and on a memory answer the policy does not accept (`ANSWER_INVALID`). The memory policy limits nothing yet: the reasoning-memory writer does not read it.

The new route `POST /api/v1/a4/projects/:id/stages/adapt/probe` (after Build; builder or owner; owner mode) runs one in-process turn on the stub provider with the plugin as an extra context, records the session's effective-policy receipt through the session writer, checks that the run's signed `user/message` snapshot carries the plugin's exact text, and records the receipt row as a `ledger_event` ref (observed when the row earns it). New readiness items: `context_reaches_runtime_frame` (READY only from that ref; `PROBE_DENIED` or `CONTEXT_NOT_IN_FRAME` otherwise; mandatory once built, so a regulated plan is activated only after the probe), `model_delivery` (not evaluated on the stub provider), `context.native_delivery` (not evaluated: nothing loads the plugin into a Studio native task or a deployed agent, P2-37), `prompts_attributed`, `memory_policy_present` (also WAITING when Build wrote no signed Enforce manifest), `profile_no_widening` and the integrity item `adapt.prompt_pack_signature`. A workspace whose session store is JSONL cannot record the probe (`PROBE_NOT_RECORDED`).

Understand now emits the primary station's operating profile to A4's own proposal file (`amc-operating-profiles/<agent>/a4-<station>.operating-profile.json`; the operator's default-path profile is never touched), signs it, and dry-runs `activateOperatingProfile` against the current verified configs: `profile_no_widening` lists each widening as `scope_changed` (`POLICY_WIDENING_REFUSED`) until a project owner's revision answers the new `acceptWidenings` question with exactly their digest. A4 never passes `allowWidening` and never activates a profile. Understand and Review also record whether the agent's latest prompt pack verifies under this workspace's keys; the pack is a Score resource the runtime does not load.

Revisions now bind `context.contextPluginSha256`, `context.memoryPolicySha256`, `context.promptPackSha256`, `operatingProfile.sha256` and `operatingProfile.activationSha256`; an open gate recorded before this release in a workspace that already has a prompt pack or an operating-profile activation record reads `RESOURCE_DRIFTED` once until a new revision is recorded. Under an active plan, `adapt.plan.nativeSessionsAllowed` reads WAITING (`LEASE_NOT_ISSUED`, `VAULT_LOCKED`) while the vault that holds the lease key is locked. `GET /api/v1/a4/projects/:id/conformance` and the `amc_a4_conformance` MCP tool now return the stage's `amc.a4-conformance-statement/v1` (Adapt's from its newest Review; every other stage says not evaluated) instead of `NO_PRODUCER_REGISTERED`. Studio's Adapt view adds the Context plugin and probe, Memory policy, Permissions, Reporting clocks and Data handling cards, states the lockout on the activation card, and its blocker inbox no longer reads as clear when Studio returned no readiness evaluation.
