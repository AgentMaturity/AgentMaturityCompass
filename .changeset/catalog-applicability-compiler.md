Experimental applicability compiler. `amc catalog compile --profile <file> [--previous <plan.json>] [--lock <catalog.lock.json>] [--out <dir>] [--request-review] [--allow-weakening] [--json]` compiles a deployment profile against the shipped Regulated Control Catalog into a signed control plan. The plan is experimental and makes no compliance claim: the catalog content is agent-drafted and unreviewed, and an applicable control is not a met control. `docs/catalog/COMPILER.md` describes the input contract, the rules and the outputs.

- The deployment profile is strict JSON: deployment ids, nine facts (`value` null means unknown; provenance `asserted`, `observed` or `reviewed`), artifact references and reviewer exceptions. An unknown key fails. When it references an F1 operating profile, the file must hash to the recorded sha256.
- Applicability is evaluated three-valued: an unknown fact stays unknown. Each control appears once with every source in `pulledInBy` and is `applicable`, `not_applicable` (with the reason) or `unresolved` (with the missing facts). Parameters of unresolved controls are still applied. A mandatory control left unresolved, or a parameter conflict the strictness rules cannot resolve (`none`, empty `intersection`), makes the plan `blocked`. Crosswalks never add a requirement.
- Every parameter difference is listed in `conflicts`. Only documented parameter names exist; an unknown name, type, strictness or enforcement point fails the compile. Reviewer exceptions can exclude a control or resolve an unresolved conflict until they expire; none may exclude a mandatory Layer 0 control.
- The plan carries the catalog lockfile, the requirements, conflicts, unsupported controls, an effective runtime policy (tool pipeline, approvals, egress, deletion, and proposed signed-config fragments) and an evidence plan. Its digest is stable across runs and input order. Nothing is activated and nothing is written under `.amc/`; only `--request-review` asks the approval engine to record an approval request bound to the plan digest (and to create its default signed approval policy when none exists). An `--out` under `.amc/` is refused.
- The plan digest is signed with the new `CONTROL_PLAN` signing kind (added to the trust config's sign kinds). Signing is blocked in agent mode. With `--previous`, the earlier plan must verify against this workspace's auditor keys and belong to the same profile, and every weakening against it is listed; every reviewer exception the plan applies is listed too, with or without `--previous`. Any listed item refuses the signing unless `--allow-weakening` is given after review. Checked against the workspace's own keys, the signature is a local audit trail: it shows who signed the plan, not that the plan is right.
- Output: `plan.json`, `plan.sig.json`, `plan.diff.md` and `catalog.lock.json`, by default under `amc-control-plans/<profileId>/<first 12 hex of the digest>/`. `--lock` refuses a catalog that differs from the lockfile. Exit codes: 0 ready, 2 blocked, 1 error or refusal.
