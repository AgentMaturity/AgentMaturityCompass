Optional pi-ai routes (pinned, reviewed) behind AMC's adapter seam; capability matrix generated from tests (P1-38). `amc agent-loop run --provider pi-ai:groq|pi-ai:huggingface|pi-ai:together --model <id>` builds the request body with `@earendil-works/pi-ai` exactly 1.3.0, an optional peer dependency that AMC does not install for npm users and loads only for these routes. It needs Node 22.19.0 or later; a missing package, any other version or an older Node is refused with the install command. AMC signs the bytes in `request/header` before sending them through its own transport, so capability, dataflow, budget and egress admission apply unchanged, and verification re-derives them (`reconstructed` with pi-ai 1.3.0 installed, `unreconstructable` without it). Only non-reasoning models from the pinned catalog are accepted. Only `max_tokens` (required, within the catalog limit) and `temperature` map. Images, thinking and failed tool results are refused before a header exists, and missing usage is recorded as unreported, never zero. Native routes stay the default; ACP and schedules accept native routes only. `npm run gen:capability-matrix` runs the native and pi contract tests (offline, local fixture servers) with vitest's JSON reporter and renders `docs/providers/CAPABILITY_MATRIX.md`: a cell is supported or unsupported only when its claiming test passed in that run, a failed claim is unknown, a claim that did not run is "not run", and live providers are "not run". `npm run check:capability-matrix` runs the tests again and fails when the committed matrix differs or cites a test that did not pass. See docs/adr/016-pi-ai-adapter.md, docs/providers/pi-ai-review-1.3.0.md and docs/providers/PI_AI_UPGRADE_POLICY.md.
