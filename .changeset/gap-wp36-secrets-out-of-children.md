Keep AMC-held secrets out of launched processes and evidence (GAP-WP36). `amc adapters run --mode SANDBOX` now passes only the adapter's own variables into the container (by name, values from docker's inherited environment; never AMC's vault, notary, backup or release secrets, nor the host's PATH or HOME), records the variable names and the lease id in the `SANDBOX_EXECUTION_ENABLED` attestation, and returns the container's real exit code instead of always 0 (`POST /api/v1/sandbox/run` also returns `exitCode`). The opt-in unconfined bash tool now runs commands with an allow-listed environment (PATH, HOME, user, shell, terminal, temp, locale and timezone variables), so `env` in a model-run command no longer shows `AMC_VAULT_PASSPHRASE`, `AMC_RELEASE_SIGNING_KEY`, cloud or GitHub tokens. Wrapped and adapter-launched agents, version probes and diagnostic runtimes no longer inherit `AMC_*` passphrase, password, secret or signing-key variables. The TypeScript SDK's `AMCNativeClient` now starts its child with a minimal environment (PATH, HOME, locale and temp variables and the parent's `AMC_*` settings) plus `options.env`, so a provider key in the embedding process must be passed in `env` or kept in AMC's credential file; pass `inheritEnv: true` to restore the previous whole-parent merge. The sdk-api snapshot gains the additive `AMCNativeClientOptions.inheritEnv` option.
