Breaking: compliance reports return not evaluated without control-bound evidence; coverage score is null when nothing was evaluated. `amc compliance report` evaluates each requirement as pass, fail or not evaluated. Evidence counts only when the event names the control in `meta.controlIds` (or a mapping's new optional `auditTypes` lists its audit type), belongs to the reported agent, comes from AMC runtime (imported, manual, webhook and synthetic events are not admitted) and falls inside the window. An empty ledger, a coincidental event type, another agent's event, an event without an agent id, an unsealed assurance report and missing or tampered map signatures now give `NOT_EVALUATED` instead of `PARTIAL` or `SATISFIED`. "No denied audit events" no longer passes when the agent has no activity in the window. Workspace `system` session events count as positive evidence only for a mapping with `binding: { scope: workspace }`, and their violations still fail every agent.

Because built-in runtime evidence does not carry `controlIds` yet, most built-in categories now report not evaluated; that is the truthful result, not a regression in evidence. The report JSON changes shape: categories gain `result`, `evidence` and `notEvaluatedReasons`; `coverage` gains `notEvaluated` and `evaluated`, and `coverage.score` (also the fleet `score`, the matrix framework and overall scores, the diff `coverageScoreDelta` and the API `coverageScore`) is `null` when nothing was evaluated. The CLI prints `Coverage: not evaluated (0 of N categories had control-bound evidence)` and no longer derives SATISFIED or PARTIAL from a percentage. A compliance report is evidence of conformity, not a certification.
