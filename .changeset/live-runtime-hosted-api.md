The hosted API (Vercel, Railway or a direct `api:start`) now rate limits POST routes to 120 a minute per route and client and answers 429 `{"error":"rate limited"}` past that (LIVE-RUNTIME-16). Behind a platform proxy every request comes from the proxy, so name the client: set `AMC_API_TRUSTED_CLIENT_IP_HEADER` to a single-value header the platform overwrites with the client address (`x-vercel-forwarded-for`, `cf-connecting-ip`, `fly-client-ip`), or set `AMC_API_TRUSTED_PROXY_HOPS` to the number of proxies that append to `X-Forwarded-For` (the client is that many entries from the right). The left-most `X-Forwarded-For` entry is never used, because the client writes it, and a value that is not one IP address is ignored (SR-6). On Vercel, Railway or Fly with neither set, the limiter cannot tell clients apart, so every client shares one bucket per route with a ceiling of 1,200 a minute, and the server logs once that per-client limiting is unavailable; the limiter is never switched off, and the admin licence route stays limited (SR-12). The Stripe webhook is never rate limited (its signature is checked first), and each route has its own bucket, so a flood on a public route cannot starve the webhook or the admin licence route (SR-7). Buckets are keyed by fixed route ids (checkout, licence issue, licence verify, quickscore); every other POST path shares one "other" bucket per client, so varying the path buys no fresh bucket (SR-13). The limiter is in memory, so on serverless platforms it counts per instance. A failed licence issue now answers 503 `{"error":"licence issuing is not configured"}` with the required variables; the underlying reason goes to the server log only.
