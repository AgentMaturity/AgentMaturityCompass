Release engineering (P0-34): `release.yml` is the only workflow that publishes, and its `release` job runs in the protected `release` environment. A `gate` job packs the npm tarball once at the commit the tag names and runs the release gate, the packed-install and content checks and the publish dry run on that file; the `release` job publishes exactly that tarball (`npm publish <file>`) after verifying its recorded SHA-256 and that the tag still names the gated commit, never rebuilds, and signs a bundle that embeds the gated tarball, SBOM and licence inventory. It fails instead of skipping when the signing key, the committed release public key (`trust/amc-release-signing.pub`) or an npm credential is missing; it publishes through npm trusted publishing or an environment `NPM_TOKEN`, verifies the signed bundle only with `--pubkey trust/amc-release-signing.pub`, and uses `docs/releases/<version>.md` as the release body. `amc release pack` gains `--npm-tarball`, `--sbom` and `--licenses` to embed given files instead of packing; `scripts/release-record.mjs` writes and verifies the record and checks the tag. `npm-publish.yml` only opens version PRs. `pnpm release` no longer publishes from a shell. New commands: `npm run release:prepare -- <version>` (version, notes, CHANGELOG and dry runs, never publishing), `npm run release:notes`, `npm run check:release-candidate` and `npm run check:pack-contents` (with `--tarball <file>` to check a given tarball). `scripts/packed-install-check.mjs --tarball <file>` and `AMC_PACKED_INSTALL_TARBALL` check a given tarball instead of packing. The packed-install check now also verifies that the A4 preview gate is closed in the installed package.
