Release engineering (P0-34): `release.yml` is the only workflow that publishes, and its `release` job runs in the protected `release` environment. A `gate` job packs the npm tarball once at the commit the tag names and runs the release gate, the packed-install and content checks and the publish dry run on that file; the `release` job publishes exactly that tarball (`npm publish <file>`) after verifying its recorded SHA-256 and that the tag still names the gated commit. It is the only job with `id-token: write` or an npm credential, installs and builds nothing, and runs an npm CLI pinned by version and integrity; a separate `sign` job signs a bundle that embeds the gated tarball, SBOM and licence inventory, and every job declares least-privilege permissions. A tag push is the only trigger (no dispatch input chooses the ref); an `approve` job in the `release` environment fails closed without required reviewers and a tag rule, and the signing and publishing jobs also run in that environment, so a re-run waits for approval. Secrets appear only in the env of the step that uses them; the GHCR login reads its token from stdin and the GitHub Release is created with `gh release create --verify-tag`. Homebrew runs only when the repository variable `AMC_HOMEBREW_TAP` is `enabled`. It fails instead of skipping when the signing key, the committed release public key (`trust/amc-release-signing.pub`) or an npm credential is missing; it publishes through npm trusted publishing or an environment `NPM_TOKEN`, verifies the signed bundle only with `--pubkey trust/amc-release-signing.pub`, and uses `docs/releases/<version>.md` as the release body. `amc release pack` gains `--npm-tarball`, `--sbom` and `--licenses` to embed given files instead of packing; `scripts/release-record.mjs` writes and verifies the record and checks the tag. `npm-publish.yml` only opens version PRs. `pnpm release` no longer publishes from a shell. New commands: `npm run release:prepare -- <version>` (version, notes, CHANGELOG and dry runs, never publishing; it applies the changesets itself, because the changesets CLI cannot see the root package in this pnpm workspace, and `npm run version-packages` now runs its version step), `npm run release:notes`, `npm run check:release-candidate` and `npm run check:pack-contents` (with `--tarball <file>` to check a given tarball). `scripts/packed-install-check.mjs --tarball <file>` and `AMC_PACKED_INSTALL_TARBALL` check a given tarball instead of packing. The packed-install check now also verifies that the A4 preview gate is closed in the installed package.
