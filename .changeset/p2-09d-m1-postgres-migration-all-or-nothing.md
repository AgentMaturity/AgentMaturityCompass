`amc evidence-stores migrate --to postgres` is all or nothing (P2-09d-M1). It used to record the chain id in `.amc` before it refused a chain that already held rows, and to write both signed heads before the mirror parity check could refuse. A refusal after the copy left committed rows in Postgres, so every retry refused as a merge. Now the determinism probe runs first, under per-run event ids, so a second migration into the same database is no longer refused by the first one's scratch chain. One Postgres transaction then copies every mirrored table and, before COMMIT, compares each with SQLite row by row, checks both head rows, and checks every A4 and action scope against the mirror log, held to the head it is about to sign. Any refusal rolls the transaction back, and `.amc` is untouched. The signed heads, the receipt, the chain id and the pin are written only after COMMIT, with the chain id last but one. If one of those writes fails, the next run finishes the migration: it copies under a fresh id when no chain id was recorded, and otherwise it proves that the committed chain is exactly this workspace's copy and keeps it. Any other rows are still refused as a merge.
