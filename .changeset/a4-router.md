A4 Forge routes (P1-57 slice B, preview). With `AMC_A4_PREVIEW=1`, Studio serves `/api/v1/a4` to signed-in workspace users through native admission. Without the variable every path answers 404 `A4_PREVIEW_DISABLED`. Release, deployment and rollback routes answer 404 `A4_ROUTE_NOT_FOUND` until P1-62.

- Who may call: the admin token reads and is refused on every mutation, project creation included (403 `ADMIN_TOKEN_REFUSED`); the demo session is refused on every route (403 `DEMO_REFUSED`); Studio's read-only mode refuses every mutation (403 `NATIVE_READ_ONLY`). Approve, deny and request-changes take APPROVER, AUDITOR or OWNER (the gate's own allowed roles then keep AUDITOR to the action classes whose signed rule admits it), and hold, resume, reopen, tune, members, gate-policy, acknowledge, effects and Adapt/Activate completion take OWNER. Retire takes OPERATOR or OWNER, and is then refused unless the caller is a workspace OWNER or the creator of a project that never reached `proposed`. Comments and presence take any read role plus project membership. Project reads need membership, except for workspace OWNERs, AUDITORs and the admin token. A body that names `userId`, `roles`, `approver`, `author`, `approved`, `approvalId`, `token` or a trust-list field is refused with 400; member roles are sent as `projectRoles`.
- Projects: `POST /projects` (OPERATOR or OWNER; a project for an agent that already exists needs OWNER), `GET /projects`, `GET /projects/:id` (head, members, current revision, gates and readiness), `GET /inbox`, `GET /options`, revisions, a revision diff, transitions, gates, members, comments (bodies are read from the encrypted blob store), evidence refs, a cursor poll with presence (`…/events`), owner holds and acknowledgements, and `POST …/evidence` (a ledger row reaches the observed lane only when its recomputed trust tier is observed; everything else is self-reported).
- Stages: answers, understand, confirm-understanding, explain, propose, build and review follow the fixed step order. No stage has a producer yet, so understand, explain, build and review store the human-written text encrypted in the project's blob store, sign it as an `a4-stage-output` artifact, and record it as a self-reported implementation-lane evidence ref. Review records its observed checks as not evaluated (`NO_PRODUCER_REGISTERED`). Once a stage's lane registers producers, these generic steps answer 409 `A4_PRODUCER_REGISTERED` for that stage. Gates are requested, approved, denied, sent back for changes and consumed through `…/complete { gateId, expectedHeadSeq, clientRequestId }`. A policy gate is approved or denied, never sent back (409 `A4_STEP_ORDER`). Effect gates are opened and retried under `…/effects/:effectId`. When an owner opened an effect gate on the gate being completed, `…/complete` runs that effect and answers its `attemptId`; consuming such a gate without its effect is 409 `EFFECT_REQUIRED`. A retry first settles a lost attempt of the same execution as `process_lost`. A hypothesis is observed through `…/hypotheses/:id/observe`. Every mutation carries a `clientRequestId`: a retry answers the recorded result (including an `attemptId` or a minted `agentId`), and a reused id with another body is 409 `REQUEST_CONFLICT`. A stale head is 409 `A4_STALE_HEAD` with the head and a transitions link; members, evidence and observe evaluate readiness on exactly the head the body names. A stored row that no longer parses is 409 `A4_INTEGRITY_FAILED`, never a 400.
- Claims: `GET /projects/:id`, `…/readiness`, `…/conformance`, `…/value`, `…/monitor` and `…/verify` are result routes whose wrapper repeats the record's own `claim` (`ClaimSource` `a4_record`); readiness, conformance and value are regulated. Value, monitor and conformance answer `not_evaluated` until their producers land. `GET …/verify` takes no query parameters and runs `verifyA4Chain` under the server operator's trust list, before any verified read, so workspace OWNERs, AUDITORs and the admin token see the report of a chain that fails (other principals get 403 when membership cannot be read from it). It reports integrity of bytes under this workspace's keys, which is not evidence about the agent. `GET …/gates` (`amc.a4-gate/v1`) states each gate's A4 status (`CONSUMED`, `STALE`, `CHANGES_REQUESTED` and the open states), the engine's quorum status as reported, and whether the binding digest recomputes from the stored request.
- `amc verify all` gains the `a4-projects` check, one row per project that any A4 row or audit session names, so a deleted project head fails rather than vanishing: a changed transition body fails with `A4_CHAIN_INVALID`, a missing or changed side row fails with `A4_SIDE_ROW_MISMATCH`, and a row no transition names fails with `A4_SIDE_ROW_UNNAMED`. Other failures are a decision not bound to its gate's request digest (`freshness: fail`; it counts for nothing), a gate request, gate decision, release, deployment or rollback transition without its `A4_RECORD` envelope (`A4_ENVELOPE_MISSING`), a ref whose stored trust tier is above what the referenced row can read under any trust list (`TRUST_TIER_INFLATED`), a self-approval the chain does not derive, and a credential in a stored request response. A stored tier that only the current trust list contradicts (an attestor unpinned since) is the warning `TRUST_TIER_CHANGED`. A ledger that predates migration 13 skips the check, and one at or after it without the A4 tables fails. Readiness on GET and at `complete` carries this verifier report in its integrity section.
- Audit: gate requests, decisions and holds are mirrored to the human action log and sent as notification-only integration events (`A4_GATE_OPENED`, `A4_GATE_DECIDED`, `A4_HOLD`). `amc mode agent` blocks `a4 acknowledge`.
- OpenAPI: `website/openapi.yaml` publishes the A4 routes and request schemas (`node scripts/update-native-task-openapi.mjs` after a build), with `ClaimResult` on the result routes.
