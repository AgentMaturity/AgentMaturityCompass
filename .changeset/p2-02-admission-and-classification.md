Protected-data admission (experimental, opt-in P2-02) now covers the gateway and the bridge, and its refusals are classified everywhere they surface. These changes apply only in a workspace that has a processor registry (`.amc/dataflow/processors.yaml` or its `.sig`); other workspaces are unchanged.

- **Gateway and bridge admission.** The gateway runs the same processor and purpose admission as native model requests on every provider call it forwards. It checks what the provider would receive: the request target with the agent's credentials stripped, each forwarded header under its name, and the body, which must be UTF-8 text the detectors can read. A binary or compressed body is refused with `detector_invalid`. The gateway records `PROTECTED_DATA_DETECTED`. When admission refuses, it also records a `DATA_FLOW_REFUSED` audit row and answers 403 with `{ "error": "DATA_FLOW_REFUSED", "reason", "processorId", "purposeId" }`, before it applies the upstream credential or calls the provider. Bridge provider calls always relay through the gateway, so the same admission applies to them.
- **Typed refusals.** A refusal now names the registry processor and purpose it decided on, never the refused content. In the native loop, the request-retry layer records it as a `DATA_FLOW_REFUSED` audit row and never retries it. If automatic compaction's summary request is refused, compaction skips the summary and the turn continues uncompacted. The run diagnostics, live error notifications and ACP turn failures report `DATA_FLOW_REFUSED` with the reason, processor and purpose, where they used to report `UNKNOWN` or a generic failure.
- **Escaped password keys.** The password rule now reads member names with their JSON and web escapes decoded. A `password` key written with escapes, even escaped twice, is detected in parsed JSON, in text that does not parse, and in tool-call arguments. The detector-set digest's walk revision is now `protected-walk-v2`.
- **Monitored process rows.** A stored PEM private key block is now recorded as `PRIVATE KEY <AMC_REDACTED>`, so the transcript `POLICY_VIOLATION` audit still sees the keyword. The `api_key` and `password` keywords were already kept, with only their values replaced. A delegated foreign child's answer, built from those rows, no longer includes the redaction markers.
