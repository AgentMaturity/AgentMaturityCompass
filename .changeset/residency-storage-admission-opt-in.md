Residency storage admission and egress checks are opt-in, including when the control checkpoint root sits inside the workspace. A workspace opts in with a destination registry (`.amc/residency/destinations.yaml` or its `.sig`) or with a compiled-plan journal that reports an active plan or fails to verify. When the checkpoint root (`AMC_CONTROL_CHECKPOINT_DIR`, default `~/.amc/control-checkpoints`) is inside the workspace, that journal cannot be verified, so the existence of `.amc/control-plan/` (or a failure to inspect it) is what opts the workspace in. With the root outside the workspace, `.amc/control-plan/` alone opts nothing in, and a journal deleted behind its host checkpoints is still an integrity failure.

Before this fix, a workspace that contained its checkpoint root refused every session open, every egress check and every native agent toolset, even with no plan and no registry. This happened, for example, after `amc init` in the home directory. The refusals named the wrong cause: `registry_unverifiable (active_policy_unverifiable)`, or advice to restore `.amc/control-plan/`. The compiled-plan loader now reads such a workspace as having no plan, and the native agent toolset, Studio native tasks, the kernel tool service and the compiled-policy guard all load the plan through it. An opted-in workspace in that configuration is still refused, under its own name: `registry_unverifiable (control_checkpoint_root_in_workspace)` from residency checks, `ControlCheckpointRootInWorkspaceError` from the agent toolset, and `NATIVE_CONTROL_CHECKPOINT_ROOT_IN_WORKSPACE` from Studio. Each message names `AMC_CONTROL_CHECKPOINT_DIR` and the condition without host paths, because these messages reach HTTP and tool responses. Legal-hold reads there report `control_checkpoint_root_in_workspace` instead of `record_corrupt` or `registry_unreadable`, and deletion stays refused. A present but invalid registry, or an active plan that does not verify, still refuses. `LlmRuntime` also no longer requires a session workspace at construction. The workspace is read when a check runs: the egress check refuses a missing one as `workspace_scope_required`, and protected-data admission treats it as an invalid registry, not a missing one.
