The native TypeScript SDK has a documented public API and semver policy; amc init --coding and --regulated create ready, signed starter workspaces; quickstart added (P1-40).

- sdk-api: `agent-maturity-compass/sdk/native` marks its stable surface `@public` (`AMCNativeClient`, `AMCNativeSession`, `AMCNativeTurn`, their options and update types, and the six `AMCNative*Error` classes); everything else that entry exports, and the `promptParts` and `promptAudioParts` members, is experimental. The snapshot `sdk/api/native.api.md` is generated from the built declarations, and `npm run check:sdk-api` (in CI) fails when it is stale or changed without a changeset that mentions `sdk-api`. `createA4Client` (package root) is tagged experimental, an A4 preview. The policy is in docs/sdk/TYPESCRIPT_SDK.md.
- `amc init --coding` signs a `tools.yaml` with `fs.read`, `fs.write` and `fs.edit` over the workspace and `bash` confined by the OS (`nativeSandbox: os-native`, writable `.`, no egress), a `warn` firewall, the default budgets, `profile: dev`, and a signed `users.yaml` with the operator as the ACTIVE OWNER. `amc init --regulated` does the same with a `block` firewall, a signed approval policy, a signed preset `regulated` (every tool call waits for a signed approval under the WRITE_HIGH rule), `profile: prod` with `trustBoundaryMode: isolated`, and a Layer 0 control plan compiled and signed from a starter deployment profile whose facts are all unknown. That plan is experimental (D-08 is open), stays blocked until the operator states `useCases` and `jurisdictions`, and is not activated: activation needs two OWNER or AUDITOR approvers other than the requester. Both print readiness, the monitor fingerprint to pin and the next command.
- Both flags refuse each other, `--minimal`, `--trust-boundary`, `--skip-vault` ("A regulated workspace needs a real vault passphrase; set AMC_VAULT_PASSPHRASE or run interactively.") and an existing `.amc` directory. The vault passphrase and the owner's login come from the operator (the environment they set, or a masked prompt); nothing is generated or printed.
- The stub provider makes the call a prompt spells out as `{"tool": "<offered tool>", "arguments": {...}}`; any other prompt behaves as before. `examples/sdk/quickstart.mjs` uses it for one governed `fs.write` and labels every output line synthetic. `npm run check:packed-install` now runs `amc init --coding` and that quickstart against the installed package and records its time.
- docs/NATIVE_SDK.md now says that `closeAndVerify()` needs the monitor key pinned (`AMC_EXPECTED_MONITOR_FINGERPRINT` or a trust list): the bundled verifier refuses an unpinned ledger, so this package never returns `workspace-key-consistency`.
