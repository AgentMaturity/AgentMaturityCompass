Evidence is verified on read, and empty inputs are no longer scored as a pass (GAP-WP37). Trust certificates, the trust drift monitor, audit binders, passports, the drift freeze detector, forecasts, failure-risk indices, org scorecards and bench collection now read only diagnostic runs whose seal verifies (`listVerifiedRuns` / `loadVerifiedRunReport`); `amc cert generate` refuses to sign when no sealed run verifies or when a tampered, unreadable or newer unsealed run would roll it back to older evidence (`--preview` still works); passports and binders then record insufficient evidence, the drift freeze check reports `INSUFFICIENT_EVIDENCE` and the trust drift monitor returns `evidenceStatus` and `unverifiedRuns`, and records the source run's `scoreSourceRunSha256`. `latestAssuranceByPack` skips assurance reports whose seal fails, so its nine callers inherit the guard, and binders and passports embed an assurance certificate only when it verifies. The Studio/API assurance run view uses the runner's own record: unmeasured evidence gates read 0, not 1, and an insufficient-evidence run reads `INSUFFICIENT_EVIDENCE`. `amc verify all` and `amc evidence verify` report `INCOMPLETE` (exit 1) when a critical check was skipped, with `skippedCritical` in the JSON. Micro-canary count probes SKIP without audit telemetry; `amc confidence calibration` prints `not_evaluated` instead of 100%; bench comparisons without an imported population report null percentiles and missing risk indices score as worst case; continuous red-team reports over zero attacks are `INSUFFICIENT_EVIDENCE`; hallucination detection without grounding returns `passed: null` (`outcome: not_evaluated`); the Shield trust pipeline treats missing trust context as untrusted. Workspace record registers gain `verifyWorkspaceRecords` (hash, signature and chain findings), updates keep the superseded revision, and the residency report lists record integrity findings as violations.
