Compose images are pinned through `.env`, the deploy/compose Studio services have resource limits, and they receive a backup passphrase secret (LIVE-DEPLOY-08). Every studio-target service in the four compose files names its image `${AMC_STUDIO_IMAGE:-amc-studio:local}` and the studio-api overlay `${AMC_API_IMAGE:-amc-api:local}`, so `up -d --build` still works for a first install while an upgrade or rollback changes the pin in `.env` and runs `up -d --no-build`; keep the previous value, and note that `docker image prune` deletes an untagged rollback image. The two `deploy/compose` Studio services are limited to `AMC_STUDIO_CPUS` CPUs (default 2, new in `.env.example`) and 2 GB of memory with a 512 MB reservation; Docker refuses to create a container whose CPU limit exceeds the host's CPU count, so a 1-vCPU host sets `AMC_STUDIO_CPUS=1`. They also mount a sixth secret, `amc_backup_passphrase` (`deploy/compose/secrets/amc_backup_passphrase.txt`, template beside the others), as `AMC_BACKUP_PASSPHRASE_FILE`, for `amc backup create` run inside the container. Existing deployments must create that file before the next `docker compose up`, or Compose refuses to start the stack.
