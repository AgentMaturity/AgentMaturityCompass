A4 Assemble runs AMC's own producers for the native path, behind the A4 preview (`AMC_A4_PREVIEW=1`). Assemble asks 11 questions (`riskTier` and `stations`, carried from Aspire by Understand and marked `CARRIED_STALE:<id>` when they no longer equal Aspire's; `capabilities`, which depends on `stations`; `autonomy` (`advise` or `act_with_approval`), which depends on `riskTier`; `tools` and `validation`, which depend on `autonomy`; `connectors`; `providers` (`stub`, or `provider:model` for a native provider); `existingSystems`; `budget`; `path`). Understand records the tool pipeline's readiness, the doctor's checks, the native task limits, providers (credential reference and `configured` only), tool scope and validation config read from Studio's live native task service, the integration frameworks, mechanic profiles, the compiled plan, the open `outcome_unknown` executions, the Enforce state and the IntegrationClaim path table, each as a self-reported stage output. Explain renders the enforcement boundary, the outcome_unknown lockout, the limits, the chosen path's claim, the shell gate (the runtime's own `nativeShellReadiness` decision, boundary and enforcement, which Understand records) and the stub provider at three levels. Propose builds the plan from the answers (no part is edited by hand): the typed graph with the agent node's permissions, tasks by executor, the agent's preset, one native build session, the validation plan, unsupported items with their keys, and the agent's baseline Enforce state, which readiness `baseline_manifest` requires to be ACTIVE and to equal what the proposal revision bound.

The IntegrationClaim table (`src/a4/assemblePaths.ts`): `native` is supported at `tool_pipeline`; `claude-code` is preview (`P1-23 (held on D-02)`); `pi` is unsupported (`P1-22 (held on D-02)`); `langgraph`, `langchain`, `crewai`, `openai-agents` and `vercel-ai` are gateway previews (`P1-54`); `generic-http` and `other` are previews with no enforcement. Readiness `path_supported` and `unsupported_acknowledged` stay WAITING with `UNSUPPORTED_INTEGRATION` until an owner acknowledges them out of scope with a reason: `path_supported` names the path's key (`KEY:<key>`), and `unsupported_acknowledged` names each item (`UNSUPPORTED:<id>:<key>`). The `native` row says the shell is confined by Bubblewrap on Linux or Seatbelt on macOS, refused when no backend is available, and unenforced only under the operator's macOS unconfined opt-in. A non-native path's scaffold, connect and trace import are described in the external-path changeset.

Build at Assemble is an owner action (`POST …/stages/assemble/build` takes a workspace OWNER and owner mode). Before any write it needs the signing key, a validly signed Enforce baseline manifest, a verifying `.amc/agents.yaml` and the native session's admission as Studio's native task route checks it (read-only refusal, the human execution identity, the approved provider still offered with its credential configured, the same tool-scope digest and validation config). It then writes the revised typed graph, signs the agent's preset `a4-<agentId>` into `.amc/agents.yaml` (readiness `preset_signed`; every revision now binds `composition.presetSha256`, and a presets file that does not verify is `RESOURCE_UNREADABLE`), journals the session's exact start in the revision, and Studio starts it on its own native task service once the step is recorded; the build response names the session (`sessions`). Review is run by the session's owner (`SESSION_OWNER_REQUIRED` otherwise) and refuses while a session runs (`BUILD_RUNNING`) or has failed (`BUILD_FAILED`, with the resume route). It records AMC's `verifyAgentRun` as the integrity item `build_sessions_integrity` with its `VerifierReportV1` attached (`VERIFICATION:workspace-key-consistency`, `SELF_CHECK`, `UNANCHORED` without a pinned monitor key), the session, its validation and the capabilities list as `synthetic_example` on the stub provider (with the review wording "tool pipeline observed on a stub model; agent behaviour not evaluated" in the bound revision), action-evidence coverage, and Enforce's evaluation of the pending changes. Review records the agent's lifecycle stage as `lifecycle/state.json` holds it, read without writing (`not_evaluated` with `LIFECYCLE_STATE_ABSENT`, `_UNREADABLE` or `_INVALID` otherwise). No lifecycle stage is advanced: `lifecycle_bridge` reads NOT_EVALUATED with `LIFECYCLE_STAGE:<stage>`, `unit_tests_passing` (not evaluated on the stub provider) and `KEY:A4_LIFECYCLE_WRAPPER`, because the development → testing bridge waits for the A4 lifecycle wrapper. On a real provider an answered capability reads "listed in the build prompt; not evaluated".

Completing Assemble runs the effect `a4.assemble.apply` (`WRITE_HIGH`, consumed by A4): an owner opens the effect gate once the completion gate has its quorum, project approvers decide its engine request from the A4 card (`POST …/approvals/:approvalRequestId/approve|deny`, bound to the request digest, as the signed-in member; `EFFECT_GATE_OPENED` now records `requestDigestSha256`), and `complete` applies the bound Enforce resource set with `applyEnforceResourceLifecycle`, recording its signed receipt. The A4 card also clears an `outcome_unknown` lockout: readiness `no_open_outcome_unknown` is BLOCKED while one is open (`EXECUTION:<id>`); `POST …/outcome-unknown/:executionId/request` files the operator's statement as an `amc.action.resolve` engine request (the statement is scanned for secrets first; the note is sealed in the project's blob store, and the engine request and the action journal carry only a reference naming the sealed blob and the note's sha256), another project approver or owner decides it from the card, and `POST …/outcome-unknown/:executionId/resolve` records it with `resolveManually` as a self-reported implementation ref (the details are in the external-path changeset). Re-opening an effect gate is refused while an attempt of that effect is still running (`EFFECT_RUNNING`), and the re-open check counts a voter who could re-run a consumed gate's effect by `retryEffect`. Studio's Assemble view adds Integration paths, Plan, Outcome unknown and Completion effect cards and an Acknowledge control for the two unsupported items. The native task descriptor does not carry the A4 project yet, so a session is attributed to its project only by the project's own record.
