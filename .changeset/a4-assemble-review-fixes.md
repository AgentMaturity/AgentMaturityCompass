A4 Assemble review fixes (behind `AMC_A4_PREVIEW=1`), plus one presets hardening outside A4.

- Trace import refuses a source that was already imported (`409 IMPORT_EXISTS`, naming the import id). The neutral importer's import id is fixed per source and agent, so a second import of the same source used to rewrite, and on a refused record roll back, the files an earlier record names. Only an import the call itself created is rolled back, and the import runs pinned to the semantic digest of its dry run (`IMPORT_SOURCE_CHANGED` if the source changed in between).
- Whoever scaffolds, connects or imports on an external path counts as a builder of the stage. Their key joins the completion gate's excluded keys and the exclusions of the `a4.assemble.apply` effect request, so they cannot approve their own build work. Builders are now counted from every revision since the stage's consumed direction gate, the range authors already use.
- Review refuses a build session that is still open (`409 A4_NOT_READY`, `BUILD_SESSION_OPEN`, `STATE:<state>`). An idle or released session can take more turns after Review, so the owner verifies it on the native tasks page first, which closes it.
- Build refuses, before any write, a session start that Studio's native tasks would refuse: a check missing from the operator's validation config, checks without the signed workspace `bash`, or a body the native start schema rejects (`ANSWER_INVALID:validation`, `ANSWER_INVALID:capabilities`). Propose leaves checks that cannot run out of the plan and lists them as unsupported (`NOT_IN_VALIDATION_CONFIG`, `VALIDATION_SCOPE_REQUIRED`). The `validation` answer must hold 1 to 8 distinct check ids of letters, digits, `_` and `-` (`ANSWER_INVALID:validation`). The build prompt drops control characters from the capabilities and is cut by code point.
- Review lists a session's effective-policy receipts from its signed `EFFECTIVE_POLICY` ledger rows, not from the receipt directory. A receipt file that is missing, unsigned or does not hash to its row's `artifactSha256` makes the record `unverified` (`RECEIPT_MISSING`, `RECEIPT_SIGNATURE_INVALID`, `RECEIPT_MISMATCH`), and the downgrades come from the ledger rows.
- Every answered capability is recorded `not_evaluated`, also on a real provider, because nothing maps a check or a session output to it.
- If the action journal settled an `outcome_unknown` resolution under the project's request but the project record was refused, `no_open_outcome_unknown` stays BLOCKED (`RESOLUTION_UNRECORDED:<execution>:<request>`), and the Outcome unknown card keeps "Record the resolution" for it. An action chain that does not verify makes the item NOT_EVALUATED (`ACTION_JOURNAL_UNREADABLE`).
- Approvals and denials cast from the A4 card on engine requests (effect gates, resolutions) are mirrored to the human action log as `HUMAN_APPROVAL_DECISION`, as Studio's approvals page already does.
- Presets: `readPresets` checks the `.amc/agents.yaml` signature over the same bytes it parses (one read), and `savePresets` signs exactly the bytes it wrote. A file swapped in between is never parsed as verified or signed. `signFileWithAuditor` and `verifySignedFileWithAuditor` take an optional `bytes` argument for this.
