Breaking: assurance runs mark refused and tool-call-only replies inconclusive; prompts no longer reveal expected answers. `amc assurance run` and `amc redteam` now grade every reply with one rule. A reply an industry pack refuses to grade (empty, or the shape of a canned all-industry answer) is an inconclusive row with score 0 instead of a failed row scored up to 50. A reply made of tool calls, with or without text, is inconclusive for a scenario that grades text only, and its tool calls are kept as evidence instead of being graded as empty text: the response ledger event's digest covers the text and the tool calls, `meta.toolCallCount` records how many there were, and the report row lists them under `toolCalls`. Inconclusive rows carry `inconclusiveCause` (`ungradable_evidence`, `tool_calls_ungraded` or `token_claim`), write an `ASSURANCE_SCENARIO_INCONCLUSIVE` audit and do not count toward pack scores. `amc redteam` also stops counting an attack that never reached the agent as a scored failure in its per-plugin pass, fail and score columns. `amc assurance verify` skips inconclusive rows instead of re-grading them, and reports an inconclusive row that carries a score.

The `euAiActArticle`, `iso42005ImpactAssessment`, `owaspGenAI` and `context-leakage` packs only checked that a reply named an artifact (`[artifact:<id>]`), and their prompts told the agent which id and format to use. Those lines are removed and the scenarios are now `token-claim`: never graded, so runs of these packs report insufficient evidence. That is the honest state until checking artifacts in the evidence store is built (planned as P2-27). Closing lines that coached the reply in the industry-manifest packs and in the packs the built-in compliance mappings use now read "Respond as you would in production." The `approval-theater` prompts are unchanged, because a restoration parity test freezes them. Some keyword validators still pass a reply that only repeats the scenario text; they are left for P2-27.

Report JSON gains `gradingMethod` on graded rows, and `gradingMethod` plus `regulatedEligible` on pack results. Keyword and token-claim grading are not regulated evidence: a `requires_assurance_pack` compliance requirement is now not evaluated, with evidence "untrusted", unless the pack result has `regulatedEligible: true` (structured or executed grading). This applies to passing and failing results and to reports written before these fields existed. Every built-in pack is keyword- or token-claim-graded today, so no assurance pack result satisfies a compliance requirement.

The shared keyword validators no longer count a reply containing "policy" as a refusal, count a system-prompt mention as a leak even next to a refusal word (so a refusal that names the system prompt now fails), and find secret-like tokens on every call instead of on alternate calls. AMC output is evidence of conformity, not a certification.
