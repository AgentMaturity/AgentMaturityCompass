Breaking: native session writers are fenced by a signed epoch and a lease, a replaced writer dispatches nothing, and resume applies a rule to every interrupted tool call (P2-12).

- Every native session row's writer meta is version 2: `{ v: 2, token, pid, hostId, state, epoch, leaseMs }`. `session/open` claims epoch 1 and every later claim must raise the epoch of the signed row it follows by exactly one, checked in the append transaction (SQLite) or writer mutex (JSONL). AMC 1.x cannot resume a session a 2.0.0 writer has appended to. A version-1 row after a version-2 writer is refused `INVALID_FENCE`.
- A writer that a newer claim replaced is refused `STALE_EPOCH` (it was `STALE_HEAD`) at its next append, and before every model request and governed tool body it re-reads the session's last signed row and dispatches nothing unless that row still names it at its own epoch. An unreadable writer meta is refused `UNSUPPORTED_OWNER`. These refusals write a signed `SESSION_WRITER_FENCE_REFUSED` audit row in their own sealed ledger session; if that row cannot be written, the refusal still stands and says so.
- A lease (`leaseMs`, default 60,000 ms) is live while the session's last signed row is younger than it; an idle writer between turns appends a signed `session/heartbeat` row at half the lease. A remote owner, a local owner whose liveness cannot be established, or a live but unresponsive local owner can be claimed only with the new option `amc agent-loop run --session <id> --takeover-expired-writer "<reason>"`, and only once its lease has been expired for one more lease by the claimant's clock. The claim row records the reason, the replaced owner and epoch, its last row's time and the lease expiry; the store re-derives that record and refuses one that does not match. Without the option the refusal stays `LIVE_WRITER` and names when a takeover becomes possible. JSONL sessions are not taken over.
- A dispatch and a resume raise this machine's high-water mark for the session journal in `<AMC home>/state/high-water.json` (P1-08's store). Resume refuses a journal older than the mark (`ROLLBACK_DETECTED`) or holding other bytes at the marked sequence (`FORK_DETECTED`); `amc session recover` reports either as `TAMPERED`.
- The first version-2 claim on a version-1 owner's session is followed by one signed `session/migration` row (`fromVersion`, `toVersion`, the source head's id and hash, the reason). Earlier rows are never rewritten.
- Resume never runs a call again. `runComposedTurn` now runs `reconcileInterruptedCalls` before a resumed turn's first request: each call recovery answered with an unknown outcome gets a resume rule from `resumeRuleFor` (`may-repeat` for `READ_ONLY`; `repeat-with-same-idempotency-key` for `fs.write`/`fs.edit` whose file still has its recorded `beforeSha256`; `reconcile-first` for every other class, every MCP tool and an unknown class) and one signed `tool/reconciled` row with the result `completed`, `denied`, `not-found` or `unknown`. A `reconcile-first` call whose execution is `outcome_unknown` is asked of its system of record through `reconcile()` with the adapters passed as `resume.reconcileAdapters`; `amc agent-loop run` passes none, so there it stays `unknown` and the journal keeps blocking the agent's later consequential calls until `amc action resolve`. `ComposedTurnOutcome.resumed` is now returned and carries `interruptedCalls`.
- The evidence-event contract adds the event types `session/heartbeat`, `session/migration` and `tool/reconciled`; `ResumeRefusal` adds `ROLLBACK_DETECTED` and `FORK_DETECTED`; `SessionWriterRefused` adds `STALE_EPOCH`.

Signatures are checked against the workspace's own keys: a local audit trail, not a portable verdict.
