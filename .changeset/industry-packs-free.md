Industry Packs are free for everyone (ADR 019): every pack's questions and runs work with no licence, checkout, account or payment on the CLI, Studio, MCP, the dashboard and the console. Pack results are still self-reported questionnaires whose content is experimental, and access never changes a score, gap, report, trust tier or verification outcome.

- No gate remains: `amc domain pack describe|run` and `amc domain assess|gaps|report|assurance|roadmap|apply` run without a licence; Studio `GET /industry-packs/<id>` no longer answers 402 and returns 200 `{ pack, entitlement, entitlementNote }` (404 for an unknown id); the MCP tools `amc_get_industry_pack` and `amc_score_industry_pack` no longer refuse with `industry_packs_locked`, and `amc_score_sector_pack` no longer refuses with the paywall text. The dashboard and console drop their locked states, and the console its checkout button and licence form.
- The entitlement (`amc domain pack access --json`, Studio `/industry-packs/access`, `/industry-packs/list`, `/industry-packs/checkout` and `/industry-packs/<id>`) always reads `active: true`, `source: "free"`, `planId: "industry-packs-free"`, `priceUsdMonthly: "0.00"`, `checkoutAvailable: false`, `checkoutUrl: null` and `expiresAt: null`. Catalogue items keep `locked`, which is always `false`. `amc domain pack access` prints `Price: free` and `Status: active`, and `amc domain pack list` prints `(free, all included)` and no Access column.
- Checkout is gone. `amc domain pack checkout` prints the free message and exits 0 (`--json`: `checkoutUrl: null` and the entitlement); its `--success-url`, `--cancel-url`, `--email` and `--reference` options are accepted and ignored. Studio `GET|POST /industry-packs/checkout` answers 200 `{ checkoutUrl: null, entitlement, entitlementNote }`. The hosted API (`api/index.ts`) answers `POST /api/industry-packs/checkout` and `GET /api/industry-packs/access` with 200 `{ planId: "industry-packs-free", priceUsdMonthly: "0.00", checkoutAvailable: false, checkoutUrl: null, message }`, and `/api/health` reports `industryPacksPlan: "industry-packs-free"` and `industryPacksPriceUsdMonthly: "0.00"`.
- Kept for existing licence holders, and not needed for access: `amc domain pack activate --key` still records a licence that verifies against an `artifact-seal` key pinned in the trust list and says it changes nothing; `amc domain pack verify --key` still verifies one; Studio `POST /industry-packs/activate` and `POST /industry-packs/license/verify` and the hosted licence issue, verify and webhook endpoints are unchanged. Licences keep the plan id `industry-packs-monthly`.
- Studio's `entitlementNote` reads "Industry Packs are free; access never changes a result, a trust tier or a verification outcome."

Migration: nothing is needed for access. JSON consumers of the entitlement see `source: "free"` (was `env`, `file` or `none`), `planId: "industry-packs-free"` (was `industry-packs-monthly`), `priceUsdMonthly: "0.00"` (was `"9.99"`) and `checkoutUrl: null`; stop branching on `active`, `locked` or `industry_packs_locked`, which no longer vary. Scripts that expected `amc domain pack checkout` to exit 1 or Studio `GET /industry-packs/<id>` to answer 402 now get success. A licence stored in `.amc/industry-packs-access.json` or set in `AMC_INDUSTRY_PACKS_LICENSE_KEY` is no longer read for access.
