Key lifecycle (P1-08): one signing key per purpose, signed rotation statements, atomic key changes, anti-rollback marks, single-file anchored revocation lists, m-of-n trust roots with signed root-set rotation, and `amc keys list|rotate|revoke|export-public`. See docs/KEY_LIFECYCLE.md.

- Purposes: `ledger-row`, `receipt`, `artifact-seal`, `revocation-list`, `config-signature`, `lease` and `session` each sign with their own key, taken from `getSigningKey(workspace, purpose)`. On the first unlock, a 1.x vault (payload v1) becomes payload v2 with the same key bytes, so no public key changes; the v1 envelope is kept as `.amc/previous-vault.amcvault`. AMC 1.x cannot read a v2 vault: downgrading is unsupported.
- Key changes (vault creation, migration, rotation) are one key-set generation, staged and committed by rename. Signing and verifying refuse while a generation is pending; `amc keys rotate --resume` finishes or rolls it back without deleting key material.
- `amc keys rotate --purpose <p>` writes a signed, chained `amc.key-rotation` statement (overlap at most 30 days, default 7; `key-compromise` needs a pinned root). `amc vault rotate-keys` remains as an alias for the monitor purposes.
- Revocation lists are one signed, sequenced file, anchored in the workspace transparency log and in this machine's high-water file (`<AMC home>/state/high-water.json`). An older list, a fork, a deleted list once anchored, or a symlinked anchor is refused. Lease revocations move from `revocations.json` + `.sig` to `revocations.signed.json` on the first write; the old pair is replaced by a tombstone, so a 1.x binary refuses every lease instead of reading an empty list. `amc lease resign-revocations` refuses a store that fails the schema, and revocations of expired leases are pruned with the sequence still rising.
- Every key use checks the workspace's key revocation list (`keys:<workspaceId>`); a missing or unverifiable list refuses every key.
- Trust lists: `trust-roots.json` may set `threshold` (m-of-n) and `rootSetId`, and a list may set `rootThreshold`. Flags never lower the threshold, and this machine refuses an older list, an older list version or a lower threshold than it accepted. Root sets rotate only with an `amc.root-rotation` statement signed by m of the pinned set and m of the new set (`applyTrustRootRotation`; `scripts/trust-list.mjs root-rotate|root-sign|root-apply`); once rotated, an edited, missing or pre-rotation `trust-roots.json` is refused.
- Cross-agent claims bind issuer, audience, key purpose and id, issue and expiry times (at most 24 hours) and a nonce. `createAgentClaim` now requires `opts.audience`, and the API's create-claim body requires `audience`. `verifyAgentClaim(claim, policy, secret, expected?)` refuses without an expectation (audience, issuer, scope, grants, replay cache), and a shared-secret claim is never above `SELF_REPORTED`. 1.x claims no longer verify.
- API: `leaseRevocationPaths` returns `{ file, pending, legacyFile, legacySig }` (was `{ file, sig }`); `signLeaseRevocations` returns the signed `LeaseRevocations` (was the signature `Buffer`); `revokeLease` takes an optional `{ expiresTs }`; `verifySignedTrustList` takes an optional `threshold`; `TrustListErrorCode` adds `ROLLBACK_DETECTED` and `FORK_DETECTED`. `issueLeaseToken`, `verifyLeaseToken`, `revokeLease` and `revokedLeaseIdSet` keep their signatures and behaviour.
