The native `bash` tool is now offered on macOS, confined by Seatbelt, when `/usr/bin/sandbox-exec` is a root-owned system binary; the receipt says `boundary: "macos-seatbelt"`. `--unsafe-unconfined-shell`, `allowUnconfinedShell` and `AMC_UNSAFE_UNCONFINED_SHELL=1` now apply only on macOS without a usable `sandbox-exec`; elsewhere they are ignored. The macOS shell may write only to the signed `writableDirectories`, a private per-call `TMPDIR` (also its `HOME`) and `/dev/null`; it cannot read or write `~/.ssh`, `~/.aws`, `~/.config/gcloud`, `~/.azure`, `~/.gnupg`, `~/.kube`, `~/.docker`, `~/.netrc`, `~/.npmrc`, `~/Library/Keychains`, `~/.amc`, the workspace's `.amc` or the signed `readDeny` paths; it has no network, Unix sockets included. Other reads stay open, and the receipt's `limitations` say so. A run is reported `confined: true` only when a check inside the profile confirmed it before the command started.

The signed `bash.nativeSandbox` policy accepts `kind: os-native` (Bubblewrap on Linux, Seatbelt on macOS; `linux-bwrap` stays Linux-only and is refused on macOS), `egress.allowHosts`, `readDeny` and `maxProcesses`. On both platforms the shell runs under RLIMIT_NPROC set to your process count at launch plus `maxProcesses` (default 256), and write grants that contain your home directory are refused. On Linux, `readDeny` masks workspace paths and refuses system runtime paths. With `egress.allowHosts` on macOS, each call gets its own token-protected HTTP proxy on 127.0.0.1, passed as `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY`; it allows only listed hosts, refuses a listed name that resolves to a non-public address unless that IP literal is listed, and records every decision as a `NATIVE_SHELL_EGRESS` audit row before it takes effect. On Linux a signed `egress` is refused at launch until its relay is reviewed (ADR-008), so the Linux shell keeps all networking denied.

`NATIVE_SHELL_CONFINEMENT` receipts now carry `enforcement.boundary`, `reads`, `allowHosts` and `processLimit`, and `enforcement.network` is `denied` or `proxy-allowlist` (it was `socket-syscalls-denied`). The gateway forward proxy uses the same host decision; an IP-literal host no longer matches an allowlist entry by suffix. Studio's native-task options report the new `nativeSandbox` fields and the `macos-seatbelt` boundary.

Security: the shared egress decision treats IPv4-mapped, IPv4-compatible and NAT64 (`64:ff9b::/96`) IPv6 addresses by the IPv4 address they carry, and treats 6to4, Teredo, local-use NAT64, documentation, benchmarking and other reserved ranges as non-public, so an allowed name cannot reach loopback, a private host or 169.254.169.254 through such an address.

Security: the macOS shell cannot ask launchd, LaunchServices or another app to start a process outside its profile. Mach lookups are limited to five system services; opening apps, AppleEvents, launchd job creation, signals to and inspection of processes outside the shell's process group, running `open`, `osascript`, `launchctl` and `at`, and creating hard links are denied.
