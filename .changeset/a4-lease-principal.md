A4 leases now name the person who asked for them, so they work under the plans A4 Adapt activates. Layer 0's mandatory `L0-IDN-01` makes every such plan require a principal for every tool call, and a call under a lease that names no active `users.yaml` user is refused (`PRINCIPAL_UNRESOLVED`, P1-78). Before, Activate minted its staging and production leases with no principal, so under such a plan every call under them was refused.

- The release effect and the deployment approval's production-lease effect mint their leases through `issueLeaseForPrincipal`, naming the owner who ran the effect (read from the authenticated session, never from a body). Under a plan whose identity binding requires a principal, or a plan that does not verify, `complete`, `POST …/releases` and a retry refuse an owner who is not an active local `users.yaml` user, a workspace-router session included, with 409 `PRINCIPAL_UNRESOLVED` before the gate or the engine grant is consumed: readiness lists `PRINCIPAL_UNRESOLVED` under that caller's `progress` and `retryEffect` at Activate, and the effect's pre-flight resolves the principal again inside the transaction that would consume the gate or start the retry. The effect checks once more beside the `lease` and `revocation-list` key reads, before anything is revoked, written, minted or signed, and again when the lease is minted; a refusal there happens only when `users.yaml` or the plan changed after the gate was consumed, and it spends the attempt. Under any other plan the lease names that user when they resolve, and no one otherwise.
- New Activate readiness item `lease.principal`: READY `PRINCIPAL_NOT_REQUIRED` when the active plan requires no principal; WAITING `PRINCIPAL_REQUIRED` (never mandatory), naming the rule, when it does; BLOCKED and mandatory (`NO_ACTIVE_LOCAL_OWNER`, or `USERS_UNREADABLE`) while no active `users.yaml` user holds the workspace role OWNER and a lease is still to be minted this cycle, so neither the release approval nor the deployment approval is requested or approved for an effect no one could run (a `DENY` is not refused: it mints nothing, and on the deployment approval it revokes the staging lease); READY `PRINCIPAL_EFFECTS_DONE`, never mandatory, once the production lease is recorded. The Activate card shows it.
- Assemble connect names the owner in the connect lease the same way, and answers 409 `PRINCIPAL_UNRESOLVED` with nothing minted when the principal does not resolve under such a plan. `buildConnectInstructions` and `issueLeaseForCli` take an optional `principalKey`; without one they mint as before.
- Assemble Build refuses a native workspace-tools session whose lease would name no active `users.yaml` user under a plan that requires one, with 409 `PRINCIPAL_UNRESOLVED` before it writes the typed graph or the preset or journals the session. Before, Build recorded the step and the session then failed to start. Other lease-mint failures, a revoked or unreadable `lease` key (`LEASE_UNAVAILABLE`) or a plan that does not verify (`POLICY_UNVERIFIED`), still surface as the session's start error after the step is recorded.
- Adapt's `adapt.plan.nativeSessionsAllowed` now also lists `PRINCIPAL_REQUIRED` and `NON_LOCAL_USER_SESSIONS_DENIED` under a plan with `L0-IDN-01`, and its next action and Explain name the case: a Studio task whose signed-in principal is not an active local `users.yaml` user (a workspace-router session or the admin token included) is refused at start, 409 `PRINCIPAL_UNRESOLVED`.
- Adapt's context probe is unchanged: its turn makes no tool call and needs no lease.
