Industry Packs and enterprise licences verify only against a key pinned in the operator's trust list, and every locked surface states the same truthful paywall text (P1-51, D-06 = B). A licence unlocks access to pack questions and runs; it never changes a score, gap, report, assurance result or roadmap.

- Licence gates (`amc domain pack describe|run`, `amc domain assess|gaps|report|assurance|roadmap|apply`, Studio `GET /industry-packs/<id>`, MCP `amc_score_sector_pack`) accept only a licence whose Ed25519 signature comes from a key that the signed trust list in the AMC home pins for `artifact-seal`. `AMC_INDUSTRY_PACKS_LICENSE_PUBLIC_KEY`, `AMC_INDUSTRY_PACKS_LICENSE_SECRET` and `AMC_INDUSTRY_PACKS_LEGACY_KEY_SHA256_ALLOWLIST` (and their `AMC_DOMAIN_PACKS_` forms) no longer unlock packs, and a stored `.amc/industry-packs-access.json` counts only when its licence verifies against such a key. Licence issue needs `AMC_INDUSTRY_PACKS_LICENSE_PRIVATE_KEY`; an HMAC secret no longer issues licences.
- The locked text, on the CLI, Studio, console, dashboard, MCP and the hosted API, names what is locked, the price `US$9.99/month (plan industry-packs-monthly)` from one constant, and either `Buy: <checkout URL>` with the activation command, or `Checkout is not available in this deployment; contact sales for access.` Checkout is offered only when a checkout URL and a pinned licence key are configured (the hosted API: a checkout URL, `AMC_INDUSTRY_PACKS_LICENSE_PRIVATE_KEY` and `AMC_INDUSTRY_PACKS_ADMIN_TOKEN`). The default checkout URL, which pointed at a page that returns 404, is removed; `checkoutUrl` is `null` when checkout is not available. A refused licence is reported with its reason.
- Locked packs keep their name, own description, regulatory basis and compliance frameworks in `amc domain pack list --json`, Studio `/industry-packs/list` and the dashboard; the dashboard and console no longer show Subscribe, checkout or activation controls that cannot work.
- `amc domain pack activate --key` verifies locally and writes nothing when it refuses; the online verification fallback (`AMC_INDUSTRY_PACKS_VERIFY_URL`) is gone, and `--expires-at` is ignored because the expiry comes from the signed licence. Studio `POST /industry-packs/activate` answers 422 with the reason instead of 500, and `POST /industry-packs/license/verify` checks against the pinned keys. `amc domain pack checkout` exits 1 with the reason instead of throwing.
- Hosted API (`api/index.ts`): `GET /api/industry-packs/access` reports price and checkout availability instead of the server's own entitlement; `POST /api/industry-packs/checkout` answers 503 `checkout_not_available` with the reason instead of 400 `Invalid JSON body`. The admin token is compared in constant time. `POST /api/industry-packs/webhook` is no longer an admin alias of licence issue: with `AMC_INDUSTRY_PACKS_WEBHOOK_SECRET` set it verifies `Stripe-Signature` (HMAC-SHA256 over `t.` plus the raw body, five-minute tolerance), records each paid `checkout.session.completed` once per event id for admin issue, and never issues a licence; without the secret it answers 503.
- `amc enterprise activate <key>` takes an Ed25519-signed licence (`payload.signature`) instead of the `AMC-ENT-XXXX-XXXX-XXXX` format, which could never verify, and refuses with `enterprise licence verification not configured` when no key is pinned; a refused key is no longer stored. `amc enterprise status` reports `Licence verification: not configured` in that case and no longer lists tier features, because an enterprise licence gates no AMC feature.

Migration: put the licence issuer's Ed25519 public key in a signed trust list in your AMC home with purpose `artifact-seal` (docs/TRUST_LIST.md), then run `amc domain pack access` to confirm `Licence verification: configured`. Licences issued from an HMAC secret or allowlisted legacy keys cannot be activated. JSON consumers of the entitlement see `checkoutUrl: null` when checkout is not available and a new `licenseVerificationConfigured` field; consumers of `amc enterprise status` lose `features`.
