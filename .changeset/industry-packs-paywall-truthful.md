Industry Packs licences (`amc domain pack activate` and `verify`) and enterprise licences (`amc enterprise activate`) verify only against a key pinned in the operator's trust list (P1-51, D-06 = B). Industry Packs themselves are free in this release (`industry-packs-free`), so an Industry Packs licence is legacy and unlocks nothing; no licence ever changes a score, gap, report, assurance result or roadmap.

- `amc domain pack activate --key` and `amc domain pack verify` accept only a licence whose Ed25519 signature comes from a key that the signed trust list in the AMC home pins for `artifact-seal`. For them, `AMC_INDUSTRY_PACKS_LICENSE_PUBLIC_KEY`, `AMC_INDUSTRY_PACKS_LICENSE_SECRET` and `AMC_INDUSTRY_PACKS_LEGACY_KEY_SHA256_ALLOWLIST` (and their `AMC_DOMAIN_PACKS_` forms) no longer count. Licence issue needs `AMC_INDUSTRY_PACKS_LICENSE_PRIVATE_KEY`; an HMAC secret no longer issues licences. A refused licence is reported with its reason.
- `amc domain pack activate --key` verifies locally and writes nothing when it refuses; the online verification fallback (`AMC_INDUSTRY_PACKS_VERIFY_URL`) is gone. `--expires-at` is refused with "--expires-at is not accepted" and hidden from help, because a licence's expiry is the one its issuer signed into it and verification enforces it; Studio refuses a body `expiresAt` with 400. Studio `POST /industry-packs/activate` answers 422 with the reason instead of 500, and `POST /industry-packs/license/verify` checks against the pinned keys.
- `amc domain pack verify` checks the same keys as `activate`: `--pubkey` is removed and `AMC_INDUSTRY_PACKS_LICENSE_PUBLIC_KEY` is no longer pinned; without a pinned key it exits 1 with "licence verification is not configured".
- Hosted API (`api/index.ts`): the admin token is compared in constant time. `POST /api/industry-packs/webhook` is no longer an admin alias of licence issue: with `AMC_INDUSTRY_PACKS_WEBHOOK_SECRET` set it verifies `Stripe-Signature` (HMAC-SHA256 over `t.` plus the raw body, five-minute tolerance), records each paid `checkout.session.completed` once per event id for admin issue, and never issues a licence; without the secret it answers 503.
- `amc enterprise activate <key>` takes an Ed25519-signed licence (`payload.signature`) instead of the `AMC-ENT-XXXX-XXXX-XXXX` format, which could never verify, and refuses with `enterprise licence verification not configured` when no key is pinned; a refused key is no longer stored. `amc enterprise status` reports `Licence verification: not configured` in that case and no longer lists tier features, because an enterprise licence gates no AMC feature.

Migration: to keep verifying an existing Industry Packs licence, put the licence issuer's Ed25519 public key in a signed trust list in your AMC home with purpose `artifact-seal` (docs/TRUST_LIST.md), then run `amc domain pack access --json` to confirm `licenseVerificationConfigured: true`. Licences issued from an HMAC secret or allowlisted legacy keys cannot be activated. None of this is needed for access, because Industry Packs are free (`industry-packs-free`). JSON consumers of the entitlement see a new `licenseVerificationConfigured` field; consumers of `amc enterprise status` lose `features`.
