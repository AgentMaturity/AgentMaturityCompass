"agent-maturity-compass": major
---

Security: the gateway forward proxy (plain HTTP and `CONNECT`) now resolves the destination for every connection and refuses it when any address is non-public (loopback, private, link-local including 169.254.169.254, CGNAT, unique-local, multicast, reserved, and IPv6 forms carrying such an IPv4 address) unless that exact IP literal is in `proxy.allowlistHosts`. A listed name that does not resolve is refused. The connection goes only to an address it checked, so a DNS change between the check and the socket (DNS rebinding) cannot send an allowed name to an internal host. Before, the proxy checked names only and let the system resolve them again at connect time.

The gateway's requests to its upstreams are checked the same way: every request resolves the upstream's `baseUrl` host again, is refused with HTTP 403 and a `NETWORK_EGRESS_BLOCKED` audit row (carrying `upstreamId`) when an address is non-public or the name does not resolve, and connects only to a checked address. An upstream opts in to non-public addresses in `gateway.yaml`: the IP literal written as the `baseUrl` host, the new `allowNonPublicAddresses` list of IP literals (for example a private endpoint reached by name over TLS), or `allowLocalhost: true` for 127.0.0.1 and ::1. A `baseUrl` expanded from an environment variable opts nothing in by its literal host, because the configuration signature does not cover the variable.

Breaking for operators who reach an internal host by name through the proxy: list that host's IP literal next to its name in `allowlistHosts`. With `denyByDefault: false` every name still passes by name, but its addresses now meet the same non-public rule. Breaking for upstreams that reach a non-public address without an opt-in, for example `http://localhost:8000` without `allowLocalhost`, a LAN model server set through `OPENAI_BASE_URL` or `LOCAL_OPENAI_BASE_URL`, or a private endpoint: add one of the opt-ins above and sign `gateway.yaml` again.

`NETWORK_EGRESS_BLOCKED` audit rows now carry the refusal `reason` (naming the refused address) and `resolvedAddresses`; proxy request, request-error and tunnel rows record `resolvedAddresses`, and tunnel rows record `connectedAddress`, the checked address the tunnel reached. The diagnostic finding for these rows now reads "Gateway refused a network egress attempt" followed by the reason, instead of saying the host was not allowlisted. New helper `resolveAndCheck(host, policy)` in `src/enforce/egressAllowlist.ts` returns `{ addresses, decision }`; an empty resolution is a refusal (`EGRESS_UNRESOLVED`).

For routes with `refuseRequestFields`, the gateway now resolves the guarded upstreams again for every request and every proxied connection instead of once at start, and decides each request's refused fields on the addresses its upstream check resolved. A pinned connection is always a new socket (keep-alive reuse would bypass the pin), so upstream requests and proxied plain-HTTP requests no longer reuse connections.

A proxy client that resets while the proxy resolves its target or reads its body, or a `CONNECT` to a port outside 1-65535 (now HTTP 400), no longer ends the gateway process. A tunnel whose client leaves during the lookup opens no upstream socket; a tunnel's client closing now closes its upstream socket, and an error on either side or an idle timeout closes both.
