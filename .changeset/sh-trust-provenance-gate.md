Assurance scores carry provenance, and every reader refuses one without it (SH-TRUST-02, the pi comparator's deciding item 2). One predicate (`src/assurance/reportProvenance.ts`) sits beside the seal check in `verifiedAssuranceByPack` (compliance), `scanVerifiedAssuranceByPack` (governor, drift, indices, dashboards, bench), `latestAssuranceReports` (readiness gate) and `amc assurance cert-issue`: a sealed report counts only when it names its runner session, that session is sealed, and every graded row's stdin, stdout and test rows exist in it for the same pack, scenario and agent. A pack score with no graded row behind it, a report written to the AMC_NO_SIGN store, or a row whose session or test row disagrees is refused (`PROVENANCE_MISSING`, `PROVENANCE_UNSIGNED_STORE`, `PROVENANCE_UNRESOLVED`, `PROVENANCE_SESSION_UNSEALED`, `PROVENANCE_LEDGER_INVALID`, `PROVENANCE_RECEIPT_INVALID`); compliance lists the reason in `unverifiable[].reason`. When the gateway captured an exchange, its signed request receipt is stored on the scenario's stdout row and its id fills the previously always-empty `correlatedRequestIds`; the gate verifies it against the workspace receipt keys. Certificate issuance is blocked over a run with no sealed report or failing provenance.
