Assurance scores carry provenance, and every reader refuses one without it (SH-TRUST-02, the pi comparator's deciding item 2). One predicate (`src/assurance/reportProvenance.ts`) sits beside the seal check in `verifiedAssuranceByPack` (compliance), `scanVerifiedAssuranceByPack` (governor, drift, indices, dashboards, bench collector), `latestAssuranceReports` (readiness gate, passport companion), `loadAssuranceSummary` (maturity caps), the read-only bench reader, the signed benchmark export and `amc assurance cert-issue`: a sealed report counts only when it names its runner session, that session is sealed, and every graded row's stdin, stdout and test rows exist in it for the same pack, scenario and agent. A pack score with no graded row behind it, a report written to the AMC_NO_SIGN store, or a row whose session or test row disagrees is refused (`PROVENANCE_MISSING`, `PROVENANCE_UNSIGNED_STORE`, `PROVENANCE_UNRESOLVED`, `PROVENANCE_SESSION_UNSEALED`, `PROVENANCE_LEDGER_INVALID`); compliance lists the reason in `unverifiable[].reason`. When the gateway captured an exchange, the runner verifies its signed request receipt against the workspace receipt keys as the reply arrives; an admitted receipt is stored on the scenario's stdout row and its id fills the previously always-empty `correlatedRequestIds`, a bad one is audited (`ASSURANCE_RECEIPT_REJECTED`) and dropped while the row still counts. The gate verifies the runner session's own rows and seal (O(session), never a whole-ledger rehash on the governor's per-intent path). Certificate issuance requires auditor-signed `run.json` and `findings.json`, a report that names the run and agent, verifies its seal when it claims one and derives to exactly `run.json`'s score, and passing provenance; a planted, re-verdicted or missing report, or an edited `run.json`, issues nothing.
