Claude Code control hooks now run through absolute Node and CLI paths, deny with exit code 2 on every failure before the hook timeout, and `amc connect hooks status` verifies control with a probe.

Breaking for existing Claude Code installs: re-run `amc connect hooks install --provider claude-code` so the handler stops looking up `amc` on `PATH`; re-install also after upgrading AMC or switching Node, because the paths are absolute. A control install from the npx cache is refused. In control mode the hidden forwarder works under a deadline of at most 5 s, shortened by the time the process spent starting, so it ends at least 1 s before the 10 s hook timeout; a policy deny, empty or invalid input, a Bridge error or the deadline now exits 2 (it exited 0 or 1 before, which Claude Code treats as non-blocking). The forwarder also skips the native database-engine rebuild at start-up, which could exit 1 before the deadline began. When a `PostToolUse` or `PostToolUseFailure` delivery fails, the forwarder exits 2 with `{}` and says the outcome was not recorded and the action already ran; it does not claim a deny. `amc connect hooks status` and `health` print `Control: verified` only after the installed handler denied a probe, and they run the probe only while the provider config still matches the signed installation manifest, so a drifted or tampered handler is reported `Control: NOT VERIFIED (drifted)` and never run. A missing command, a failed probe, or `disableAllHooks` or `allowManagedHooksOnly` in settings also prints `Control: NOT VERIFIED`; `status` then exits 1, and `health` exits 1, or 2 when its signed-evidence projection already fails closed. `GET /api/v1/watch/hooks/{provider}/health` does not run the probe. Control is enforced at the Claude Code `PreToolUse` hook only while Claude Code runs it. Gemini CLI outputs and exit codes are unchanged; its forwarder gains only the deadline.
