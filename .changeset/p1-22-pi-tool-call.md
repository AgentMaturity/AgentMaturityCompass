Adds an optional Pi extension that sends Pi tool calls to AMC's hook control path (allow, deny, ask) with signed decision receipts; enforcement is limited to Pi's tool_call hook.

`amc connect hooks install|status|health|remove --provider pi` (`--mode observe` or `--mode control`; `pi` is a new value of the existing `--provider` option, not a new command) writes `.pi/extensions/amc.js`, a dedicated `0600` lease, the managed `.gitignore` block and a manifest signed by the workspace auditor key that binds the SHA-256 of that file and of AMC's extension module, the Bridge origin and AMC's monitor public keys. The extension is exported as `agent-maturity-compass/pi` (`createAmcPiExtension`). Pi loads `.pi/extensions/` only for a trusted project (or with `pi -e`); while Pi does not load it, nothing is enforced.

In control mode the extension posts every Pi `tool_call` to the loopback route `/hooks/control/v1` (new provider `pi`, runtime `pi`). AMC derives the action id from Pi's session and call id, denies a Pi version outside `QUALIFIED_PI_VERSIONS` (1.0.2 and 1.0.4; an unreadable version included, recorded as `unknown`), maps `read`, `grep`, `find`, `ls` to `fs.read`, `write` and `edit` to `fs.write` and `bash` to the shell command plan, each with a lowest action class the signed ToolHub config may give it, and denies every other tool (Codemode and extension tools included) with `Pi tool <name> is not mapped to an allowed ToolHub tool.` Every Pi `ask` is denied (capability-lossy): a Pi call cannot carry an AMC approval and Pi's own confirmation is not one; quorum policies deny. An allow binds a P1-02 authorization record (principal and delegation from the hook lease, idempotency key = Pi's call id, execution id = AMC's action id) and is recorded as a v2 `action_state` receipt whose body digest covers Pi's response and the digest of the exact request; `enforcement` is `enforced` at `pi:tool_call` only for a qualified version. The extension allows only when that receipt verifies under the pinned AMC keys and binds this call, then freezes the call's input. Each request carries a nonce, so re-sending a call is a conflict, never a second decision. Any error, timeout, malformed or unbound answer, bad signature, lease or manifest failure, unrecognised Pi event or Bridge outage blocks the call: `AMC control unavailable; action denied.` Observe mode never blocks; in both modes requested and finished calls are recorded as `observed` events without arguments or output.

Not covered: OS containment; effects that bypass `tool_call` (another extension's own I/O, Pi Durable, Codemode-internal calls unless step 2 confirms they emit `tool_call`). The qualification run confirmed that Codemode-internal calls emit `tool_call`; AMC denies the `codemode` tool in control mode. See docs/adapters/pi.md.

Internal: the provider request mapping and responses moved from `hookControl.ts` into `src/bridge/hookProviders.ts`, and the shared install helpers into `src/adapters/hookProviders/installFiles.ts`, with no behaviour change for Claude Code or Gemini CLI. `amc connect hooks health --provider` names `pi` among the accepted providers, and onboarding activation counts a Pi installation.
