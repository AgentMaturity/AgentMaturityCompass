The gateway now caps request bodies (LIVE-RUNTIME-01). A request whose body passes `AMC_GATEWAY_MAX_REQUEST_BYTES` (default 8 MiB, accepted range 1024 to 268435456) is answered 413 `{"error":"payload too large"}`, audited as `GATEWAY_PAYLOAD_TOO_LARGE`, and never forwarded; the forward proxy applies the same cap. A request whose lease does not verify (signature, expiry, revocation, workspace, agent, scope and route; the model is checked once the body names it) is refused with 401 or 403 before any of its body is read, so a forged lease-shaped header no longer makes the gateway buffer anything. Before, the gateway buffered request bodies of any size before it checked the lease, so any client that could reach the port could exhaust its memory. A client holding a valid lease can still have up to the cap buffered per open request; revoke its lease if it abuses that. Unauthenticated refusals, including kill-switch refusals and the provider-key and query-carrier audits of a request no lease vouches for, write at most 10 audit rows per client address a minute plus one summary row. Upstream responses are not capped. `amc config print` lists the new variable.

The signed ops policy's evidence limits still apply to what the gateway records: by default 64 KiB per evidence event (`retention.maxPayloadBytesPerEvent`) and 10 MiB per blob (`retention.maxBlobBytes`). A model call whose recorded request or response is larger than those limits fails with 502 until you raise them in `.amc/ops-policy.yaml` and sign it again.
