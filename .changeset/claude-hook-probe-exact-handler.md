Security: `amc connect hooks status` and `amc connect hooks health` no longer run a Claude Code control handler that AMC did not write. Before, the control probe ran any handler whose command and first argument were existing absolute paths, as long as the workspace's signed installation manifest matched the settings file; a cloned or shared workspace can carry its own `.amc` keys and a self-consistent manifest, so `status` could run any program, for example `/usr/bin/env /bin/sh -c …`, with the user's rights. The probe now runs only the exact handler the running AMC would install for the signed manifest: its own Node executable, its own CLI script, the `connect hooks forward` arguments built from the manifest's agent, Bridge URL and token file, the `*` matcher and the 10 s timeout. Any other handler is reported `Control: NOT VERIFIED (stale)` with the re-install command, is never run, and `status` exits 1; AMC no longer checks whether the paths such a handler names exist. `Control: NOT VERIFIED (command_missing)` now means only that AMC's own handler names a Node or `dist/cli.js` that no longer exists. A genuine install is still probed and still prints `Control: verified` when it denies. What `install` writes is unchanged; after upgrading AMC or switching Node, re-install as before.
