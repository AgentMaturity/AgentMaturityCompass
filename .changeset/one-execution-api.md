The CLI, the TypeScript SDK, the Python wrapper and Studio share one execution API: the same eight verbs (start, stream, approve, cancel, resume, fork, dispose, verify) and the same four phases (admission, model completion, side-effect completion, evidence verification) on every result (P2-13, docs/sdk/EXECUTION_API.md).

- **Phases on every result.** `amc agent-loop run --json` and `amc agent-loop verify --json` gain an `execution` field; every ACP prompt result of the native runtime carries it under `_meta["dev.agentmaturity.amc"].execution`; the TypeScript SDK's `AMCNativeRunResult.execution` and `AMCNativeReceipt.execution`, the Python `RunResult.execution` and `VerificationReceipt.execution`, and each Studio task view's `execution` report it. Each phase has one source and none implies another: evidence verification reads `pending` until `verifyAgentRun` runs. Side-effect completion comes from the verified receipt chains of the session's journaled actions (P1-03): it reads `unknown` while any is `outcome_unknown` and `refused` when one was denied. `recheckFailures` lists the typed authorization failures of denied actions (for example `purpose_violation`, P2-02), identically on every surface.
- **New verbs where they were missing.** `_amc/session/fork` on `amc acp` and `POST /api/v1/native-tasks/{taskId}/fork` in Studio fork a session the way `--fork-from` does: the child's signed open row names the parent's verified final row, with no inherited model context, its own run lease and its own limits; a parent that does not verify is refused with its reason (`MISSING`, `TAMPERED`, ...), as error data `reason` or Studio code `NATIVE_FORK_<reason>`. The TypeScript SDK gains `forkSession`, `approve`, `pendingApprovals` and `dispose` (sdk-api), and the Python wrapper `fork_session`, `approve`, `pending_approvals`, `dispose` and `verify_session`; approvals go through `amc approvals approve`, the signed approval engine every surface uses. `dispose` releases each idle writer, then stops the runtime.
- **Behaviour that changes.** The TypeScript SDK and the Python wrapper refuse a runtime that does not advertise execution API v1 (`executionApi: 1`), before any session, so an older `amc` CLI is refused. `amc agent-loop run` now records the OS account as the initiator of the approvals its turn raises, so that account can no longer approve its own request where the action class requires distinct users, as `amc acp` and Studio already enforced (P1-78). Studio answers an initiator's own approval with 403 instead of a server error.
- **Starter profiles.** `amc init --coding --web-allow-host <host>` (repeatable) also grants `web_fetch` and `web_search` exactly those origins in the signed tool policy; `--regulated` keeps them off, and `ask_user`, `todo` and `plan` stay off in both profiles.
- **Python CI lane.** A `python-sdk` CI job installs the wheel into a fresh virtual environment and runs `sdk/python/tests` against the CLI built from the same commit on Python 3.10 and 3.12.
