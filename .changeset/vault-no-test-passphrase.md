AMC no longer picks a vault passphrase from a test signal. Before, `VITEST=1` or `VITEST=true` sealed a new workspace vault with `amc-test-passphrase`, and `NODE_ENV=test`, `VITEST=1` or `VITEST=true` sealed a new host vault with `amc-host-vault-test-passphrase`. Both passphrases are written in AMC's source, so anyone holding such a vault file could open it, private signing keys included. Now only `AMC_VAULT_PASSPHRASE` (and `AMC_HOST_VAULT_PASSPHRASE` for the host vault) supplies a passphrase. Without one, creating a workspace vault fails with "AMC_VAULT_PASSPHRASE environment variable is required: AMC has no default vault passphrase, and NODE_ENV or test-runner variables never supply one", and creating a host vault fails with "Host vault passphrase is required". With `NODE_ENV=test` and no passphrase, opening a workspace that already has a vault no longer fails with the passphrase error: the vault stays locked, as it does without `NODE_ENV=test`, and a command that needs a key says the vault is locked. `amc org run` no longer reports its artifact signed because `NODE_ENV=test` or `VITEST` is set (see the org-run changeset). A vault or host vault created with one of these variables set and no passphrase used a public passphrase: re-create it and re-sign what it signed.
