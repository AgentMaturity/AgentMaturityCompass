A4 (P2-41): a write on a held project is refused with `409 A4_ON_HOLD` (design §17), a second hold included, instead of `409 A4_NOT_READY` naming `ON_HOLD`; the `detail` (`reasonCodes`, `items`) is unchanged, role refusals and `FREEZE_ACTIVE` still come first, and comments, members, `RESUME` and rollback are still allowed while held. Every A4 route that loads a project whose records fail verification, readiness included, answers `409 A4_INTEGRITY_FAILED` with the fixed `detail: { status: "BLOCKED", reasonCodes: ["A4_INTEGRITY_FAILED"] }` instead of the store's problem list (which named failed rows and member principal keys before membership was checked), and a stored row that does not parse with the fixed message `A stored A4 record does not parse.` (MCP tools too). Only `GET …/verify` reports the problems, to a workspace OWNER or AUDITOR, the admin token, or a member proven by member rows that verify; when the member rows fail, any other reader gets that 409 instead of `403 A4_NOT_A_MEMBER`. Clients that matched `A4_NOT_READY` with reason code `ON_HOLD` should match `A4_ON_HOLD`.
