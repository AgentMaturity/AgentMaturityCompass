Add an optional per-rule `requireRunIntegrityAtLeast` (0..1) to `.amc/action-policy.yaml`: the integrity index the agent's latest sealed, ledger-anchored diagnostic run must reach before that action class may run in EXECUTE mode. A rule that does not set it gets 0.6, the HIGH TRUST line every policy had before, so existing signed policies behave as before and their bytes do not change.

The governor now separates a hard gate from that rule condition. The hard gate, which no rule can waive, covers a policy, budgets or tools signature failure, a refused run history (planted, tampered, foreign, unanchored or rolled back), and a latest trusted run that failed ledger verification, is not VALID, or violated or did not record the trust boundary. A missing or low-integrity run is now the rule's `run-integrity` condition, which every EXECUTE decision lists with its threshold and the run's integrity.

A threshold below 0.6 is an owner waiver. It still needs a sealed, anchored run: with no run every threshold fails. It never covers findings against the agent (contradictions, unsupported claims, inflation attempts, invalid receipts, or a run that does not record those counts). Every decision made under a waiver carries a `RUN INTEGRITY WAIVED:` reason; `amc doctor` warns on every waived rule and on a signed policy that does not parse; `amc policy controls` shows each class's threshold and names a waiver; operating-profile activation reports a lowered threshold as a widening. A waiver has no expiry, and `amc fix-signatures` records its activation as a sealed `CONFIG_RESIGNED` audit row.

The default policy, `amc init`, the SDK quickstart and the packed-install check are unchanged: a fresh install still runs EXECUTE calls as SIMULATE. A fresh agent's decision changes shape: the `action-policy-signature` condition passes, `run-integrity` fails, the reasons list every failing rule condition, and `amc policy simulate` and `amc policy test` report `failClosed: false` for action controls. The evidence-logic API's `mandatoryGates` gains `run-integrity` (10 entries). `docs/GOVERNOR.md`, the quickstart and the TypeScript SDK guide describe the waiver, its limits, the self-reported import path and why removing the policy is not a grant. The installed crash-recovery runner signs such a waiver for READ_ONLY and WRITE_LOW, asserts that each approval it records is for an EXECUTE request, and states in its receipt that it proves the governed EXECUTE path, not maturity. No CLI command or Studio route is added.
