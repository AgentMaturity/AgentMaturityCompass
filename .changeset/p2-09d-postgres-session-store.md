An optional Postgres session store (P2-09d). `AMC_SESSION_STORE=postgres`, or `amc evidence-stores migrate --to postgres` for an existing SQLite workspace, keeps session events in Postgres so an HA Postgres can keep them through the loss of a node. The store stays synchronous: the `pg` driver (an optional peer, not shipped; refused with `POSTGRES_DRIVER_MISSING` when absent) runs in a worker thread. The connection string comes only from the chmod-600 file named by `AMC_POSTGRES_URL_FILE`, must set `sslmode=verify-full`, and the server must authenticate with SCRAM over TLS. Each append locks the chain head, `UNIQUE (chain_id, prev_event_hash)` makes a fork unwritable, and a retry with the same event id returns the committed row. During a primary loss every call fails closed with `POSTGRES_UNAVAILABLE` and writes nothing; appends resume after promotion. The migration authenticates the SQLite history, copies it in one transaction, compares every row, runs the backend determinism check and writes a signed receipt before pinning the workspace. `amc verify` reports a Postgres store it cannot read as an error, and checks the chain against the database head and a head AMC signs into the workspace after each append, so a truncated tail is caught. Event ids are keyed per chain; an id another workspace's chain holds is refused. Run verification, budgets, native session reads and audit packets read the Postgres rows. Blobs and keys stay on the workspace volume. Tested against a SQLite-backed fake driver only; the real-Postgres failover drill (`docs/runbooks/POSTGRES_FAILOVER.md`) is pending.

freeze-exception: P2-09d — `amc evidence-stores migrate --to postgres` is the SQLite-to-Postgres migration the P2-09 spec asks for.
