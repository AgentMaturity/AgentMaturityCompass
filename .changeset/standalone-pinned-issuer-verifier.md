Adds `amc-verify`, a standalone verifier in `packages/verifier` (working name `@amc/verifier`, private and not published; the published name is still to be chosen). It has no dependencies, imports only Node built-ins, runs offline on Node 20 or later, and checks scoped attestations, state receipts, external evidence profiles, signed trust lists, key and root rotation statements and revocation lists against trust lists and root keys its user pins. It never admits a key, authority or anchor named only inside the record, has no flag that admits an unpinned issuer, takes the m-of-n root threshold from `--root-threshold` (a trust list can raise it, never lower it), and judges distrust, key validity and revocation as of `--as-of`: a revoked or expired key is refused even for a record that claims an earlier signing time. It reports integrity, issuer admission, scope, freshness, completeness and satisfaction separately, with normative reason codes, as of `--as-of` (time basis `claimed`), and exits 0 when all six pass, 1 when one fails, 3 when none fails but one is not evaluated, and 64 on a usage error. `spec/fixtures/v1/` adds 46 normative cases (regenerated byte-identically by `spec/fixtures/v1/generate.mjs`) and `packages/verifier/conformance/run.mjs` checks any implementation against them; see docs/STANDALONE_VERIFIER.md.

The verifier report contract gains an optional `reasonCodes` object and accepts any non-empty `verifier.name`. The contract-only scoped attestation, which no AMC command emits yet, is finalized before any is issued: it now requires `tenantId`, `workspaceId`, `subjectId` and `sequence`, its signature envelope refuses unknown members, and its signed bytes are fixed as sha256 of `AMC_SCOPED_ATTESTATION_V1`, a 0x00 byte and the canonical attestation without `signature`. `npm run build` also builds the verifier package, and `npm run typecheck` checks it.
