"agent-maturity-compass": patch

Security: `amc federate import` no longer lets an admitted federation peer steer where a package is written. Before, the peer-signed manifest's `sourceOrgId`, `manifestId` and `files[].path` were joined into inbox and file paths unchecked, so an admitted peer could write attacker-chosen bytes outside its inbox (for example over the workspace's signed configs) with `..` segments in `sourceOrgId` or `manifestId`, and could file a package under another org's directory by claiming that org's `sourceOrgId`. The manifest schema now requires `sourceOrgId` and `manifestId` to be one safe path segment (`[A-Za-z0-9][A-Za-z0-9._-]{0,127}`) and each `files[].path` to be a relative POSIX path with no leading slash, drive letter, backslash, empty, `.` or `..` segment; `federate import` and `federate verify-bundle` also refuse any resolved path that leaves its root, and an import resolves every path before writing the first file. The inbox directory is now named after the identity that was admitted (the matching peer's `peerId`, or `key-<first 16 hex of the key id>` when only the operator's trust list admitted the key), not after the manifest's claimed `sourceOrgId`, which is still reported as claimed. Packages from `amc federate export` are unaffected; a hand-edited `federation.yaml` whose `orgId` is not a safe id can no longer export.

Security: benchmark imports had the same flaw one level down. The `benchId` inside a signed `.amcbench` was joined into the import directory unchecked, so a benchmark signed by an admitted federation peer, or by any key the operator pinned, could write `bench.json`, `bench.sig` and `public-keys/auditor.pub` outside `.amc/benchmarks/imported`. The benchmark schema now requires `benchId` to be a safe id (the `bench_<32 hex>` ids that `amc benchmark export` produces are unaffected; a benchmark with any other unsafe id no longer ingests or lists), and `amc benchmark ingest`, the API and Studio import routes and `amc federate import` refuse a target directory outside `.amc/benchmarks/imported`. Registry bench imports (`amc bench import`) likewise refuse a `benchId` or version that would leave `.amc/bench/imports/benches`.

Security: `amc federate import` extracts a package twice, once to verify it and once to copy from, so a bundle replaced on disk between the two could be imported unverified. It now refuses, before it writes anything, unless every file it copies, and `manifest.json`, `manifest.sig` and `public-keys/publisher.pub`, still hashes to what verification admitted; each file is hashed again as it is written.
