Behind trusted reverse proxies, Studio now takes the client address from the `X-Forwarded-For` entry the trusted hops appended, `chain[length - AMC_TRUSTED_PROXY_HOPS]` (LIVE-RUNTIME-18). Before, it took the entry one hop further left, so behind a proxy that appends to the header (ALB, HAProxy `forwardfor`) a client could prepend an address of its choice and pass the allow list and the per-address limiters.

Forwarded headers now count only from the reverse proxies named in the new `AMC_TRUSTED_PROXY_CIDRS` (SR-1). Before, Studio and the host router believed `X-Forwarded-For` from any peer in `AMC_ALLOWED_CIDRS`, so any allowed LAN client could name its own address, rotate it, and slip past the per-address limiters and login throttle. Now `X-Forwarded-For`, `X-Forwarded-Proto` (the `Secure` cookie flag and HSTS) and an inbound `X-Request-Id` count only on a request that a named proxy forwarded; an allowed client is never a proxy. An empty `AMC_TRUSTED_PROXY_CIDRS` trusts no proxy, so Studio refuses to start when `AMC_TRUSTED_PROXY_HOPS` is above 0 and no proxy is named: otherwise every client behind the proxy would share its address and the allow list would judge the proxy instead of its clients. Upgrading a deployment that sets `AMC_TRUSTED_PROXY_HOPS`: set `AMC_TRUSTED_PROXY_CIDRS` to the proxy's addresses. The shipped configs never trust a whole private range, because any container or pod inside it could name its own client address (SR-10). The Compose TLS stack puts Caddy at a fixed address on its own `amc_edge` network and trusts only that address. The Helm chart now defaults to `AMC_TRUSTED_PROXY_HOPS: "0"` with no proxy named, and refuses to render with `ingress.enabled` or hops above 0 until `env.AMC_TRUSTED_PROXY_CIDRS` names the ingress controller pods; the ingress example leaves it empty for you to fill in. The raw Kubernetes manifests leave the list empty, so Studio refuses to start until it is set. The chart and Studio refuse documentation ranges (RFC 5737/3849: 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24, 2001:db8::/32), which pass CIDR validation but name no real proxy. At start, Studio warns about a trusted IPv4 range of /12 or wider, a trusted range (not a single address) that overlaps `AMC_ALLOWED_CIDRS`, or a proxy list that misses every private range `AMC_ALLOWED_CIDRS` admits. Upgrading a Helm release with an Ingress: set `env.AMC_TRUSTED_PROXY_HOPS` and `env.AMC_TRUSTED_PROXY_CIDRS`. A TLS socket always counts as HTTPS.
