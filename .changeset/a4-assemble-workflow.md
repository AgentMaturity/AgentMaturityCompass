A4 Assemble (behind `AMC_A4_PREVIEW=1`) adds the `workflow` executor's plan. Assemble asks one more, optional question, `workflow`: a declared workflow as JSON (`agent`, `parallel` and `pipeline` nodes, at most 64, unique ids, valid scopes), checked with `parseWorkflowPlan` before anything could spawn. It depends on `autonomy` and needs `act_with_approval`; a plan that does not parse, or one declared with `advise`, is `ANSWER_INVALID:workflow`, and `ask_complete` names the reason. Understand records whether the active compiled plan shows the `workflow` tool. Propose adds a `workflow` task (the plan, its delegation count, and every reason it cannot run) and lists it under unsupported items. A declared workflow runs only through the agent's `workflow` tool, each helper through `spawnSubagent`, and A4 never starts helper agents itself. Studio's native build sessions compose no delegation, so the task reads `NATIVE_TASKS_NO_DELEGATION` and stays listed until an owner acknowledges it out of scope. Once a compiled plan is active, its default `visibleTools` hides the tool. The task then also reads `C6_COMPILED_POLICY_DENIES` and carries the runtime's denial, the plan revision and the plan's tool-pipeline controls. An unreadable plan reads `COMPILED_POLICY_UNREADABLE`. Explain describes the executor when a workflow is declared, and Studio's Plan card shows a Workflow executor section. Re-opening an effect gate now first settles that effect's lost attempts on the gate as `process_lost`, as retry does, so a crashed executor no longer holds the re-open path at `EFFECT_RUNNING`.
