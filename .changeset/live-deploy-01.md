Compose stacks start, keep their signed controls and stop gracefully (LIVE-DEPLOY-01). Every Studio and API service in `deploy/compose/docker-compose.yml`, `docker-compose.tls.yml`, `docker-compose.studio-api.yml` and `docker/docker-compose.yml` drops the tmpfs at `/home/amc`: Docker created the nested state-volume mount point as `root:root 0755` inside it, and Studio refused that AMC home and exited after bootstrap. The image owns the 0700 home, so the read-only root keeps working. Studio services mount a third named volume, `amc_control_checkpoints`, at `/workspace` with `AMC_CONTROL_CHECKPOINT_DIR=/workspace/control-checkpoints`, so firewall, guardrail, legal-hold and compiled-control checkpoints persist outside the workspace (the A4 Compose overlay already uses the same path). Studio and API services get `stop_grace_period: 40s`, and the HTTP stack's `studio` gets `restart: unless-stopped`. The HTTP stacks publish their ports on `127.0.0.1` unless `AMC_PUBLISH_ADDRESS` (new in `.env.example`) says otherwise, and the `AMC_*_PORT` keys in `.env` now set the host ports. `deploy/compose/.env` is git-ignored. The `docker run` example in `docker/README.md` uses the same volumes and `--stop-timeout 40`.
