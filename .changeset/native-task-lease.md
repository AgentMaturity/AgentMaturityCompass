Studio native tasks can now make tool calls under an active compiled plan that includes `L0-IDN-01`. When a task with workspace tools starts or resumes while a plan is active, Studio mints a signed lease for that runtime alone: the task's agent, the task id as the work order, `toolhub:execute` narrowed to the action classes of the task's pinned signed tools, and at most the runtime's one-hour lifetime. Studio records only the lease id on the signed task descriptor and passes the token to the `amc acp` child through `AMC_NATIVE_TASK_LEASE`. The child unsets that variable before anything runs and scrubs the token from tool output. Every call binds the lease to its authorization record through the pipeline's existing lease verifier, so the `identity-binding` guard admits the call with the lease as its principal. Studio revokes the lease when the runtime stops, including a runtime process that exits on its own, before it mints the next one on resume, and at archive. Archiving refuses with `NATIVE_LEASE_UNREVOKED` when the signed lease revocation store does not verify. When the lease cannot be minted, because the lease signing key or the signed lease revocation store is unavailable, Studio does not start the runtime. The session's `EFFECTIVE_POLICY` receipt gains `leaseId`, which names the lease only when the verifier accepted it when the receipt was written, and is `null` otherwise.

Nothing changes for sessions without a plan: no lease is minted or bound. A native session that carries no verified lease is still denied every call under a plan with `L0-IDN-01`. This covers a task started before this release or while no plan was active, a CLI agent session and a delegated child. Native task `LIMITS` are unchanged. The receipt records which lease the calls ran under. It does not show that the plan's controls are satisfied.
