Studio native tasks can now make tool calls under an active compiled plan that includes `L0-IDN-01`. When a task with workspace tools starts or resumes while the active plan's `identity-binding` requires an agent lease, Studio mints a signed lease for that runtime alone: the task's agent, the task id as the work order, `toolhub:execute` narrowed to the action classes of the task's pinned signed tools, and at most the runtime's one-hour lifetime. Studio passes the token to the `amc acp` child through `AMC_NATIVE_TASK_LEASE`, and records only the lease id on the signed task descriptor once the runtime holds the session's writer claim. The child unsets that variable before anything runs and scrubs the token from tool output. Every call binds the lease to its authorization record through the pipeline's existing lease verifier, so the `identity-binding` guard admits the call: the record's `delegation.leaseId` names the verified lease, and its principal is the approvers for an approved call (every Studio workspace-tool call is approval-gated) or `lease:<id>` when no approval is named. Studio revokes the lease when the runtime stops, including a runtime process that exits on its own, and at archive. A resumed runtime revokes the previous runtime's lease only after it holds the writer claim, so a refused resume in a second Studio process no longer affects a live runtime in another. Archiving refuses with `NATIVE_LEASE_UNREVOKED` when the lease cannot be revoked, because the signed lease revocation store does not verify or cannot be signed. When the active plan does not verify, or the lease cannot be minted because the lease signing key is unavailable, Studio does not start the runtime; when the previous runtime's lease cannot be revoked, the resumed runtime is stopped. Start and resume then return a failed task view whose error states the reason, and a lease Studio could not revoke is named with its cause rather than reported as a store failure. The session's `EFFECTIVE_POLICY` receipt gains `leaseId`, which names the lease only when the verifier accepted it when the receipt was written, and is `null` otherwise.

The native task lifetime clock now starts when Studio begins launching the runtime, and the sweeper stops a runtime up to 10 seconds before the one-hour limit, so a runtime never outlives its lease. `revokeLease` (used by `amc lease revoke`, Studio and the lease API) now verifies and parses the signed revocation list from one read and holds a lock beside the store (`.amc/studio/leases/.revocations.lock`) for its whole update, so two concurrent revocations can no longer drop each other's row; `revokedLeaseIdSet` likewise verifies and parses the same bytes.

Nothing changes for sessions under no plan, or under a plan whose `identity-binding` does not require a lease: no lease is minted or bound. A native session that carries no verified lease is still denied every call under a plan with `L0-IDN-01`. This covers a task started before this release or under a plan that did not require a lease, a CLI agent session and a delegated child. Native task `LIMITS` values are unchanged. The receipt records which lease the calls ran under. It does not show that the plan's controls are satisfied.
