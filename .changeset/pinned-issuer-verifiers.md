Verification refuses issuer keys that are not pinned by --pubkey or a signed trust list, and fails unanchored ledgers; --allow-unpinned and --allow-unanchored give integrity-only results with exit code 2.

This applies to `amc bundle verify`, `cert verify`, `cert verify-revocation`, `passport verify`, `assurance cert-verify` and `release verify`, and to `amc verify`, `verify all`, `evidence verify`, `session verify` and `agent-loop verify` for the ledger. A key shipped inside a bundle, certificate, passport, assurance certificate, trust certificate or release no longer vouches for it; a refusal prints the key id to pin. Bundles and certificates are anchored only when their monitor key is pinned (`--expect-monitor`, `AMC_EXPECTED_MONITOR_FINGERPRINT` or a trust list), a revocation counts only when its issuer is pinned for `revocation-list` and is the certificate's own issuer, and passport and assurance-certificate inclusion proofs must resolve to their signed Merkle root. The commands gain `--trust-list`, `--trust-root`, `--json` and, where missing, `--pubkey` and `--expect-monitor`; no command path is added. Exit codes: 0 trusted, 1 failed, 2 integrity verified but untrusted because an allow flag was used (stderr starts with `UNTRUSTED:`). The verifier functions take a required `TrustContext` and return a `VerifierReportV1` as `report`, with `ok` equal to `report.trusted`; API routes use the server's trust list and refuse request-supplied pins and allow flags; `POST /api/v1/assurance/cert/verify` now verifies the certificate instead of only parsing it. A monitor key that is distrusted or revoked fails even with `--allow-unanchored`, and a key revoked for a reason other than key compromise, or past its `validTo`, still admits signatures that claim an earlier time (`timeBasis: "claimed"`). The workflow `amc ci init` writes pins the auditor key and monitor fingerprint from the repository variables `AMC_AUDITOR_PUBKEY` and `AMC_MONITOR_FINGERPRINT`. The remaining verifiers (binder, audit packet, bench, backup, plugins, prompt packs, federation, console) are wired by a separate change; see its changeset. See `docs/TRUST_LIST.md` and `docs/security/verifier-inventory.md`.
