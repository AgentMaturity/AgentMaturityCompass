`amc agent-loop run` for scripts and CI (SH-UI-01): the prompt can come from stdin (`-`, or a piped stdin with no positional prompt; 10 MiB bound, refused over it); `--output-format text|json|stream-json` (`--json` stays the alias of `json`); `stream-json` writes one JSON event per line on stdout (`system/init`, the loop's live notifications, provisional `text_delta`, each newly committed row as an authenticated `update` in ACP's shape with `seq`/`eventId`/`eventHash`, and a terminal `result` or `error`), through the same row authentication ACP applies. On `--session`/`--fork-from` the stream carries only this run's rows (the existing rows are authenticated, not re-emitted). The exit code now follows the execution contract: 0 complete with settled side effects, 1 failed or refused (or no readable ending), 3 cancelled or interrupted, 4 `max_steps`/`max_tokens`, 5 `blocked`, 6 completed with unsettled session side effects; goal rounds exit by their stop reason (`done` 0 only when the receipts of every session the rounds ran in settled, else 6; `failed`/`refused`/`check-failed`/`check-unavailable` 1, `cancelled`/`human` 3, `max-rounds` 4, `blocked` 5; an integrity failure in any of those sessions 1), and the `json` summary carries those receipts as `goalReceiptStates` (`docs/NATIVE_HEADLESS.md`). `agent-loop chat` reads 3 to 6 from its turn child as "completion not established" (6 named from the code) and sends the prompt over stdin. No new command: no freeze exception needed.
