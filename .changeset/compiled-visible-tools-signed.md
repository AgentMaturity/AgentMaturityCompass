`amc catalog compile` now takes a plan's visible tools from the workspace's signed `.amc/tools.yaml`, so `delegate` and other tools the signed allowlist grants beyond the built-in default list can run under an activated plan (P1-10F). Before this release every activated plan showed only the built-in default list, which has no `delegate` or `workflow`, so every `delegate` call was refused (`"delegate" is not a visible tool`) whatever tools.yaml allowed.

- **Visible tools.** `toolPipeline.visibleTools` is the set of tools the signed tools.yaml lists, narrowed by any `toolPipeline.visibleTools` parameter of the plan's controls. The compile reads tools.yaml, its signature and its schema from one read, and uses it only when all three verify. A missing, unsigned, edited or invalid tools.yaml compiles with the built-in default list, and `delegate` stays refused. The output says which list was used: a `visible tools:` line, or `visibleToolsSource` with `--json`.
- **The digest is bound.** A plan compiled from tools.yaml records its SHA-256 as `runtimePolicy.toolPipeline.toolsConfigSha256`, inside the plan digest and the policy digest that the plan review approves. While that plan is active, every tool call is refused (`compiled policy denied this call (toolPipeline.toolsConfigSha256)`) once tools.yaml's bytes change, until you recompile and reactivate the plan. A plan that shows more tools than the active plan is a weakening, so activating it needs `--allow-weakening` after review. The digest on its own is not compared.
- **Plan digests change** for every workspace whose tools.yaml verifies, which `amc init` signs by default, because the plan now records the digest. If tools.yaml differs from the built-in default list, the plan's visible tools and its proposed tools config change as well. `compilePlan` without `signedTools` (A4 Adapt, the test harnesses) and a compile with a tools.yaml that does not verify give byte-identical plans to before.
- **Unchanged.** A plan activated before this release records no digest. Its sessions keep the built-in default list and do not read tools.yaml for this check. A delegated child's own tool calls are still refused under a plan with `L0-IDN-01`, because no lease reaches the child. The visible list governs which tools the plan lets a session call. It does not show that the plan's controls are satisfied.
