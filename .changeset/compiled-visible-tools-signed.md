`amc catalog compile` now takes a plan's visible tools from the workspace's signed `.amc/tools.yaml`, so `delegate` and other tools the signed allowlist grants beyond the built-in default list can run under an activated plan (P1-10F). Before this release every activated plan showed only the built-in default list, which has no `delegate` or `workflow`, so every `delegate` call was refused (`"delegate" is not a visible tool`) whatever tools.yaml allowed.

- **Visible tools.** `toolPipeline.visibleTools` is the set of tools the signed tools.yaml lists, narrowed by any `toolPipeline.visibleTools` parameter of the plan's controls. The compile reads tools.yaml, its signature and its schema from one read, and uses it only when all three verify. With no tools.yaml it compiles with the built-in default list, and `delegate` stays refused. A tools.yaml that is unsigned, edited after signing, signed by another key or invalid now refuses the compile with `TOOLS_CONFIG_UNVERIFIED` (exit 1), naming the reason: re-sign it with `amc tools sign`, or remove it to compile with the default list. A4 Adapt's Understand compiles from the same verified tools.yaml and reports the same code. The output says which list was used: a `visible tools:` line, or `visibleToolsSource` with `--json`.
- **The digest is bound.** A plan compiled from tools.yaml records its SHA-256 as `runtimePolicy.toolPipeline.toolsConfigSha256`, inside the plan digest and the policy digest that the plan review approves. While that plan is active, every tool call is refused (`compiled policy denied this call (toolPipeline.toolsConfigSha256)`) once tools.yaml's bytes change, until you recompile and reactivate the plan. A plan that shows more tools than the active plan is a weakening, so activating it needs `--allow-weakening` after review, and so is a plan that drops the digest the active plan binds. A new digest that only narrows the tools is not a weakening. A native session reads and verifies tools.yaml once per call, and the plan's digest check, egress, the allowlist and the native tool identity all decide from those bytes.
- **Plan digests change** for every workspace whose tools.yaml verifies, which `amc init` signs by default, because the plan now records the digest. If tools.yaml differs from the built-in default list, the plan's visible tools and its proposed tools config change as well. `compilePlan` without `signedTools` (the test harnesses) and a compile with no tools.yaml give byte-identical plans to before.
- **Unchanged.** A plan activated before this release records no digest. Its sessions keep the built-in default list and do not read tools.yaml for this check. A delegated child composes its tools with the run's lease (`run-principal-lease`) under the same active plan, so it can call only the visible tools its delegation scope allows. The visible list governs which tools the plan lets a session call. It does not show that the plan's controls are satisfied.
