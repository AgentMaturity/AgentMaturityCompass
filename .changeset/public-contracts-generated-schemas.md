Breaking: published JSON Schemas are now generated from the schemas AMC enforces; unknown fields are refused where AMC refuses them. `amc standard generate` no longer writes the hand-written permissive schemas (`additionalProperties: true`, a bare required list and a caveat that passing them did not mean AMC would accept the artifact). Each schema now carries every field type, enum, length and range AMC checks, a `$id` under `https://agentmaturity.co/spec/schemas/v1/`, and is pretty-printed with sorted keys, so schema digests and the signed bundle manifest change. The `amc standard` artifacts still accept unknown keys, because AMC ignores them; `registry.passport` is now checked by a schema that refuses a `registry` that is not an object. New public contracts for the evidence event, receipt states, legacy receipt, authorization record, control result, claim envelope, scoped attestation, trust list, verifier report and signature envelope are committed under `spec/schemas/v1/` with `spec/ACCEPTANCE_RULES.md`, the checks a verifier runs beyond shape, and are served on the docs site at their `$id`. `amc evidence export`, the evidence export API and audit packets check every row against the evidence-event contract and refuse with `export refused: row <id> violates evidence-event v1: <path> <message>`; an event type outside the published list is refused. Export rows now carry `claimKind` (`synthetic_example`, `self_reported` or `observed`). `npm run check:schemas` fails when a committed schema is stale.
