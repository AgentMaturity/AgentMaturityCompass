Compliance crosswalks: eight sourced framework families, 290 clause-level controls and crosswalk links with a relation and a rationale, all labelled experimental (P1-45, landing S6 and the round-2 framework controls after an AI refutation pass and an independent review).

- `amc comply report --framework` accepts eight more families: `DORA`, `NIS2`, `HHS_HTI_1`, `NIST_AI_600_1`, `CO_AI_ACT`, `TX_TRAIGA`, `CA_AI_LAWS` and `KR_AI_BASIC_ACT`, with 48 built-in mappings that cite the official text and the date it was read. `amc compliance init` seeds them into new maps; existing signed maps are unchanged. Versioned or clause-qualified names (`GDPR Art. 9`, `PCI DSS v4.0.1`, `SOC 2 Type II`, `EU NIS2 2022/2555`) now resolve to their family. `ONC_HTI_1` is an input alias for `HHS_HTI_1`, not a framework id.
- Every family, mapping and crosswalk link is experimental: drafted and refuted by AI agents, with no named-expert sign-off (D-08 pending). Reports carry this as an additive `familyReview` field (`status`, `expertSignOff: null`, `flags`). The field appears in the report JSON, the API report response, Studio's compliance page, `amc compliance matrix` (JSON and Markdown) and the fleet report. The Markdown report prints it above its results. The flags: HHS HTI-1 is at risk because an HTI-5 final rule may delete its model-card requirements. Colorado SB26-189 was re-verified on 2026-10-18. The Korea pinpoints are unverified.
- A crosswalk link has `relation` (`equivalent`, `partial` or `conflicting`) and a non-empty `rationale`; `equivalent` needs an expert sign-off id, so every built-in link is `partial`. The `coverage` label is removed. A result for one framework never sets a result for another.
- ISO/IEC 42005 is descoped. The name resolves to no family (zero mapped controls, `unverified: source unreachable`). The three ISO 42005 categories of `ISO_42001` are listed as NOT_EVALUATED with `descoped: "not evaluated: descoped (licensed text unavailable)"`; they are never evaluated, and `coverage` and the matrix `total` leave them out.
- Coverage scores: UNKNOWN keeps earning 0, as since P0-17. A self-reported PARTIAL now counts as not evaluated, so a report holding only that scores `null` instead of 0. A category without a control id makes `coverageScore` throw instead of being scored. Scores of reports with UNKNOWN rows that were computed before 2.0 drop when recomputed; warn `amc comply report` users who compare them.
- `buildControlCrosswalkReceipt` (public export) changes for mappings that carry their own `sources`: such a row cites exactly those sources instead of every receipt source, so its row hash and the receipt hash change. The receipt fails closed with `<mappingId>:sourceCitations:unlisted` when one of them is missing from the receipt's `sourceCitations`. `mappingSourceCitations(mappings)` builds that list.
- The review corrected built-in maps that new workspaces receive. Seven S6 mappings and three HIPAA mappings had a "no denied audit" check naming only audit types AMC never emits, so it could not fail. Each now names emitted types (`TRACE_RECEIPT_INVALID`, `TRACE_EVENT_HASH_NOT_FOUND`, `SECRET_EXFILTRATION_SUCCEEDED`), or the check is removed where no emitted type fits (`nist600_data_privacy`, `hipaa_physical_safeguards`). Six more unemitted names in four GDPR mappings, `sox_itgc_change_management` and `fedramp_config_management` were dropped or replaced (`CONFIG_SIGNATURE_INVALID`, the trace types). `hti1_dsi_feedback` now says §170.315(b)(11)(ii)(C) asks for feedback on evidence-based DSIs, not on a Predictive DSI.
