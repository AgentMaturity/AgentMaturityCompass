One documented way to run AMC for live users, with Compose runbooks beside the reference runbooks (LIVE-DEPLOY-17). `docs/DEPLOYMENT.md` opens with "Running AMC for live users": the Compose TLS stack for a single host and the Helm chart 0.4.1 for a cluster, both documented and not qualified in D-03's vocabulary, the Compose HTTP stack for loopback or private networks, and Railway/Vercel for the standalone API only, with links to the reference runbooks. The new `docs/deploy/reference/COMPOSE.md` gives numbered steps for install, the monitor-key pin, pairing, backup (a signed bundle and an archive of the state and checkpoint volumes, both taken with Studio stopped so the signed-control journals and their checkpoints come from one moment; the bundle is created in a one-off container and streamed out), upgrade from the previous release and from 1.1.1 (including the one-time ownership change of the 1.1.1 HTTP stack's data volume), rollback with the restore (the state and checkpoint volumes are emptied before the archive is extracted, keeping only the kill-switch mirror, and the firewall status is checked afterwards), TLS for a public hostname, and A4 Forge's limits, and it lists what was run on 2026-11-08 and what was not. `docs/INSTALL.md` "Upgrading" starts with the backup and links the runbooks; the Compose README shows the `.env` image pin; the reference BACKUP_RESTORE runbook documents feeding the backup passphrase on stdin in Helm, and the Helm backup, restore, rollback and upgrade runbooks carry the signed-control checkpoints from the state claim with the bundle; the deployment checklist asks for Node.js 22 or 24.
