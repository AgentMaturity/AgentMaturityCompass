Protected-data detection now reads each line NFKC-normalised with zero-width characters and every other default-ignorable or format character removed, so a card number in fullwidth digits or split by such characters is detected and its line replaced; member names are folded the same way and their Cyrillic and Greek look-alike letters read as Latin (`pаssword`) and fullwidth or mathematical letters read too; an XML element's text (a CDATA section in it included), an HTML input's quoted `value` under its `name` (attribute values holding `>` included), any Basic token in an `Authorization` header, and a Basic run in free text whose decoded bytes hold a `:` are read as credentials, while ordinary XML, HTML forms and prose such as "Basic Settings" are left as they are. A line's NFKC view is always read whole, its length charged to the request's scan budget where it passes the walk's length limit, so a line is never left partly folded and a benign line is not refused for its fold. The detector set digest changes with these rules.
