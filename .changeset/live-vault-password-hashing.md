Console passwords are hashed with scrypt at N=2^15 (twice the previous work), with Node's memory limit set explicitly so the stronger setting cannot fail at runtime. A new password must have at least 12 characters and must not be the username (`amc user init|add|password`, `POST /users/add`, `amc bootstrap`, and the owner of `amc init --coding|--regulated`, which checks it before writing anything); the route answers a refused password with 400 and the message. A starter profile that fails after creating `.amc` now names the phase and the cause. Existing passwords keep working, and an account's stored hash moves to the new cost at its next successful sign-in while Studio holds the unlocked vault. `users.yaml` and its signature are now written with mode 0600. A stored hash asking scrypt for more than 64 MiB (128·N·r), for p above 4 or for a key longer than 128 bytes is refused, so one signed `users.yaml` entry cannot stall a sign-in for more than about half a second.
