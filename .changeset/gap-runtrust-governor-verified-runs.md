The governor no longer trusts any run JSON in an agent's runs directory. Before, the run that lifts "untrusted config" (and with it the native Action Policy guard's EXECUTE to SIMULATE downgrade, AXR-02) was the newest file marked `VALID`, unverified, so anyone who could write the workspace could plant one. The governor, ToolHub, the native Action Policy guard, `amc governor confidence-check`, transformation planning and tracking, the target what-if and the correction baseline now use only a run whose `runSealSig` verifies under the workspace run-hash keys, which names this agent, and which the ledger `runs` table anchors with the same hash, seal and status. A newer unverifiable or tampered run file blocks instead of rolling back to an older sealed one, and the decision says why (`UNTRUSTED RUN: …`). The display commands (`operator-dashboard`, `why-capped`, `action-queue`, `confidence-heatmap`, `unknowns`, `meta-confidence` and rollup claim lines) still show an unsealed run, which is the only kind a `--no-sign` workspace has, but label it `UNVERIFIED` and never pass it to a gate. `amc governor confidence-check` also no longer looks for a run file named after the agent.
