Breaking: diagnostic levels are now cumulative and earned only from runtime evidence that a registered emitter writes (methodology `2026.10.08-r226`, P1-07). A question's level is the highest n for which the gates for every level 1 to n pass; before, `amc run` kept the highest passing gate, so a question could reach L3 without its L2 gate. Every L3, L4 and L5 gate used to require audit types that only the dogfood seeder wrote. Now L1 is self-declared (two rows tagged to the question that a registered emitter admits); L2 is configuration evidence, evaluated for AMC-5.29, AMC-SCI-2, AMC-OPDISC-6 and AMC-2.15 from observed tool-call and scoped-delegation rows; L3 has no admissible emitter yet and is reported as not evaluated; L4 and L5 are not evaluated. No question can score above L2, and scores drop wherever seeded, untagged or unregistered evidence counted. A question can rise from L0 to L1 where it has two admitted rows but no `stdout` row. Reports explain rejected rows that no registered emitter wrote.

Breaking: `STRICT_EVIDENCE_BINDING=false` (or `0`, `off`, `no`) no longer makes untagged evidence count. Setting the variable prints `STRICT_EVIDENCE_BINDING is no longer supported: untagged evidence never counts toward a level` once per run.

The public methodology manifest (`amc methodology --json`) moves to `2026.10.08-r226` with a changelog entry and migration text; r225 reports and badges still verify as historical. Its published formulas now match the code (no confidence multiplier), each published gate carries `notEvaluated` where it applies, and level bands, layer and overall arithmetic and trust-label thresholds are unchanged. `docs/SCORING_METHODOLOGY.md` gains "How a Level Is Earned" with the emitter registry, evidence maps and reachability table, and `npm run check:gates` checks in CI that every evaluated gate requirement has a registered, non-synthetic emitter.

Security: above L1, a row now counts toward a question only through that question's evidence map; the row's own `questionIds` or `questionId` tag is ignored, so a writer cannot pick which questions its rows lift. A row is admitted for an emitter only when its P0-18 provenance (producer and effective trust tier) matches the emitter's declared producer and claim kind, not on its event type, audit type or metric key alone, and unscoped delegations bind to nothing. Levels are computed from each gate's declared level, never its array position: duplicate gate levels are refused and a missing level stops the climb.
