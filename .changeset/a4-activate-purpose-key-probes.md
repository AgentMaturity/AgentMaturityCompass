A4 Activate's up-front key checks name the P1-08 purpose keys their later signers use. The release and production-lease effects check the `lease` key and the `revocation-list` key (which signs every lease revocation), and a `DENY` of the deployment approval checks the `revocation-list` key, instead of the auditor role's `artifact-seal` key. A rollback checks both `artifact-seal` (its grant, freeze, Enforce restore and receipt) and `revocation-list` (its lease revocations). A revoked key now refuses these before their first side effect, as a locked vault already did: before, a revoked `revocation-list` key let the production lease be minted and let a `DENY` be recorded with its staging lease still live (409 `LEASE_REVOKE_FAILED`). A revoked key answers 409 `A4_KEY_REVOKED`, naming the purpose and the recovery (`amc keys rotate --purpose <purpose>`), in all four places, and a locked vault 423 `A4_VAULT_LOCKED`; any other failure to read the key (an unreadable or unverifiable key revocation list, an incomplete key set) is 409 `SIGNING_FAILED` with its reason. P1-08's revoked-key refusal is now a typed `KeyRevokedError` (code `KEY_REVOKED`, with the same message), so callers tell it from a locked vault without matching text.
