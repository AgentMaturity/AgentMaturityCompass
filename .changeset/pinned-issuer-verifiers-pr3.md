`amc audit binder verify`, `bench verify`, `benchmark verify`, `backup verify`, `plugin verify`, `plugin registry verify`, `prompt pack verify` and `federate verify-bundle` now refuse issuer keys that are not pinned by --pubkey or a signed trust list; --allow-unpinned gives an integrity-only result with exit code 2.

A key shipped inside a binder, bench, benchmark, backup, plugin package, plugin registry, prompt pack or federation package no longer vouches for it, and a refusal prints the key id to pin. The commands gain `--trust-list`, `--trust-root`, `--allow-unpinned`, `--allow-unanchored`, `--json` and, where missing, `--pubkey` (`benchmark verify`, `plugin registry verify`, `federate verify-bundle`); `backup restore` takes the same pins. No command path is added. `prompt pack verify --pubkey` used to be accepted and ignored; it now pins the signer. Audit binder and bench inclusion proofs must resolve to their signed Merkle root, and `verifyBenchProofBundle` refuses a proof whose own `rootHash` differs from the signed root. Imports and installs admit only what the operator pinned: `benchmark ingest` and `plugin search` use the AMC home trust list, `federate import` admits peers added with `amc federate peer add`, and `plugin install`, the marketplace and bench registry imports need the registry fingerprint pinned in the workspace's signed registries config and admit only the publisher or signer the pinned index names. The verifier functions take a required `TrustContext` and return a `VerifierReportV1` as `report`, with `ok` equal to `report.trusted`; their API routes use the server's trust list and refuse request-supplied pins, now including `pubkeyPath`. The audit packet README tells auditors to check the manifest with an auditor key pinned outside the packet, and the console labels its browser seal check "consistency only" next to the server's verdict. Seven portable verify commands outside the P0-09 table are not wired yet; `docs/security/verifier-inventory.md` lists them.
