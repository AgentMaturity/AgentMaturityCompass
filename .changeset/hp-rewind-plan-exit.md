File checkpoints and rewind (HP-06), plan mode in chat (HP-08). Before `fs.write`, `fs.edit` or `apply_patch` changes a file, the file's earlier bytes are kept as an encrypted spill object behind a signed commitment, and a signed `NATIVE_FILE_CHECKPOINT` row names the call; a file too large, past the session limit, or written without the workspace encryption key is recorded as not kept, never stored in plain text. Because the copies are spill objects, the existing spill inventory, erasure (with legal holds), encrypted export and restore, bundle transport and SQLite retention cover them. `amc session rewind <session> --to-turn N` puts back the files those tools changed after turn N, only where a file still holds what the session last wrote; with any conflict nothing is written unless `--only-clean`; `--dry-run` shows the plan. It is refused in agent mode, for a recognised agent, and while any session in the workspace has a live writer; it is recorded in the signed operations audit, and `amc agent-loop chat --fork-from <session>` then continues the conversation from turn N, citing the rewind as the new session's first row. `amc agent-loop verify` checks the rewind against the cited checkpoints and `amc session show` describes it. Chat gains `--plan` and `/plan`, and a plan-mode turn offers `plan_exit` (when the signed tools policy lists it), which records the plan and ends the turn; only the person leaves plan mode.
