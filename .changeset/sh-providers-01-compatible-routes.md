SH-PROVIDERS-01: named native routes for OpenAI-compatible servers and Azure OpenAI. `--provider` on `agent-loop run`, `acp`, the schedules runner and the SDKs now accepts `groq`, `mistral`, `xai`, `openrouter`, `together`, `fireworks`, `lmstudio`, `vllm`, `llamacpp` and `azure-openai`. Each route sends the unchanged `openai-chat@4` bytes through the shared Chat decoder under its own honest adapter identity (`openai-compatible-chat@1`, `azure-openai-chat@1`, the latter authenticating with the `api-key` header on Azure's v1 surface and requiring an explicit `--base-url` and `--credential`), signs the real provider id in every `request/header`, declares image input and the cache counters `unknown` until proven for that server and thinking, audio, image output, video input and prompt-cache control unsupported, and attaches no catalog pricing. The local servers default to a loopback origin without a credential; a non-loopback origin still requires `--credential`. `--cache-retention` is refused on these routes even though they share the OpenAI encoder: retention admission is now keyed by adapter id, not encoder id alone. `agent-loop chat` and `agent-loop guide` offer them too, derived from the same inventory. The guide and chat now apply the run's credential rule: a default reference goes only to the provider's own origin, so an `--base-url` override (for any provider) needs an explicit `--credential` instead of silently carrying the default key there. Studio's native tasks keep their reviewed provider set by design (a browser-started task may not choose an origin or a local port). `docs/NATIVE_PROVIDERS.md` records each origin and limit.
