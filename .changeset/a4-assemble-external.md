A4 Assemble (behind `AMC_A4_PREVIEW=1`) builds an external path and tightens its native flow.

External path. After Build and before Review (step `built`), an owner in owner mode can run three actions for a path other than native, each recorded as a self-reported implementation ref. `POST …/stages/assemble/scaffold { directory }` writes the path's scaffold (the LangChain callback handler for `langgraph`, `langchain` and `crewai`; the generic HTTP guide for `openai-agents`, `vercel-ai` and `generic-http`; the custom guide for `other`), the bridge contract tests and the agent's policy pack (with its sha256 manifest) into a new workspace directory outside `.amc/` that must not exist yet (`SCAFFOLD_DIRECTORY_EXISTS`). The record binds `a4-scaffold-manifest.json`, which lists every file's sha256; the files are written only after the record commits. `POST …/stages/assemble/connect { mode, adapterId? }` returns connect instructions. The lease token is in that one response and is never stored. The record keeps the leaseId, route, mode and command; a replay answers `token: null` (`TOKEN_ALREADY_DELIVERED`), and a lease whose record is refused is revoked. `POST …/stages/assemble/import { inputPath }` runs the neutral importer over a workspace file or directory with originals retained. The record binds the import manifest, and a refused record rolls the import back. The plan's bounded first task through `createForeignRunner` is listed as unsupported (`NATIVE_TASKS_NO_DELEGATION`, because a foreign child runs only under `spawnSubagent`), with a supervised command for you to run instead. Studio's Build card has these three forms and shows the lease token once, with a Hide control.

Review. Review now refuses a build session whose task does not match the start Build journaled (provider, model, tools, scope digest, validation selection, step and token limits, request id): `409 BUILD_SESSION_MISMATCH`. The prompt is not compared, because the native task view exposes no submission hash; Review records that as not evaluated. Review records each session's effective-policy receipts (signature-checked; their compiled-policy digest and `downgrades`, which also join the limitations) and four execution phases: admission, model completion, side-effect completion and evidence verification. A session with no head event is `build_sessions_integrity` NOT_EVALUATED (`NO_HEAD_EVENT`); no digest is made up for it. `unit_tests_passing` reads evidence present only when every pinned check passed and the session's validation passed; otherwise it reads `not_evaluated (checks pending, unavailable or failed)`. On the stub provider, the capabilities and limitations list is `synthetic_example` in the implementation lane. The non-mandatory item `composition_bound` reads NOT_EVALUATED (`COMPOSITION_SLOTS_UNBOUND`, `KEY:NATIVE_TASK_COMPOSITION_DIGESTS`): `composition.compositionDigest` and `composition.policyDigest` are not recomputed per session yet. The reviewed receipts are bound through the review spec. If the `tools` answer lists fewer tools than the signed scope, Propose lists `tool-subset` as unsupported (`NATIVE_TASKS_WHOLE_SCOPE`), because a native session is granted the whole scope. A declared workflow over 64 nodes is refused before it is parsed recursively.

outcome_unknown and effect decisions. `resolve` records nothing until A4's own dual control holds. It needs approvals bound to the recorded request digest from live project approvers or owners other than the operator: at least the class rule's `requiredApprovals`, and two distinct live-checked (users.yaml) keys when the project is regulated. Otherwise it is `409 RESOLUTION_QUORUM_INSUFFICIENT`. The engine's own fold, which counts any APPROVER's vote, is no longer enough. The resolution is recorded as a `ledger_event` ref on the journal's ACTION_STATE row, still self-reported. The completion effect's Enforce apply receipt is an `artifact` ref, so it resolves with its signature. Deciding an engine request from the A4 card refuses a host session on a regulated project (`403 IDENTITY_CHECK_LIMITED`) and the operator approving their own resolution (`400 SOD_VIOLATION`). It also refuses an APPROVE that the effect's consumption would refuse: A4's separation of duties with the gate's exclusions and the revision's builders. A DENY is still recorded. Refused resolutions return the engine's business reason, or a code with a fixed message, never a workspace path. Readiness names each engine request's status (`RESOLUTION_REQUESTED:…:<status>`, `APPROVAL_STATUS:<status>`). The Outcome unknown card offers the request form again after a DENIED, EXPIRED or CANCELLED request. `effect_gate` and `manifest_active` read only the current completion gate, and the apply effect's execution id names the gate (`a4-apply-<gateId>-<manifestId>`), so a later cycle's failed apply can be retried. The Build card can load an owner's build log from Studio's native task route with its cursor contract.
