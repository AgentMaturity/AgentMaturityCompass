`amc acp` for editors (SH-UI-04): `session/request_permission` is sent when the signed approval gate raises a request, offering `reject_once` always and `allow_once` only with the new `--reviewer-session-token-file <path>` (an operator-pinned tracked login whose decision is recorded through `amc approvals approve`, digest-bound, and read back signed; the reason comes from the client's `_meta` or `--reviewer-reason`, never invented); the request names the committed `tool_call` it gates (flushed to the client first; no request is sent when that row cannot be delivered) and is bound to the prompt that raised it (a late answer cancels that prompt or nothing; the request is withdrawn with `$/cancel_request` when the prompt ends, the approval expires or it is decided elsewhere, and an `allow_once` that arrives after an out-of-band decision records and cancels nothing); `tool_call` updates carry the standard `kind`, `title` and `locations` (absolute, workspace-contained paths) from the signed row; committed `thinking` blocks project as `agent_thought_chunk`; `available_commands_update` lists the workspace skills (the roots an ACP prompt resolves) after `session/new`, `session/load` and `session/fork`. Clients that identify as AMC SDKs or Studio receive each new frame only when they opt in (`thoughtUpdates`, `availableCommands`, `permissionRequests` in `clientCapabilities._meta["dev.agentmaturity.amc"]`), so the shipped SDKs are unchanged; generic ACP clients get the standard set (`docs/ACP.md`). New flags only, no new command: no freeze exception needed.
