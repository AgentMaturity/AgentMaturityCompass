CLI, SDK and ACP native runs can now make tool calls under an active compiled plan whose `identity-binding` requires a principal (`L0-IDN-01`, which every activated plan includes), and runs whose principal does not resolve now refuse at start (P1-79).

- **A run with workspace tools mints its own lease.** `amc agent-loop run` (which `amc agent-loop chat` drives) and each `amc acp` session, at `session/new`, `session/load` and `session/fork`, mint a signed lease through `issueLeaseForPrincipal`. A fork's lease is minted before the operator's fork factory runs and reaches it as `AcpForkSessionParams.leaseToken`, for the factory to compose the child with. The SDK's `AMCNativeClient` runs `amc acp`, so its sessions do too. The lease grants `toolhub:execute` for at most one hour. It names the ACTIVE user of the signed `users.yaml` whose username is the OS account running the process. That user is read from the verified file, never from a flag, an environment variable or a request body. Every call binds the lease to its authorization record, whose principal is that user (`authenticatedVia: "lease"`) and whose `delegation.leaseId` names the lease. The OS account is a local binding: whoever runs as that account and can unlock the vault's lease key acts as that user.
- **Existing flows now refuse.** Under such a plan, a run with workspace tools whose OS account is not an active `users.yaml` user, or whose `users.yaml` does not verify, is refused with `PRINCIPAL_UNRESOLVED` before any session row is written and before any lease is minted. Before this release the session opened and every tool call in it was denied. `amc agent-loop run` exits non-zero. ACP answers `session/new`, `session/load` or `session/fork` (before the fork factory runs) with JSON-RPC error -32602, whose `data.reason` is `PRINCIPAL_UNRESOLVED`, and `AMCNativeClient.newSession()` rejects with `AMCNativeRefusedError` carrying that code and data.
- **Unchanged.** A lease Studio hands an `amc acp` child for a native task is kept. A run without workspace tools mints no lease and is not refused. With no plan, or a plan that requires no principal, nothing is minted and calls bind as before. A delegated child, an in-process `openAgentSession` caller that passes no lease, and every call after a run's one-hour lease expires are still denied under a plan with `L0-IDN-01`. `amc init --regulated` now says which runs mint the lease. The lease records who the calls ran for. It does not show that the plan's controls are satisfied.
