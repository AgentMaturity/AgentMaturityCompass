A4 Forge (preview) readiness and `amc a4 guide`: the next action now names the step the project can actually take. A new project says to answer the questions before running Understand; at Understand's confirmation it says Explain, not Propose (which the routes refuse until Explain has run); at proposed, an open gate, a met quorum, direction approved and built it names the gate request, the approvers' decision, completing the gate, Build or Review instead of "nothing is waiting"; a moved Enforce baseline or a denied gate says a new revision is needed (answer again, then understand, confirm, explain and propose). A blocked integrity item, such as a failed build-session check, now reads BLOCKED and is named, as the gate request already refused it. Readiness also says that approvers must be project members (`members.candidates` waits with `NO_SECOND_APPROVER` and names `amc a4 members … --project-role approver`), and warns on a non-regulated gate whose eligible members are fewer than its quorum (`sod` waits with `QUORUM_UNREACHABLE`; a warning, never a refusal). The deploy plan's receipt form shows `helmRevision` as an integer to replace (0) instead of a string the record route refused. docs/A4_FORGE.md and the README state who approves which gate and how many people a full walk needs, that adding a member supersedes open gates, that a project chain's verification never reads trusted (`--allow-unanchored`, exit 2), that Activate's release approval is refused on a Studio outside Compose or Helm, how the claude-code and pi paths are classified, and that a stub-provider `act_with_approval` build turn is cancelled after 120 seconds unless its approvals arrive.
