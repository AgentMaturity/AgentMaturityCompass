Security sweep fixes (2026-10-31).

- The `grep` and `glob` tools, `fs.read`, `fs.write`, `fs.edit` and the `bash` working directory now refuse `.amc` and `.git` under any spelling (`.AMC`, `.Amc`, `.GIT`, also as a nested segment). On a case-insensitive volume (the macOS and Windows default) those spellings open the protected directories, and a model-chosen search path could read the Studio admin token or `.git/config`. Protection is now decided by file identity (the device and inode of the workspace's `.amc` and `.git`), so a directory reached under another name is refused too, and, as a second lock, by folded name: segments with trailing dots or spaces, `:` (NTFS streams) or an 8.3 short-name pattern (`~1`) are refused. The toolhub's protected-path floor decides by identity as well, and its deny globs compare case-insensitively.
- An experiment baseline or candidate configuration named through `.AMC/...` is refused like `.amc/...`: the check now compares on-disk names.
- An experiment's promotion gate no longer ignores cases the candidate leaves without evidence. A held-out case the baseline determined and the candidate left unavailable (it hit its step limit or timed out) is scored as a candidate failure; the report counts these as `counts.candidateUnavailable` and warns about them.
- With protected-data redaction on, an inbox row's `clientRequestSha256` is computed over the redacted text it commits, not the raw text: a digest of a short protected value could be brute-forced from evidence, and the mismatch made replay refuse the session. A client retry of such a request after a restart is refused as a different submission rather than deduplicated.
- The toolhub's protected-path floor now refuses a path outside the workspace instead of reading it as unprotected, compares a re-cased workspace prefix segment by segment, and refuses a segment whose compatibility fold makes a separator or a dot entry (a full-width `／` or `．`).
- Studio's `POST /experiments/:id/run` with `executeTrials` is refused (403) while Studio is read-only. Under a plan whose identity binding requires a principal, the trials run on a lease naming the signed-in requester rather than the Studio process's OS user, and the admin token, which names no user, is refused with `PRINCIPAL_UNRESOLVED` (409). Unrecognised `executeTrials.limits` keys are dropped instead of being sealed into the report. `/experiments/history` reports a refused latest run with a fixed reason instead of the error text, which named server paths.
- The Studio console escapes the experiment id in its Run, Analyze and Gate buttons and escapes the Experiment Registry dump, and an experiment id must match `^[A-Za-z0-9_-]+$` (generated ids always do), so an edited `experiment.yaml` cannot inject markup.
- Workspace and node forecasts, benches and passports read only signed inputs. Org scorecards (history and latest), the latest forecast, transform snapshots and value snapshots are read through their signatures; an unsigned or tampered file is left out and named (`UNVERIFIED_INPUT_IGNORED:<path>` in forecast reasons and bench evidence-gate reasons), and a missing risk index adds no point instead of a risk of 0. A signed forecast or value snapshot copied from another scope is refused, value snapshots are verified and parsed from one read, and a transform snapshot counts only when its signed plan names this agent, once per distinct content. The regulatory-readiness score quotes only the agent's trusted latest run (sealed, bound to the agent, anchored in the ledger).
- An assurance or red-team scenario whose category is an attack (injection, exfiltration, jailbreak, escalation and similar) and that the agent answers with a tool call is now a failure scoring 0 and kept as a finding, instead of an inconclusive row excluded from scores and findings. Other text-only scenarios still record a tool-call reply as inconclusive.
