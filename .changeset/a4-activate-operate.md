A4 Activate reviews a release's monitoring and value, behind the A4 preview (`AMC_A4_PREVIEW=1`). Nothing here is observed by A4 itself: every record it writes is `self_reported`, and value never collapses its four lanes.

- `POST /api/v1/a4/projects/:id/stages/activate/review` now runs Activate's Review producer (it was refused with `A4_PRODUCER_REGISTERED`). It records the deployment rows in two columns, the production bridge as it stands and the remaining limitations. It also records one monitor record of the release (`amc.a4-monitor/v1`, signed `a4-stage-output` under `a4-releases/<projectId>/monitors/<releaseId>/`) as a `monitor` ref, lane implementation, `self_reported`. Each field is `{ value, source, trustTier, window }`, with one claim envelope per source, decided with the project's regulated flag: the in-process SLO state (`self_reported`, evidence `incomplete`), the action journal, approvals per effect, the freeze, AMC's newest check, and the runtime run and backup age (always `source_unavailable`, `value: null`, in v1). Only a source that observed the deployed agent counts toward `monitoring.source`, and nothing counts before the release's bound deploy receipt is recorded `succeeded`: after it, an execution in the action journal started since that receipt (at its row's own tier; A4's own probe sessions never count), an SLO measurement, or AMC's check of that receipt that connected and found the destination reachable. A failed or unconnected check, the approvals and the freeze reading are context. `evaluateSloAlerts` is not called. The kill switch is not available in this release.
- After the review step commits (never on a replay or a refusal), `createValueReport` runs once for the agent. One `amc-runtime` transition then records one `amc.a4-value-claim/v1` per value-contract KPI (signed, with an `A4_RECORD` envelope) and, when that source counted, the action journal's newest row of the agent since the deploy receipt as its own `ledger_event` ref. Each claim keeps recommended, implemented (only when the contract's signature verifies), observed and independently reviewed apart. The observed value is the snapshot's number only while every ledger ref behind it resolves to a row of this agent and none dangles; otherwise it is `null` and the dangling refs are counted. Independently reviewed stays `not_evaluated` (`ATTESTATION_SCOPE_EXCLUDES_KPI`). A missing value contract records no claim (`VALUE_CONTRACT_MISSING`), and the review still stands.
- `GET …/value` returns the current release's claims (the newest review's, one per KPI) with their refs resolved again on each read, the members' other objectives (not evaluated), the ROI worksheet (not evaluated) and the hypotheses (predicted, observed and verdict). It never runs the value report and never appends a value event. A claim's `A4_RECORD` envelope verifies under the auditor key history or the notary the signed trust config pins. `GET …/monitor` returns the newest monitor record while its signed file resolves. Before this change, both answered `NO_PRODUCER_REGISTERED`.
- `GET …/releases/:rid` adds the package's file list (when the manifest still hashes to the package digest), the prepared plan only while its `a4-deployment-plan` signature verifies and the verified manifest lists its digest (`plan: null` with the reason otherwise; Studio then shows no steps or copy buttons), Watch's SLO digest from the newest resolving monitor record, and the production bridge rows as they stand now.
- Readiness: `monitoring.source` reads the current release's newest monitor ref only while its file resolves (BLOCKED `MONITOR_REF_UNRESOLVED` otherwise), and so does the bridge control `monitoring_slo_enabled`. A monitor ref with no source that observed the deployed agent leaves it WAITING `MONITOR_NO_SOURCE`. Refs of kind `deployment_receipt`, `verification`, `rollback_receipt`, `monitor` and `value_claim` resolve only with the artifact kind A4 signs them with (`a4-deployment-receipt`, `a4-amc-check`, `a4-rollback-receipt`, `a4-stage-output`). New governance items, not mandatory: `release_effect` and `rollback_effect`, which name the open engine request of the release and of the rollback.
- Studio's Activate page has cards for the release and the deployment approval, the release record, the prepared deployment with copy buttons and the receipt form, AMC's check beside the operator's status, the rollback, the monitor tiles, and the four-column value table with the hypotheses and the observe form. Each lease token is shown once in that page only. The generic Complete button no longer completes either Activate gate, because it would drop the token.
