Breaking: `amc verify all` and `amc evidence verify` gain the check status `NOT_CONFIGURED` and the JSON field `notConfigured` for an optional part the workspace never set up, and a part reads `NOT_CONFIGURED` only when authenticated records show it was never configured (the verified, anchored evidence ledger and the verified transparency log for the passport policy and the prompt and forecast schedulers, the verified ledger and the verified log for prompt packs and for A4 projects), so a part whose signed files were deleted fails, a transparency log older than the ledger's configuration witnesses fails as rolled back, an A4 project that either record shows was created and the ledger no longer holds fails (the witness names each project, and a replayed create completes a witness a crash left unwritten; each project chain is checked on the verified ledger handle), and a missing transparency log or seal is skipped rather than recreated, which reads `INCOMPLETE`, or `FAIL` when the ledger holds a witness the log lacks. Absence of a witness proves "never configured" only when both verified records hold the `WITNESSING_ENABLED` marker a new workspace records at creation; a workspace created before 2.0 has none (it is not backfilled), so its unwitnessed parts read `SKIP` and `verify all` reads `INCOMPLETE` until `amc passport init` (or the part's first witnessed save) records the witnesses.
