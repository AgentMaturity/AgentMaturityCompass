Container images now start from `node:22-bookworm-slim` pinned by its multi-platform index digest (resolved 2026-10-11), and `Dockerfile` pins its BuildKit `# syntax=` frontend by digest. `node scripts/check-image-pins.mjs` fails on an unpinned base. The images are still not reproducible: `apt-get` packages and npm production ranges resolve at build time. The quickstart image (`docker/Dockerfile.quickstart`) moves from Node 20 to the same pinned Node 22 base, checks the downloaded 1.1.1 release tarball against `AMC_TGZ_SHA256` with `sha256sum -c` before installing it (an empty or wrong hash stops the build), and runs as UID/GID 10001 instead of root. The README run command is now `docker run -it --rm amc-quickstart` (quickscore) or `docker run --rm amc-quickstart --version`; the old `... amc-quickstart amc` ran `amc amc`. The CI `docker-smoke` job becomes a linux/amd64 and linux/arm64 matrix that builds and qualifies studio, runner and the quickstart natively, and the release workflow is prepared to push each qualified architecture and join them into one `ghcr.io/agentmaturity/amc-studio` tag; it has not run, and no image is published by this change.
