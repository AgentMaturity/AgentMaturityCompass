Claude Code control hooks now govern sessions, not single calls, for Claude Code 2.1.296 only; every existing Claude Code control installation must be re-installed (`amc connect hooks install --provider claude-code --mode control`), because the pinned hooks reference changed (sha256 `31754d5a…`) and the old handlers read as stale.

- **Handlers.** Control installs six exec-form handlers that run AMC's forwarder entry `dist/adapters/hookForwarder.js` (no CLI start-up) with `--event <hook>`, matcher `*`, timeout 10 s and `onFailure: "block"`: PreToolUse, PostToolUse, PostToolUseFailure, SessionStart, UserPromptSubmit and Stop. A handler with another matcher reads as drifted. `amc connect hooks install --dry-run --json` returns the exact `hooks` block it writes. The hidden `amc connect hooks forward` takes `--event` too.
- **AMC only restricts.** The forwarder lets a PreToolUse call through only through `claudeAllow`, and then answers exit 0 with `{}` (no `permissionDecision`), so Claude Code's own permission settings and prompts still decide. The Bridge's answer must verify against its sealed, signed ledger row for AMC's envelope of the exact payload bytes and a fresh nonce, allow the action derived from that payload's `session_id` and `tool_use_id` (`cc.<sha256>`), and bind the SHA-256 of those bytes under a qualified registration with an authorization record. Every other outcome, a missing or unknown `--event`, invalid input, a timeout and any error deny with exit 2. Claude Code no longer receives `ask`: a call that needs approval is denied (`fail_closed_deny`).
- **Payloads.** AMC reads each payload as strict UTF-8 JSON (no byte-order mark, repeated key or lone surrogate) against the release's own schemas, including each mapped tool's input from its `sdk-tools.d.ts`; anything else is denied. `Bash` is mapped only in its pure form (single-quoted words, an absolute binary path, no shell syntax) to `process.spawn`; Glob and Grep globs must stay under their directory; WebFetch URLs must be canonical; MCP and other tools stay unmapped. Write or Edit of `.claude/settings*.json` or `.amc/**`, Read of `.amc/**`, a Grep or Glob whose search root is in or holds `.amc`, `.claude` or `~/.claude` (so a search of the workspace root is denied), and a Bash command any of whose words names those files are denied, every path resolved one way (symlinks, `~`, relative to the working directory, segments folded for case, NFKC and trailing dots) ("AMC protects its hook configuration."); a Bash command can still reach them through a path it does not name. Bodies over 256 KiB are refused before parsing.
- **Sessions.** SessionStart records a signed registration (a lease-holder attestation) after measuring AMC's forwarder, the bound Claude Code binary, the session process's executable and the merged settings (no foreign hook that can change a call; managed `disableAllHooks` refuses), and that no plugin is enabled, no skill or agent declares hooks and the process was not started with `--settings` or `--plugin-dir`, unless managed settings deliver AMC's hooks with `allowManagedHooksOnly`. Every decision re-checks the files, the settings and the session's skill and agent files (any change, or a source AMC cannot read, leaves the session not governed); a session without a registration is not governed and its calls are denied. A session's first registration binds its configuration directory (another is refused); registrations are capped at 30 a minute per lease and 60 per workspace.
- **Admission and observations.** UserPromptSubmit is admitted only on a signed admission row (lease valid, signed policies intact, no freeze), recording the prompt's length and SHA-256, never its text. PostToolUse and PostToolUseFailure record whether the input that ran is the input AMC authorized (`authorizationMismatch`, observed not prevented) and are accepted only with the decision's receipt digest and lease; anything else is recorded as unmatched or as a conflict and refused. Stop records the turn end and never blocks. Observations are capped per session (120 a minute), lease (360) and workspace (1,200); a refused observation is listed in a signed intake summary row (an episode's first refusal at once, then rows of up to 50 ids), its call reads `observationNotRecorded: "rate-limited"` and reason `OBSERVATION_RATE_LIMITED` in `hooks lifecycle`, and the capped scope's calls are denied until its minute passes.
- **Audit latch.** A failure of AMC's own writer while recording for a registered session latches the workspace's hooks in `<AMC home>/state/hook-audit-latch/`: every hook request of the workspace is refused until `amc connect hooks health --recover-latch` (new flag; owner mode, vault passphrase) records the recovery as verified evidence. Input never latches.
- **Lifecycle and API.** `HookActionLifecycleResponse` gains `authorizationMismatch`, `observationConflict` and `observationNotRecorded`. A Pi lease without a named principal now binds the CLI's OS user as principal (P1-78).
- **Measured.** The installed PreToolUse handler takes p50 566 ms / p95 680 ms on macOS arm64 and p50 670 ms / p95 768 ms on Linux arm64 (200 calls, loopback Bridge), far above the 50 ms target.
