wrapFetch's ordinary (non-race) dispatch now meets checkEgress, which applies residency (P2-01) and the kill switch (P2-26) on the `provider` channel before every attempt, with wrapFetch's configured `agentId`. A typed refusal propagates: it is never retried, caught or turned into a fallback, and a kill that lands between retries refuses the retry. `WrapFetchOptions` accepts an optional `workspace`; without one the scoped fallback applies (the asynchronous workspace scope, otherwise only an unregulated working directory). A race stage without its own workspace now uses wrapFetch's. wrapFetch's dispatches (ordinary and race winner) and the race's candidate requests no longer follow redirects: a 3xx is returned (`redirect: "manual"`, or `"error"` when the caller asked for it), so it cannot reach a host the egress check never saw. `amc a4 verify` checks `network-tool` residency for the A4 workspace before each `/readyz` and `/healthz` GET as AMC's own traffic (agent `system`, so a kill does not refuse it); a residency refusal propagates instead of being recorded as a failed check. The A4 API answers an egress refusal with 403 and a named code (`AMC_RESIDENCY_EGRESS_BLOCKED`, or `KILL_SWITCH_ACTIVE`) instead of `A4_INTERNAL`. The generic LLM API client (`LLMApiClient`) checks `provider` residency and the kill switch before every provider fetch, with or without `captureWire`, using a new optional `agentId`; a refusal propagates typed and is never retried, and outside `captureWire` a redirect is returned (`redirect: "manual"`) rather than followed. The egress inventory adds the ordinary dispatch as gated, the A4 deployment verify GETs as gated, and the local Studio liveness probe and wire Unix-socket connections as exempt, the generic LLM API dispatch as gated, drops four rows for code that no longer exists, and its line numbers are refreshed.
