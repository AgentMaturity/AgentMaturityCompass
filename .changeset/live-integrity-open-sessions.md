Verification on a running deployment (LIVE-INTEGRITY-01..07). An unended, unsealed legacy ledger session (a running Studio's gateway, a request in flight, a tool run) is open only while its last signed row is 0 to 15 minutes old at the verification time; a row dated in the future does not count, and nothing is open when any row fails verification. An open session is named, never an error: `amc verify`, `amc verify all` (in `ledger-hash-chain` details), `amc session verify`, the Vault surface of `amc run`, diagnostic reports, assurance runs and `amc agent-loop verify` now pass while Studio runs and print `1 session open: <id> (gateway; last signed activity <n> min ago)`. Any other unended or unsealed session, including one whose end and seal were erased once its last row is older than the window, is `Session <id> missing seal`; r2-c's verified-prefix verdict (`amc verify` exiting 1 INCOMPLETE, `verify all` failing on "only a prefix verified", the Vault module "skipped") and the claim reason `LEDGER_NOT_FINALIZED` are removed.

- The gateway's session: a payload-less signed heartbeat when it has been idle 5 minutes (checked every minute); at start and on every check the running gateway seals a gateway session left by a crashed earlier process once it has been silent 8 minutes, with a signed `interrupted-sealed` marker, in one transaction; a session sealed by someone else is continued in a new one (`resumedFrom`); a failed listen seals the session it opened. Closing is bounded at about 4 seconds: new requests get 503 `gateway shutting down`, in-flight ones get 3 seconds before their upstream calls are aborted, and nothing is written after the seal. Heartbeat and marker rows never count toward trust coverage or gate evidence.
- Each gateway start event witnesses the gateway sessions sealed since the last start (`sealedGatewaySessions`); verification fails a witnessed session whose seal is missing or changed, and no sweep re-seals it.
- Copies: a bundle is verified as of its signed export time when its manifest and files verify under an admitted signer, a certificate as of its signed issue time when its signer is admitted, and a restored backup as of its creation time when it verified as trusted; otherwise at the real time. A bundle export reports `openSessions` (and prints `open sessions: <n>`); the verifier report lists them under `warnings`; restore records them as `INFO:` lines and writes `RESTORE_WARNING.txt` only for a real warning.
- `amc verify --repair` gains the action `seal_interrupted_sessions`: when every failure is the missing seal of an unended, unsealed legacy session with a signed row older than the window, `--apply` seals those sessions with the same marker (no typed confirmation; `--yes` is accepted and ignored). A locked vault is refused with the unlock step and nothing changes.
- Claims: an unsealed report's self-asserted fields are stripped in one place (`distrustUnsealedReport`), which the GRC export now uses too, so an unsealed VALID run exports `untrusted` with `SIGNATURE_INVALID`.
- Docs: scheduled verification with a cron line, a `kubectl exec` CronJob, an exit-code table and the limits of the liveness rule in docs/DEPLOYMENT_CHECKLIST.md.
