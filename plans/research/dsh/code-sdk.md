# SDK & Distribution — DeepSeek Harness monorepo report

## 1. PACKAGE PURPOSES
- `packages/sdk/protocol` — shared wire protocol: newline-delimited JSON-RPC 2.0 transport class + named request/notification types for driving a Harness runtime out-of-process.
- `packages/sdk/client` — TypeScript client SDK: `DeepSeekHarness` (high-level run API) over `HarnessClient` (protocol client that owns the runtime subprocess).
- `packages/sdk/server` — `jsonrpc` Cordis plugin serving SDK clients over stdio; creates one agent per sessionId inside a host composition.
- `packages/bundle/base` — the shared dsh core as a profile patch layer (`cordis.patch.yml`): model adapters, tools, persistence, policy, sandbox, subagent providers.
- `packages/bundle/headless` — one-shot task bundle over base: `dsh --profile headless "task"` → prints final assistant text, exits 0/1.
- `packages/bundle/web-app` — browser-surface bundle: web server, browser plugin roster, client HMR, CLI flags, browser auto-open.
- `packages/experimental/agent-team` — `ctx.agentTeams`: Lead/teammate roster, durable peer mailbox, shared versioned task DAG (private, unreleasable).
- `packages/experimental/tool-agent-team` — model-facing Agent Teams tools (10 schemas, spawn→task-update) scoped per team member.
- `packages/examples` — demo *bundles*: `agent-spine-demo` (executor-less agent spine as one plugin), `acp-demo` (ACP automation app), `jsonrpc-demo` (bin booting an external `cordis.yml` for SDK serving).
- `packages/test-support` — acp-snapshot (keyless snapshot suite kit), agent-loop-testkit, client-runtime (jsdom slot bench), llm-mock-server (scriptable OpenAI-compatible fault server), llm-replay (replay LLM from session JSONL), loader-smoke (subprocess boot harness).
- `python/sdk` — `deepseek-harness-sdk` PyPI dist: synchronous `DeepSeekHarness`/`Session`/`HarnessClient` twin of the TS client.
- `python/sdk-runtime` — `deepseek-harness-runtime-bin` platform wheels carrying a single-file Node exe runtime + default `cordis.yml`.
- `examples/` (top-level) — runnable `cordis.yml` *leaves*: acp-agent, headless-agent, jsonrpc-agent, mcp-memory, web-cordis, web-schedule; ~60% of its 628 files are snapshot fixtures.
- `vendor/` — source-vendored Cordis framework (cordis, cosmokit, schemastery, loader, include, group, timer, hmr, logger-console), rescoped to `@deepseek-ai/*`.
- `patches/` — one pnpm patch: `node-pty@1.2.0-beta.15` spawn-helper resolution for single-exe packaging.

## 2. KEY MECHANISMS
- **Wire protocol** (`packages/sdk/protocol/src/types.ts`, `transport.ts`): 3 requests (`initialize`, `session/prompt`, `shutdown`) + 4 notifications (`session.event`, `session.status`, `subagent.started/finished`). `session/prompt` returns only a durable-enqueue `messageId`; there is deliberately **no per-prompt result** — clients define their own "activity interval."
- **Owned-run semantics** (`packages/sdk/client/src/api.ts`, mirrored in `python/sdk/src/deepseek_harness/api.py`): `run()` queues a prompt, waits for its `messageId` in an `agent/inbox/spliced` receipt, collects every notification through the next whole-agent `idle`, returns `RunResult{sessionId, finalResponse, events, notifications}` (Python adds `finish_reason` from `turn/end.kind`). Subagent lineage from `subagent.started` scopes a client-side session-tree subscription.
- **Teardown ladder** (`packages/sdk/client/src/dispose.ts`, `client.ts`): protocol `shutdown` (1s) → stdin-EOF quiesce (6s) → SIGTERM → SIGKILL (3s), idempotent, with a 400-line stderr tail folded into `TransportClosedError`.
- **Profile bundles**: a bundle is any npm package whose manifest declares `"dsh": {"bundle": {"patch": "./cordis.patch.yml"}}`; `dsh --profile X` composes empty root ← base patch ← mode patch ← home patch ← `--patch` overlays. A patch replaces whole row configs (no deep-merge). Platform-conditional rows use `disabled: !!js process.platform === 'win32'` to pick bash vs pwsh sandbox stacks in one file (`packages/bundle/base/cordis.patch.yml`).
- **Python distribution** (`python/sdk-runtime/hatch_build.py`, `platforms.json`, `scripts/build-exe-for-python-sdk.ts`): the runtime wheel's root `package.json` is a pure dependency manifest whose closure IS the exe's plugin set; carriers are `exe` (pkg'd Node 24 single file + ripgrep `-rg` sidecar + macOS `-spawn-helper`) and dev-only `node` closure. Fixed wheel tags `manylinux_2_28_{x86_64,aarch64}`, `macosx_14_0_arm64`. Zero-config = client injects the wheel's `cordis.yml` via `DSH_CORDIS_CONFIG`; the runtime itself always demands explicit config.
- **Vendoring** (`vendor/README.md`): 9 Cordis packages rescoped to `@deepseek-ai/*` (to avoid registry-squatting upstream names on publish), 18 exhaustively logged local modifications (fiber lifecycle hardening, transactional loader reconciliation, lazy `!!js` config resolution, `dsh --dump-config` support), with a `verify-vendored-links` hygiene gate asserting workspace `link:` resolution.
- **Snapshot testing** (`packages/test-support/acp-snapshot/`): scenario table + fixtures dir → full describe tree; normalizers tokenize cwd/UUIDs/system-prompt/tool schemas (`{{cwd}}`, `{{system}}`, `{{tools}}`), enforce stdout protocol purity, and structurally carry stable UUIDs across fixture refreshes. `llm-replay` reconstructs model streams from persisted `assistant/chunk` events; `replay.override.json` sidecars inject non-replayable failures (pre-chunk throw, hang with `readyFile` cancellation marker).

## 4. PATTERNS WORTH STEALING
1. **Enqueue-receipt + idle-boundary run semantics** — no fake "response to prompt" attribution; `RunResult` documents an *interval*, honest under steering/injection (`packages/sdk/client/src/api.ts`). Great for any agent SDK.
2. **Manifest-as-distribution**: the Python wheel's plugin set defined solely by a dependency-manifest `package.json` compiled into a single exe; adding a capability = one dependency line (`python/sdk-runtime/package.json`, `README.md`).
3. **Zero-config as visible parameter pass, not hidden fallback** — the runtime always demands explicit config; the *client* injects the bundled default via env, disabled the moment the caller customizes launch (`python/sdk/src/deepseek_harness/client.py:_inject_bundled_default_config`).
4. **Profile = ordered patch layers over an empty root**, with `!!js` interpolated `disabled` rows for platform gating and a `--dump-config` that reuses the exact production patch algorithm (`applyEntryPatches`, vendor mod #11).
5. **Fixture-is-the-session-log replay** (`packages/test-support/llm-replay`): record once with a real key, replay keylessly forever; override sidecars for unrecordable failure modes.
6. **Exhaustive vendor-divergence ledger** with CI-enforced link resolution and a rescope script (`vendor/README.md`) — auditable framework ownership.
7. **Twin SDKs with one documented contract** — TS and Python clients explicitly mirror each other's layering, filter-crash isolation, and dispose ladder; docs cross-reference the twin.
8. **Every README carries "Model Experience / Token effect / KV Cache effect / Known Limitations"** sections — prompt-cost accounting as a documentation standard.

## 5. MATURITY NOTES
- 57 test files in this area (unit + `.e2e.ts` + pytest); Python suite covers runtime resolution, macOS deployment target, release-version match, bundled carriers (skip-if-unbuilt). CI: `python-runtime` job runs smoke scenarios against a freshly built exe with committed model-visible snapshots (`scripts/snapshots/python-sdk-single-exe/`).
- Effectively zero TODO debt in code: 1 real TODO (`examples/acp-agent/tests/acp.snapshot.ts:133`, scenario-ownership move); others are false positives.
- Experimental surface is formally gated: `@deepseek-ai/dsh-experimental-*` prefix, `private: true`, release-family exclusion enforced by workspace constraints; promotion procedure documented (`packages/experimental/AGENTS.md`).
- Known limitations are candidly documented per package: no wire-level cancel or per-session close in the SDK protocol; sessions live until process shutdown; patch layers have no deep-merge; DeepSeek-specific adapter fallback in server initialize; ACP mailbox is process-local retry, not cross-process exactly-once; one open upstream issue referenced (#2488, macOS/Linux runtime-context divergence).
- Windows: SDK runtime wheels ship Linux x64/arm64 + macOS arm64 only (no Windows wheel), though the base bundle supports win32 via pwsh/ACL sandbox.
