# Pages 13–32: Cordis Paper Summary

## §3.1.2 (end): Effect Composition and Lifting (pp. 13–15)

- **Effect composition `f ◇ g`** (Eq. 13): runs `g` then `f` on context Γ, composing yielded inverses as `s ∘ t` (undo in reverse order).
- **Thm 10**: `(𝔈_Γ, ◇)` is a monoid with unit `η_Γ = γ ↦ (γ, id_Γ)`; pairing `(f,g)` into effects is a monoid homomorphism from 𝔗_Γ.
- **Thm 11**: witnessed effects `𝔈*_Γ` form a submonoid — composing revertible effects stays revertible; any pair with `g∘f = id` lands in `𝔈*_Γ`.
- **Def 12 (`effect_Γ`)**: lifts `𝔈_Γ` to `𝔈_∂Γ` — the runtime mechanism of effect tracking: applying an effect on the lifted context `(γ, φ)` produces `((δ, φ∘g), track(g, pr₁∘e))`. The inverse of an effect is itself an effect (undo = re-perform), and it composes onto the accumulator exactly as `track` prescribes. **This is how the runtime tracks inverses automatically.**
- **Thm 13**: `effect` preserves ◇ (homomorphism), so tracking composites = composing tracked effects.
- **Thm 14**: projection `pr₁` relates lifted maps to the maps they lift (two-level commuting diagram).
- **Thm 15**: the lifted inverse recovers the state exactly: `g′(Δ) = (γ, φ∘g∘f)`; accumulator is restored iff `g∘f = id`; in every case `(φ∘g∘f)(γ) = φ(γ)`, preserving the soundness invariant (recovery target untouched).
- **Thm 16 (LIFO revert)**: applying `e₁…eₙ` then reverting in reverse order recovers each intermediate state; every step satisfies the soundness invariant — needs no independence hypothesis.

## §3.1.3 Independence of Effects (pp. 15–17)

Motivation: revert at a state foreign effects have moved — withdrawing one component from a running system, or interleaved multi-component sequences. A single accumulator settles neither.

- **Def 17**: **transformation monoid `𝔐(e)`** = submonoid of Γ→Γ generated by e's forward map plus every inverse it yields.
- **Lemma 18**: commutation is settled on generators; ◇ enlarges no monoid.
- **Def 19 (independence)**: (1) every transformation of one commutes with every transformation of the other; (2) neither's transformations disturb the inverse the other yields. Pairwise independence for families.
- **Thm 20**: for pairwise-independent witnessed effects, an inverse run at a later state withdraws exactly its own contribution — reaches the state the sequence-without-it would have reached, and other inverses are unchanged.
- **Cor 21**: n inverses may be applied at `δₙ` in **any permutation** and reach `γ₀`.
- Design summary: these constructions are **revertible effects** delivering *local temporal composability*: loading a component = applying its effect sequence accumulating inverses in φ; unloading = applying φ. Where independence fails, order is carried by the accumulator (LIFO within a component, §4.3.2) or by a **declared coeffect** ordering activations across components (§4.3.1).

## §3.2 Reactive Coeffects (pp. 17–22)

*Spatial composability*: components declare dependencies; the system resolves, provides, withdraws them at runtime, re-evaluating satisfaction on each context change.

- **§3.2.1 Def 22 (coeffect context Σ)**: dependent partial function `(k:K) ⇀ 𝒱ₖ` (typed IoC container). Operations: apply, extend (precondition k∉dom), restrict (k∈dom); violated preconditions error, no transition.
- **Def 23**: `get`/`set`; **`set(k,v)` has type `𝔈*_Σ`** — a witnessed effect on Σ, so `effect_Σ` gives automatic tracking/recovery of dependency registrations. Key synergy: *coeffect operations are effects; effects are revertible*.
- **Def 24 (coeffect at key k)**: triple `(𝒱ₖ, ≃ₖ, 𝒜ₖ)` — value type, comparison equivalence, and operations. Each op `a : Xₐ → 𝒱ₖ ⇀ 𝒱ₖ×(𝒱ₖ⇀𝒱ₖ)×Bₐ` (effect + outcome) must respect ≃ₖ; its **lift** `a^Σ` (Eq. 23) reads/writes only binding k — typing confines it, no side condition needed.
- **§3.2.2 satisfaction predicate** `σ ⊨ d := ∀k∈d. k∈dom(σ)` — decidable; since all mutations pass through effect functions, satisfaction changes are detectable at each effect boundary — **the algebraic basis of reactivity**.
- **Def 25/26**: spec `d = Set(K)`; `notify_d(σ,σ′)` classifies transitions as **activating / deactivating / neutral**. Reactive invariant: activation executes effects (with tracking); deactivation applies the accumulator. Delivers *local spatial composability*: activate only when satisfied; every loss of satisfaction detected where it happens. Gap: ordering a provider's withdrawal after the deactivations it causes is global (→ §4.3.1).
- **§3.2.3 Def 27 (realizations)**: *in-place* (mutate + nontrivial inverse) vs *derived* (fresh derived context, identity inverse, recovery discards it). §5.1.2 implements both. Isolation/interception use derived realization — no inverse to track.
- **Def 28/29 (isolation)**: `Σ^iso = (ρ,σ)` — realm table + realm-keyed store; `get` resolves `ρ(k)` then `σ(r)`; `isolate` derives context. Runtime ad-hoc polymorphism: same key, different values per context (multi-tenancy, testing, sandboxes).
- **Def 30/31 (interception)**: context-carried metadata ι + provider functions; component-declared metadata d(k); per-key monoid `⊕ₖ`, **right-biased merge** — enclosing context overrides the component's declaration without modifying it.

## §3.3 The Context Paradigm (pp. 22–27)

- **Def 32 (Γ∞)**: `μΓ. Γ×(Γ→Γ)×Σ` — recursive unified context: state, accumulator, coeffect table. `effect` maps `𝔈_{Γ∞}` to itself. Any shared mutable state encodes as a dependency. **Hierarchical composition**: parent aggregates child effects (tree-shaped control); loading = plugging in, unloading = unplugging without affecting others.
- **§3.3.2**: recovery holds only up to **observational equivalence ≃** (free/malloc, generative names). **Def 33**: contexts related when same keys bind ≃ₖ-related values. **Def 34/Lemma 35**: indistinguishability `≈_𝒜` via tests (words over operation generators, comparing outcomes) — the coarsest admissible relation. **Def 36/37**: `𝔈*_Γ` re-read up to ≃; **Lemma 38**: all §3.1 equalities survive.
- **Def 39/Thm 40**: operation independence adds undisturbed outcomes; **operations at distinct keys are independent outright**. Commutative keys: tables of independent entries (route/listener registries) yes; ordered middleware chains no; allocators depend on published interface.
- **Def 41/Thm 42**: coeffect-mediated effects (stages choose continuations by outcome) at commutative keys are independent — discharging §3.1.3's assumption. Decomposition: effects carry the commuting part; coeffects carry the order-sensitive part (accumulator LIFO within a component; provider-before-declarer across components). Composability at component grain.
- **§3.3.3**: paradigm spectrum — functional state-threading (traceable, boilerplate-heavy) vs implicit mutation (React's `useEffect` call-order fiber state; Spring's `getBean` service locator). Context paradigm: explicit context parameter gives attribution; **teardown is derived from loading** (inverses compose); runtime auto-resolves and re-wires dependencies — correctness structural, not discipline.

## §4 Calculus of Dynamic Composition (pp. 28–32)

- **Def 43 (component)**: triple `(d, p, e)` — dependency spec, **provision** (keys it may provide; effect writes no key outside p), witnessed effect. Provisions of distinct fibers disjoint (single provider per key; no realms in the calculus).
- **Def 44 (fiber)**: `⟨d,p,e,π,σ,τ,θ⟩` — component fields + parent π, own coeffect table σ (written by its effects as they run), retirement flag τ, lifecycle state `θ ∈ Inactive | Active(g, ω)` with accumulator g and **committed view ω : d → 𝔑** (key ↦ provider fiber name at commit time). Fiber names are atoms (dynamic local names discipline).
- **Def 45 (registry)**: `F_γ : 𝔑 ⇀ 𝔉_Γ`, parent pointers form a tree rooted at root. **Coeffect context is derived, not stored** (Eq. 40): σ_γ = union of Active fibers' tables; provisions disjoint ⇒ unique `provider_k(γ)`. Only the coeffect part is recorded this way; other effects tracked by g but unnameable in specs.
- **§4.2 base calculus** (atomic, immediate, infallible transitions): **Def 46 target view** `target_n(γ)` = ⊥ if retired or unsatisfied, else map each declared key to its provider; **quiescent** when every fiber matches its target. Recording the *provider* (not value) makes comparison usable; implementation holds `fiber.committed` and a hash in `fiber.target` (§5.1.3).
- **Five rules**: orchestration **O-Insert** (fresh name, disjoint provisions — single-source imposed here), **O-Retire** (unconditional request; lifecycle carries it out), **O-Remove** (only retired+Inactive+childless — prevents accumulator leaks; children before parents); lifecycle **L-Reload** (Inactive, target ≠ ⊥ ⇒ run e, install accumulator + committed view) and **L-Unload** (committed view ≠ target ⇒ apply inverse, discard view). Reactive: transitions fire whenever the target view changes, regardless of cause.
- **Def 47 (registration)**: an effect application may register a component (O-Insert with π = self), inverse = O-Retire (not Remove, since removal has failable premises) — how plugin hosts load plugins.
- **Def 48 (confinement)**: an effect confined to n writes only its own σ (plus registrations) and reads only σ_n, its declared keys' tables, and fiber-table-free state — a fiber sees the coeffects it declared and no control fields; makes Table 1 (§4.4) a complete inventory. Rules are nondeterministic and reactive.

**Agent-harness claims: none in these pages.** Runtime relevance: effect tracking via `effect_Γ` accumulators; coeffect resolution via derived σ_γ union + provider uniqueness; component lifecycle as target-vs-committed-view comparison (the reconciliation loop underlying loader/HMR — reload fires automatically when a provider changes); implementation pointers to §5.1.2 (both realizations) and §5.1.3 (committed/target hash fields).
