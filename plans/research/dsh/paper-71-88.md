## Pages 71–88 Summary (Cordis paper)

### §6.4 (end) — Language Independence: access interposition & metaprogramming
- Host language must let the runtime **interpose on dependency access transparently** without changing consumer code — e.g., JavaScript `Proxy`, Python descriptor protocol (`__get__`); absent such a primitive, runtime reflection can mediate access dynamically at the cost of type safety/DX.
- Metaprogramming supplies typing + mediation together: annotations/decorators attach metadata a processor expands into a mediating accessor; compile-time metaprogramming (Rust proc macros, Scala macros, Zig comptime) emits a typed declaration plus accessor per dependency, dispensing with a general interception primitive.

### §6.5 Mutual Dependencies and Component Granularity
- **Design decision:** in the reactive coeffect model, a dependency cycle (A needs a key from B, B from A) simply leaves both components **permanently inactive** — satisfaction predicates never become true. Unlike deadlock, this is **predictable from dependency declarations alone**, so the runtime reports it at component load time.
- **Mechanism — cycle decomposition:** any bidirectional interaction factors into unidirectional bindings. Example: server + access-controller become four components (server-core, access-control-core, request-mediation, policy-management); only integration components depend on both cores, eliminating the cycle. Always possible in principle; integration components can grow quadratically with n interacting components. No correctness/performance cost (components are lightweight); finer granularity increases composability but raises developer cognitive overhead. Mitigations (engineering, not theory): package bundling, convention-based wiring, scaffold tooling generating boilerplate integration components from declarative specs.

### §6.6 Dependency Typing and Versioning
- In the formal model, a link is **nominal**: providing key k satisfies any declarer of k; type family 𝒱ₖ only guarantees agreement within one compilation unit. Two failure modes across independently built components: **interface drift** (provider changes the interface behind k; coeffect satisfied — k ∈ dom(σ) — but value violates consumer expectations) and **key collision** (unrelated providers reuse key name k; no shared lineage, unpredictable failures).
- Gap: coeffect model supports only nominal linking, not versioned or structural linking. Three approaches:
  1. **Key namespacing** (K → K × P, package-qualified keys): kills collision by construction but couples the formal model to an external package registry.
  2. **Peer dependencies** — *what Cordis currently adopts*: components don't bundle dependencies; the runtime context supplies them; the host package manager (e.g., npm peer deps) enforces version ranges at **install time**. Limits: relies on faithful semver; package managers resolve one version per package, blocking multi-version loading.
  3. **Structural compatibility**: replace k ∈ dom(σ) with a structural-subsumption predicate (width subtyping easy; behavioral contracts hard; undecidable with bounded quantification). Unifying all three while preserving dynamic-composition guarantees is stated as an open problem.

### §6.7 Co-Design with Languages and Operating Systems
- **Language co-design:** a context-paradigm language can make the context **implicit** again (Definition 27 distinguishes in-place vs derived context realizations; derived needs a language construct). Benefits: (1) functions needn't thread the context as an argument/receiver; (2) closes two leaks of the library realization — an effect installed via a captured foreign context escapes its lifecycle, and a coeffect read there escapes its dependency specification. Compiler-known effects/coeffects: an effect iterator (Definition 51) currently allocates a closure per step to hold the inverse + restore state; with effect syntax the compiler can emit **one state machine holding inverses in its frame**. Coeffect specs in the type system give compile-time cycle detection (vs runtime, §6.5) and structural (row-type-like) dependency comparison.
- **OS co-design:** OS-level would supply fine-grained composition (vs coarse process/container temporal/spatial composability). OS supplies the **sandbox §6.3 defers externally**: bound a component to declared dependencies, supply them at load, nothing else reachable — like a WebAssembly module receiving imports at instantiation; also OS-native coeffect isolation/interception (per-component key binding, access mediation). OS resources as coeffects: kernel records acquisitions once per requesting component (memory, file descriptors; cf. Nooks-style kernel tracking); OS can make revertible operations that a runtime (§6.1) can only withhold/compensate — transactional persistent writes rolled back, copy-on-write/immutable storage rewound by moving a pointer.

### §7 Related Work
- **7.1 Effects/coeffects.** Monadic systems (ZIO, Effect-TS, fp-ts): tracking bought via monadic embedding and requirements discharged by interpretation; Cordis instead tracks effects **as an overlay over ordinary host code** and pairs each effect with an inverse, **re-resolving as providers come and go**. Effekt (effects-as-capabilities): shares context-as-mediator, but targets modular interpretation and static, scope-based discipline; Cordis targets **tracking and reversion at runtime**. Heunen et al. reversible effects (dagger/inverse arrows): closest formal account; categorical, globally invertible, two-sided inverses; Cordis requires less — only each **atomic effect admits a one-sided, caller-supplied inverse**; composite inverses follow by composition. Orchard et al. graded modal types (Granule) unify effects/coeffects statically; Cordis's contribution is **orthogonal: lifting both notions to runtime mechanisms** re-resolved as the loaded-component set evolves.
- **7.2 Paradigms.** COP: nominal resemblance; COP's context is ambient situation and layers neither track nor revert side effects; Cordis's context is the Γ∞ entity, activation runs revertible effects driven by reactive coeffect satisfaction, deactivation reverts fully; COP is expressible as one coeffect (minus dynamically-scoped activation). AOP: Cordis's aspect-analogue is a shared coeffect — declared, not oblivious pointcuts — giving determinacy/traceability at the configuration layer; crosscutting changes are lifecycle-integrated (reverted on unload, propagated reactively), unlike standalone dynamic weaving.
- **7.3 Temporal composability.** Four families: (1) **stateful forward migration** — quiescence (Kramer/Magee) / tranquility; Cordis's rolling-update pattern enforces this by draining in-flight requests; DSU (Hicks, Stoyle, Kitsune), Erlang `code_change/3`, HMR (webpack/Vite `module.hot`/`import.meta.hot`) migrate state forward; Cordis module replacement instead **reverts old tracked effects and reapplies the new component's from a clean slate** (state survives only in longer-lived dependencies; layering DSU atop revertible effects is future work) — but needs no hand-written migrations and supports full unload + resource recovery. (2) **Developer-authored recovery** (OSGi/IDE unload callbacks, Command undo, sagas, finalizers, event sourcing): inverse is an unenforced duty; React `useEffect` pairs effect/cleanup structurally but can't compose (no conditionals/loops/async/iterators); Cordis effects compose freely, hand-written inverses only for atomics, **complete recovery is a system invariant**. (3) **Statically scoped reversal** (STM, reversible computing/Janus, RCCS, causal-consistent reversibility ≈ Cordis's LIFO accumulator + Theorem 63 guard deferring provider withdrawal until consumers deactivate; linear types/RAII/Rust fix scope statically; Cordis fixes none in advance, reverting over component lifecycle). (4) **Interposed reclamation** (Nooks, shadow drivers, Akeso): runtime-maintained records — closest systems precedent; but platform fixes what's recordable, whereas Cordis components introduce novel effects with per-atomic inverses, reverting whole lifetimes and propagating removal to dependents.
- **7.4 Spatial composability.** DI frameworks (Spring, Guice, Angular) and UI context wire at initialization, never re-resolve reactively; Cordis's reactive coeffects trigger **lifecycle transitions whenever satisfaction predicates change**. OSGi Declarative Services/iPOJO/R-OSGi are closest (provide/require prefigures `ctx.provide`/`ctx.get`), but recover via hand-written synchronous deactivation callbacks; Cordis reverts accumulated effects automatically and its **inertial Unloading state (§4.3.3) runs asynchronous teardown to completion before further change**. FRP/signals are value-level, glitch-free per turn; Cordis is component-level, guaranteeing only that no single transition straddles two coeffect resolutions (**Theorem 64**); complementary — a coeffect can carry reactive values.

### §8 Conclusion
- Recap: **revertible effects** (every context transformation carries a runtime-tracked inverse; tracking and recovery preserve composition) + **reactive coeffects** (activation/deactivation/neutral classification against coeffect specs; isolation varies key resolution, interception varies binding use) unified in a single **context type** with observational equivalence giving effect independence; components yield a calculus whose metatheory carries spatiotemporal composability from one component to interleaved systems. Realized as the **Cordis meta-framework: core library for effect tracking and coeffect resolution, plus a declarative component loader with configuration reconciliation and hot module replacement**; validated by the **Koishi case study (4000+ community plugins)**.
- **Agent-harness claim:** self-evolving agent harnesses (§1.2.2), where an AI agent generates/replaces its own harness components continuously with little oversight, are the compelling future validation — testing temporal guarantees (complete recovery under rapid replacement) and spatial guarantees (dependency coordination under frequent topological change), positioning Cordis as a foundation for recoverable, coordinated, continuous self-evolution in agent harnesses and autonomous systems.
