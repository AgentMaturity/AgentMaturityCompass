## 2. KEY MECHANISMS

**Twin LLM adapters over one seam** (`packages/llm/llm/src/index.ts`, `types.ts`, `assembler.ts`): adapters implement `stream(): AsyncIterable<StreamChunk>` and register routes; `BlockAssembler` folds deltas so adapters never reassemble. Strict contract: `usage` before `finish`, tool args stay raw JSON strings, one adapter call = one provider attempt, empty completions map to retryable `EMPTY_RESPONSE`, `max-tokens` drops truncated tool calls (and prunes replay-envelope entries in step). `prepareCall()` pins one adapter registration across capability resolution, durable `request/header` logging, and dispatch so HMR can't mix adapters. Requests are deep-frozen and reconstructable from the session log (`docs/subsystems/llm-streaming.md`). Adapter-private `ReplayEnvelope` state is passed back only when the same adapter instance owns both historical and target providers.

**Retry as a loop concern, not a transport wrapper** (`packages/llm/llm-retry`): failures surface via the `agent/request-error` waterfall; each retry opens a fresh durable turn reconstructed from the log. Policy (`normal` finite / `always` unbounded, backoff+jitter, code allowlist) is captured per provider route at registration; durable `llm/retry`/`llm/retry-started` events with a shipped `./invariant` checker.

**Continuable subagents** (`packages/subagent/subagent/src/continuation.ts`): a durable child Session has at most one process-local Activation; the child Agent's inbox is the only FIFO — no second queue, no result wrapper. Providers contribute only a `ContinuableCreateSpec` (optionally a parent-history seed); the manager owns identity reservation, cold resume via `ctx.agents.resume()`, ownership graph, child-first disposal, and an unconditional manager-authored settlement notice to the parent (distinct `subagent-settled` provenance so runtime words are never credited to the child). Capability discovery is split: start-time flags checked pre-start (fail loud on `UNSUPPORTED_CAPABILITY`), continuable capability = method presence (`prepareContinuable`).

**Workflow engine** (`packages/workflow/workflow-worker-thread`): one `node:worker_threads` worker per run executes the model-written script in `node:vm` (containment, not security); children run host-side via `ctx.subagents` over a typed message protocol. Script hooks: `agent()`, `parallel()`, `pipeline()`, `phase()`, `log()`. Hook misuse throws `fatal` errors that combinators re-throw (never dissolve into `null`); cancellation force-settles within `disposeGraceMs` even against a spinning script. `materializeFromRealm` enforces plain lossless JSON across the realm boundary (`__proto__`-safe).

**Jobs** (`packages/jobs/jobs-local`): `<kind>-N` ids, authorization by owner session (not id secrecy), first-wins settlement, `start()` refuses owners no attached controller serves, scope-layered listeners so per-preset `tool-jobs` mounts see only their own agents. Completion notices wake idle owners with a bounded `maxConsecutiveWakes` budget to stop self-exciting wake loops.

**Hooks bridges** (`packages/hooks/hook-protocol/src/*`): shared matcher/exec/decode/merge primitives (`deny > ask > allow` fold; exit-2 = block); bridges map `hooks.json` events onto native waterfalls (`tools/pre-execute`, `agent/pre-step`, `agent/turn-stopping`); detached emit-point runs tracked by `createDetachedRuns()` so dispose reaches quiescence. Durable `hook/invoked`/`hook/result` session events.

**Skills** (`packages/skill/skill/src/index.ts`): host+per-scope layered provider registry (nearest layer wins); rank-ordered root discovery, incomplete-observation semantics (never cache partial discovery; consumers keep last-good catalog), and a digest-driven durable `<available_skills>` catalog republished via `agent.inject()` only when rendered entries change (`packages/skill/tool-skill`).

**Presets** (`packages/preset/agent-presets`): a preset directory mounts once per process under a standing scope; sessions join by scope-key parenting (`agent → preset → global`). Generation stamping (mtime+size) means edits apply to new sessions while running ones keep their composition; children join via synchronous `composeFrom()` bind, recorded on their durable header.

**Schedule** (`packages/schedule/schedule`): the session log is the only durable authority (`schedule/change` events, strict v1 fold); the live-owner timer is a disposable projection. Delivery claims the Agent's idle maintenance phase, queues one `followup()`, never steers; fixed-rate records advance directly past missed occurrences (at-least-once, batched).

## 4. PATTERNS WORTH STEALING

- **Reconstructable requests**: every model request is a pure function of the durable session log (`request/header` snapshots + derived history), with a dev invariant recomputing the equation — retries, replays, and audits get exact fidelity (`docs/subsystems/llm-streaming.md`, `packages/llm/llm/src/call-config.ts`).
- **Retry at the turn boundary, not the transport**: `packages/llm/llm-retry` — one adapter call = one attempt; recovery opens a new durable turn; policy captured per registered route so disposal can't change an in-flight failure's policy.
- **Capability = fail-loud flags for options, method-presence for whole modes** (`SubagentCapabilities` vs `prepareContinuable`, `packages/subagent/subagent/src/types.ts`): requests needing unsupported features reject rather than degrade silently.
- **Agent inbox as the only queue**: continuable children take follow-ups, reports, schedule dispatches, and job notices all as FIFO turns or step-boundary injections — one ordering, no parallel mailbox (`packages/subagent/subagent/src/continuation.ts`).
- **Provenance-typed context** (`MessageSource` kinds + semantic `ContextForm` vocabulary: instructions/catalog/snapshot/notice/relay/recall) so transcripts never credit runtime accounts to agents (`packages/llm/llm/src/message.ts`).
- **Dormant-provider directory**: adapters declare routes configuration *could* activate (`listConfigurableProviders`) so settings UIs offer providers before any exists; live activation without restart (`packages/llm/llm-pi-ai`).
- **Digest-driven durable catalogs**: skill/tool catalogs republish full replacements only when the rendered digest changes — KV-cache-friendly and compaction-recoverable (`packages/skill/tool-skill`).
- **Bounded wake budgets** for completion notices (`packages/jobs/tool-jobs`) — prevents self-exciting agent wake loops.
- **Standing preset mounts with generation stamps** (`packages/preset/agent-presets`): one mount serves N sessions; edits apply forward only; children bind synchronously to the parent's exact generation.
- **Model Experience sections in every README** documenting what the model sees, token cost, and KV-cache effect per feature — a discipline worth copying wholesale.
