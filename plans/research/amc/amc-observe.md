# AMC Observation Plane — Exploration Report

## 2. HOW IT ACTUALLY WORKS

**Gateway proxy** (`gateway/server.ts:startGateway`, started by `studio/studioSupervisor.ts` on `amc up`, default 127.0.0.1:3210): request → longest-prefix route → strip agent-provided credentials (`stripAgentProvidedCredentials`, lines 397–448, denylisted headers + query keys) → verify signed lease token (scope `gateway:llm`, revocation list, per-lease RPM/TPM computed by replaying last-minute ledger events in `usageCountersLastMinute`) → budget check → redact headers/body → `ledger.appendEvidenceWithReceipt` `llm_request` → inject real upstream key from env (`applyAuth`) → forward with circuit breaker + retry/backoff (`requestUpstreamWithResilience`) → redact + record `llm_response` with signed receipt → respond with `x-amc-request-receipt` headers. `streamPassthrough:false` (default) buffers whole responses; when true it streams while still buffering chunks for evidence and delivers the response receipt in an `x-amc-receipt-trailer`. A second listener (3211) implements HTTP CONNECT with client-CIDR checks, `proxy:connect` lease scope, and host allowlist (`hostAllowed`, deny-by-default) — TLS tunnels are audited by destination only.

**Env rewriting** (`adapters/envAssembler.ts`): `assembleAdapterEnv` strips all provider keys from `process.env` (`stripProviderKeys`), then sets adapter-declared base-URL env vars to `{{gatewayBase}}{{providerRoute}}` and API-key env vars to the *lease token* (e.g. claude-cli sets `ANTHROPIC_BASE_URL` + `ANTHROPIC_API_KEY=<lease>`), plus `AMC_*` vars and optional `HTTP(S)_PROXY`/`NO_PROXY`. The gateway later recognizes the lease in the auth carrier and swaps in the real key.

**Monitored spawn** (`adapters/adapterRunner.ts:runAdapterCommand`): requires Studio up; issues a lease bound to budgets, spawns the CLI with the assembled env (or via `sandbox/runSandboxCommand` in SANDBOX mode), tees redacted stdout/stderr into ledger events `agent_process_started/stdout/stderr/exited`, seals the session. Unsigned adapters config forces `AMC_REQUESTED_MODE=SIMULATE`. Parallel legacy paths: `amc wrap <runtime>` / `amc wrap --agent-token` (posts events to `/bridge/telemetry` as `amc-wrap`) and `amc supervise --route`.

**Hook write flow** (`adapters/hookIntegration.ts`): `amc connect hooks install --provider claude-code|gemini-cli --mode observe|control` edits `.claude/settings.json` / `.gemini/settings.json`, adding handlers on `PreToolUse`/`PostToolUse`/`PostToolUseFailure` (Claude) or `BeforeTool`/`AfterTool` (Gemini) that run `amc connect hooks forward --provider … --mode … --agent … --token-file .amc/hooks/<…> --bridge-url http://127.0.0.1:3212`. Ownership is tracked by `statusMessage` (Claude) / `name` (Gemini) markers; a signed manifest (v1/v2, auditor-signed) pins handler SHA-256s, config hash, lease id; a dedicated `hook:observe`(+`hook:control`) lease is written 0600 under `.amc/hooks/` with a managed `.gitignore` block; install is locked, dry-runnable, and remove deletes only AMC-owned handlers.

**Hook consume flow**: the forwarder reads provider JSON on stdin, refuses >256KB/ambiguous JSON, verifies the signed manifest/lease/handler bindings still match (`authorizeForwardInvocation`), maps to a privacy-minimal AEP 0.1 event (`mapProviderHookEvent`: tool args/outputs never forwarded; correlation via provider `tool_use_id` for Claude, or a derived correlation SHA resolved through `/bridge/hooks/aep/0.1/correlation` for Gemini terminal events) and POSTs to `/bridge/hooks/aep/0.1/events` (lease-authed, rate-limited, idempotent replay, signed receipt). In control mode, `PreToolUse`/`BeforeTool` input goes loopback-only to `/bridge/hooks/control/v1`, where `hookControl.evaluateProviderHookControl` replays signed ToolHub/action-policy/approval/budget/governor gates, performs compound shell-command blast-radius review (`enforce/shellCommandPlan`), and returns a native allow/deny/ask response bound to a receipt; any failure emits `failClosedProviderControlResponse` (deny). Gemini `ask` degrades to deny (`capabilityLossy`).

**Bridge LLM path**: `/bridge/{openai|anthropic|gemini|openrouter|xai|local}/...` → intent parse → lease + `enforceBridgePolicy` (provider enabled, route prefix, model allowlist, signed model taxonomy) → prompt-pack policy + optional runtime firewall + truthguard (blocks streaming under ENFORCE) → forwards to the gateway route, recording receipts.

**Log ingestion formats**: (a) `ingest.ts` — arbitrary files as `review` events tagged `SELF_REPORTED`, upgradeable via `attestIngestSession` (re-appends every event as `ATTESTED` + signed bundle-hash audit); (b) `neutralImporter.ts` — detects 8 artifact categories in JSON/JSONL/YAML, redacts, writes normalized episode/lifecycle artifacts + rollback manifest; (c) `amc_trace_v:1` JSONL (`correlation/traceSchema.ts`) parsed inside the neutral importer; (d) AEP hook events; (e) `/bridge/telemetry` process events.

**OTel export** (`observability/otelExporter.ts`): every `ledger.appendEvidence*` calls `queueEvidenceEventSpan`; a shared buffered exporter (spans/metrics/logs; deterministic trace/span IDs from session/event IDs; `amc.*` attributes) auto-flushes at 128 items via `fetch` JSON-OTLP to targets from `AMC_OTEL_ENABLED`/`AMC_OTEL_EXPORTERS`/endpoint env vars; `platformConfigs.ts` maps Grafana Cloud/Datadog (needs local agent)/New Relic; scores and incidents export as metrics/logs.

## 4. REUSE VERDICTS

- **Gateway proxy (`gateway/server.ts`)** — REFACTOR: mechanism (lease→key swap, redaction, receipts, CONNECT) is sound and worth keeping, but it's one 1831-line file mixing routing, auth, CIDR, evidence, and resilience; decompose before wrapping as a service.
- **`gateway/redaction.ts` + `config.ts`** — KEEP-AS-SERVICE: small, schema-driven, self-contained.
- **Bridge hook ingress + control (`hookIngress.ts`, `hookControl.ts`, `hookActionIdentity.ts`)** — KEEP-AS-SERVICE: the strongest asset — pinned AEP schema, idempotency, receipts, fail-closed control; API surface is already service-shaped.
- **`hookIntegration.ts` (installer/forwarder)** — REFACTOR: excellent security posture but 1952 lines fusing installer, manifest verifier, mapper, and HTTP client; split before reuse.
- **`envAssembler.ts` + adapter builtins/catalog** — KEEP-AS-SERVICE: clean, declarative, easily portable.
- **`adapterRunner.ts`** — REFACTOR: spawn/tee/ledger logic is fine but hard-couples to Studio being up and to ledger internals.
- **Bridge LLM facade (`bridgeServer.ts` + compat/)** — REFACTOR: valuable provider-intent parsing, but the 1377-line handler chains prompt-pack, firewall, truthguard, taxonomy concerns inline.
- **`observability/otelExporter.ts` + `platformConfigs.ts`** — KEEP-AS-SERVICE: dependency-free OTLP-JSON exporter with buffering/retry.
- **`runtimes/*`** — REPLACE: trivial `which`+`--help` detection plus an interactive-readline JSON retry harness; superseded by adapter detection and any harness-native runner.
- **`ingest/ingest.ts`** — REPLACE: "attestation" merely re-appends duplicate events with a signed hash — weak semantics, doubles ledger rows.
- **`importers/neutralImporter.ts`** — KEEP-AS-SERVICE: complete plan/validate/import/rollback lifecycle with manifests.
- **Timeline/anomaly/cost/sessionCorrelator** — KEEP-AS-SERVICE individually; independent pure modules over ledger events.

## 5. SURPRISES & DEBT

- **Three unreconciled redaction systems**: gateway (config-driven denylists), bridge (`bridgeRedaction.ts` hardcoded patterns), adapters (`redactSecretsInText` + ad-hoc `redactWithGatewayRules` re-implementing regex application). Same defect class must be fixed thrice.
- **Duplicated resilience code**: `backoffMs`/`sleep`/retryable-status logic copy-pasted in `gateway/server.ts` and `otelExporter.ts`.
- **Rate limiting by ledger replay**: `usageCountersLastMinute` re-reads and JSON-parses a full minute of ledger events per request — O(events/min) on the hot path.
- **`runtimes/common.ts` blocks on stdin**: `runHarnessWithRetries` falls back to interactively prompting a human to paste JSON — lethal in CI/agent contexts.
- **Interactive `--help` probing**: `discoverCapabilities` spawns the target CLI at detect time; slow/side-effectful for some CLIs.
- **`streamPassthrough` still buffers**: even in passthrough mode the entire response accumulates in memory for evidence; large streams are unbounded (only request bodies are size-capped).
- **`src/cli-new-commands.ts.fragment`** — dead uncompiled fragment (shield commands) sitting in `src/`.
- **Legacy triplication of "run an agent under observation"**: `amc wrap`, `amc supervise`, `amc adapters run` are three generations of the same feature, all live; runtimes (`claude|gemini|openclaw`) vs adapters (16) vs hook providers (2) taxonomies don't align.
- **Ingest "ATTESTED" tier is cosmetic**: identical payloads re-appended with a new meta tag; trust upgrade isn't cryptographically distinct from the SELF_REPORTED originals beyond one signed bundle hash.
- **OTel "jaeger"/"zipkin" exporters are OTLP-shaped**: jaeger target defaults to the OTLP port 4318; zipkin payloads are OTLP JSON, unlikely to be accepted by a real Zipkin.
- **OTel flush is threshold-only** (128 buffered items); short-lived CLI invocations below threshold silently drop telemetry unless something calls `flush()`.
- **Docs are unusually honest** (README explicitly disclaims AEP conformance, Gemini ask-degradation, unsupported providers) — public claims largely match code; the gap is breadth (only Claude Code + Gemini CLI have hook contracts; Codex/Cursor/OpenCode explicitly unsupported) and the CONNECT proxy observing TLS destinations only, which the OBSERVED trust-tier table ("Captured via gateway proxy") glosses over.
- **Hook contract pinning is by doc hash/commit** (`CLAUDE_CODE_HOOK_SOURCE` sha256, Gemini repo commit `f354eeb`) — drift detection is manual; no automated re-verification against live provider versions.
