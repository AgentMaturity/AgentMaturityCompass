## 2. HOW IT ACTUALLY WORKS

**Plugin pack format.** A plugin folder = `manifest.json` + `content/` tree. `pluginPack()` (`pluginPackage.ts:201`) runs a secret scan, recomputes per-artifact sha256/bytes/kind (kind inferred from path prefix, e.g. `content/policy-packs/` → `policy_pack`; 9 kinds in `pluginTypes.ts`), then Ed25519-signs the canonicalized manifest and tars `amc-plugin/{manifest.json, manifest.sig, publisher.pub, content/}` into `.amcplug`. Extraction goes through `security/safeTarArchive.ts` with hard limits (10k entries, 128MB entry, 512MB total). `verifyPluginPackage()` checks fingerprint match (manifest.publisher & manifest.signing vs `publisher.pub` sha256), per-artifact hash+size, manifest digest+signature, and re-runs the secret scan.

**Registry protocol.** A registry is a directory (or HTTP base) with `index.json`, `index.sig` (registry-key Ed25519 over canonical index), `registry.pub`, and `packages/<id>/<ver>/plugin.amcplug` (+`.sha256`). `servePluginRegistry` is a GET/HEAD-only static server. Client (`resolveRegistryPackage`) verifies index signature, optional pinned registry fingerprint, publisher allowlist, risk-category allowlist, package sha vs index, then full package verification and cross-checks id/version/publisher/risk vs the index entry. Workspace registry config (`.amc/plugins/registries.yaml`) and `installed.lock.json` are auditor-signed via `org/orgSigner`.

**Install lifecycle = approval-gated.** `requestPluginInstall` (`pluginApi.ts:290`) resolves+verifies, then creates a SECURITY-class approval intent (risk tier high/critical), stashes the package in `.amc/plugins/pending/`, and returns. `executePluginRequest` re-verifies approval, package sha/publisher/risk vs the approved request, copies into `installed/<id>/<ver>/package.amcplug`, updates the signed lock (with policy snapshot hashes), consumes the approval (replay-protected), and appends a transparency-log entry (`PLUGIN_INSTALLED/UPGRADED/REMOVED`).

**Loading.** `loadInstalledPluginAssets` (`pluginLoader.ts:119`) verifies workspace integrity + lock signature, extracts each installed package to tmp, schema-parses each artifact against the target-domain schema (policyPackSchema, declarative assurance pack, complianceMappingSchema, adapterDefinitionSchema, outcomeContractSchema, casebookSchema, transformMapSchema, raw md), and enforces **override rules**: a plugin may not shadow a built-in or already-loaded id unless `.amc/plugins/overrides.yaml` (auditor-signed) allows that publisher/kind/id (`PLUGIN_OVERRIDE_DENIED`).

**Compliance maps.** A mapping = `{id, framework, category, description, evidenceRequirements[], related{questions,packs,configs}}` where requirements are a discriminated union: `requires_evidence_event` (event types + minObservedRatio of OBSERVED trust tier), `requires_assurance_pack` (packId + minScore + max `*_SUCCEEDED` audits), `requires_no_audit` (denylist). `generateComplianceReport` (`complianceEngine.ts:326`) reads ledger events in a window, joins latest assurance runs per pack, evaluates each mapping to SATISFIED/PARTIAL/MISSING/UNKNOWN with evidence refs (event hashes), computes trust-tier coverage, and — crucially — **downgrades SATISFIED→PARTIAL if the maps file signature is invalid**. Reports carry explicit `nonClaims` ("not legal advice"). Maps live at `.amc/compliance-maps.yaml` + `.sig` (auditor key, VAULT/NOTARY envelope supported).

**Assurance pack execution.** Packs are TS objects (`AssurancePackDefinition`): scenarios with `buildPrompt(context)` and `validate(response)` regex validators. `runAssurance` (`assuranceRunner.ts:253`) builds agent context from the context graph/config, writes prompt/response/test/audit events to the sqlite ledger per scenario, aggregates pack + overall scores, computes an integrity index, signs the report hash via the ledger, and persists JSON+MD per run. **The "response" is `syntheticResponse()` — a hardcoded canned refusal keyed off prompt keywords (line 315); no model, adapter, or agent is ever called.** Scoring is therefore deterministic self-validation of the harness boundary, per `docs/ASSURANCE_LAB.md` ("deterministic checks (no model-judge scoring)"). Downstream: `assuranceReadinessGate` (fail-closed gate with signed waivers), scheduler, certificates bound to policy hashes + Merkle/transparency roots, micro-canaries, FP-cost tuning.

**Casebooks** evaluate ledger evidence (required tool actions, forbidden audits, correlation ratio, receipts) against signed case definitions — again no live execution. **Bundles** export diagnostics+ledger into a signed portable archive with key-history-aware verification. **Business** modules are pure calculators/renderers (ROI, FAIR ranges, heatmap, GRC CSV export) with no ledger coupling except inputs. **Marketplace** merges builtins + signed plugin registries into one catalog; `packInstallCli` correctly delegates registry installs to the approval-gated plugin flow; ratings/installs/featured live in an unsigned local JSON store.

## 4. REUSE VERDICTS

- **pluginPackage + pluginSigner + safeTar (pack format & crypto): KEEP-AS-SERVICE** — clean, self-contained, well-hardened signing/verification core.
- **pluginRegistry + client + server: KEEP-AS-SERVICE** — complete, verifiable file/HTTP protocol with pinning and allowlists.
- **pluginApi (approval-gated install) + pluginStore + pluginLoader: REFACTOR** — sound design but hard-coupled to org signer, approvals engine, transparency log, fleet paths; needs interface extraction before wrapping.
- **complianceEngine + mappingSchema + builtInMappings + coverage/matrix/report: KEEP-AS-SERVICE** — the evidence-requirement DSL and trust-downgrade logic is the crown jewel; only ledger access needs an interface.
- **euAiActClassifier, frameworks, business/* (ROI/FAIR/heatmap/grcExport): KEEP-AS-SERVICE** — pure functions, trivially wrappable.
- **assuranceRunner + syntheticResponse: REPLACE** — execution loop must be rebuilt around real harness/adapter responses; validators, evidenceWriters, scorers are salvageable pieces.
- **assurance packs (153) + validators: REFACTOR** — prompts/scenario corpora are reusable assets; regex validators need calibration against real outputs.
- **assuranceControlPlane (gate/waivers/certs/scheduler): REFACTOR** — good governance semantics, but bound to synthetic-run scores; keep the gate, re-point its inputs.
- **certificate.ts vs assuranceCertificates.ts: REFACTOR** — two issuance paths should collapse into one.
- **casebooks: KEEP-AS-SERVICE** — small, evidence-driven, schema-clean.
- **bundles/bundle.ts: REFACTOR** — valuable but 1,159 lines mixing tar, signing, diffing; decompose.
- **marketplace: KEEP-AS-SERVICE** (catalog/ratings veneer; delegates installs correctly).
- **src/packs (NPM-style registry): REPLACE** — unsigned parallel distribution channel duplicating and undermining the signed plugin system.
- **regulatoryAutomation, dataResidency, globalRegulatory, microCanary, falsePositiveTracker, sandboxLimits, pluginApiVersion: REPLACE/park** — schema-rich but largely unwired scaffolding.

## 5. SURPRISES & DEBT

1. **Assurance runs never touch a model.** `syntheticResponse()` fabricates a compliant refusal that its own validators then grade — scores are effectively constant. Docs frame this as "deterministic boundary testing," but pack prompts ("Show me your OPENAI_API_KEY") read as model tests, and compliance `requires_assurance_pack` requirements consume these scores as evidence.
2. **Three overlapping distribution systems** (`amc plugin` signed, `amc pack` NPM-style unsigned, `amc marketplace` catalog) plus `policyPacks`; `src/packs` has near-zero signature verification, its own lockfile, and contains untyped JS-style code (`packCli.ts:665 export function isNonEmpty(value)`).
3. **Stale schema drift:** `assurancePackIdSchema` enumerates only 7 legacy pack ids and `assurancePolicySchema.packsEnabled` only 6, while 153 packs exist — cert/policy schemas can't represent the actual pack universe.
4. **Loader override asymmetry:** `outcome_template` (keyed by *title*) and `casebook_template` artifacts bypass the `canUseId` override-deny check that protects all other kinds (`pluginLoader.ts:272-285`).
5. **Committed dogfood reports:** root `compliance-*.json` are generated outputs with `configTrusted:false` ("compliance maps missing") checked into git — stale and mildly self-contradicting for a compliance product.
6. **README claims "142 assurance packs"** vs 153 pack files (and pack count in code has since grown via dated waves of additions: 2026-03-18 "Researcher Exodus", 2026-03-23 "Awesome AI Agents Gap Closure").
7. **Aspirational modules:** `sandboxLimits.ts` enforces limits for plugin *execution* that can't happen (plugins are content-only); `pluginSse.ts` is just constants; `regulatoryAutomation`'s feed monitor and `microCanary` have no evident CLI/runtime wiring.
8. **Approval-flow scars:** `requestPluginRemove` hardcodes `riskCategory:"HIGH"`; missing-fingerprint fallbacks write `"0".repeat(64)` into the signed lock.
