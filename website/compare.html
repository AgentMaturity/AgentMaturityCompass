How to check an AI agent

Pick the proof that fits your decision.

A model benchmark, an agent tool, a model card, an audit report, an attack test, and a record of what an agent did at work each answer a different question. AMC covers one of them. It does not replace the others.

Reviewed 2026-07-10 Primary sources linked Unknowns stay unknown

Start with the question

Seven questions, seven kinds of proof

These approaches work together. Each card names the decision it helps most with and what it produces.

01

Build and operate an agent

Agent harness or SDK

Use a harness (the tool that runs an agent) for interactive work, scripted sessions, tools, model providers, and add-ons. Pi is one current example.

Evidence unit: session, event stream, or application behavior.

Source: SRC-PI
02

Compare model capabilities

Model and embedding benchmark

Use standard tasks, scenarios, and metrics to compare large models or embedding systems.

Evidence unit: benchmark run and task-level result.

Sources: SRC-HELM, SRC-MTEB
03

Measure agent task performance

Agent task benchmark

Use test environments to compare how agents reason, decide, and act on set tasks.

Evidence unit: benchmark trajectory and environment result.

Source: SRC-AGENTBENCH
04

Communicate model intent and limits

Model card

Use a standard document to state what a model is for, how it was tested, how well it did, and its known limits.

Evidence unit: versioned model documentation.

Source: SRC-MODEL-CARDS
05

Check a service company's controls

Organizational assurance report

Use an independent audit to learn about a company's controls for security, uptime, correct processing, confidentiality, or privacy.

Evidence unit: scoped assurance report.

Source: SRC-SOC2
06

Find how an attacker could make it fail

Expert testing and risk management

Use attack testing and expert review to find failures. Then feed what you find into ongoing risk management and monitoring.

Evidence unit: test finding, scenario, mitigation, and retest result.

Source: SRC-NIST
07

Oversee a running agent from records of what it did

AMC execution assurance

Use AMC to tie together, for one agent over its life, what it was seen doing, whether there are enough records, its score, rule checks, changes in its behavior, and signed records of each action (receipts).

Evidence unit: signed lifecycle artifacts and claim-readiness state.

Source: SRC-AMC

Honest product boundary

Use these approaches together

AMC covers one part of checking an agent. It should not push out the other parts.

Unchanged does not mean enough

A signed artifact proves integrity, not evidence sufficiency. It shows who signed it and that it has not changed, not that it is true or enough. AMC reports INSUFFICIENT_EVIDENCE when the accepted records cannot support a claim.

Mapping is not certification

AMC can link records to control or legal questions. AMC does not certify legal compliance.

Records of what an agent did have limits

AMC does not replace model benchmarks, model cards, organizational assurance reports, or expert adversarial testing.
