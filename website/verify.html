Check it yourself

Don't trust us. Check us.

Every AMC score comes in a bundle: one signed file that holds the score and the records behind it. Anyone can check a bundle offline. You need no account and no AMC server, only the sender's public key, which you get from them some other way than the bundle. You can try it now on a real bundle we made and published.

Check a real bundle in two minutes

1. Install AMC (free, open source). The current version is the source build; the Get AMC section has the commands. Check that it works:

amc --version

2. Download the sample bundle we published:

curl -fsSLO https://agentmaturity.co/verify/amc-sample-evidence.amcbundle

3. Save the sample's auditor public key. We publish it here, outside the bundle, because a key packed inside a bundle cannot vouch for that bundle. Its fingerprint (SHA-256 of the key file) is eb6f84cc395175206962b8054442619563ceca075ff38a746739cd6df2031945.

cat > amc-sample-auditor.pub <<'EOF'
-----BEGIN PUBLIC KEY-----
MCowBQYDK2VwAyEAiknpzbSC8obwQGVNQZXdMt3yFExL1xzvEoHCg2WA8+U=
-----END PUBLIC KEY-----
EOF

4. Check it. The command pins (names in advance) that key and the fingerprint of the sample's monitor key, the key that signs its log of records:

amc bundle verify amc-sample-evidence.amcbundle \
  --pubkey amc-sample-auditor.pub \
  --expect-monitor 93a2ad7bebb2e8b93a0de857710f9c39205f3dd29e23c8557291a0c4a470610f

The first line should be this, and the exit code 0:

Bundle verification PASSED

The lines after it describe the sample: a first run on a new workspace, self-reported, with no accepted records yet.

Without the two pins, the same command prints Bundle verification FAILED, lists each signing key as not-pinned with its fingerprint, and exits 1. Anyone can sign a fake bundle with a new key and put that key inside it. So AMC trusts only keys you got from outside the bundle. With --allow-unpinned --allow-unanchored it only checks that nothing changed: exit code 2 and an UNTRUSTED: line, never a pass.

AMC checks the bundle's signatures, the chain of fingerprints that links its records, and its list of contents, all offline. If one byte changed after signing, the check fails. Try it: change one character anywhere in the file and run the command again; the check fails.

To check the download itself, here is the sample's SHA-256:

b5860614cf52ef621693e41241c0c608c455538431263ac58aa1e18bb6029441

What this shows, and what it does not

  • It shows who signed it and that nothing changed. The bundle you checked is exactly what was signed. Nobody edited the score, the records, or the times afterward. A signature does not show that the records are true.
  • It does not show the agent is good. A signed bundle of weak records is still weak. So AMC reports whether there are enough records separately from the signature check. A score can back a claim only when that report says READY. The published sample is a first run on a new workspace: valid and signed, and it says it holds no accepted records yet.

Check anyone's agent the same way

When a vendor, contractor, or teammate sends you an AMC bundle, ask for their auditor public key and monitor key fingerprint. They got these when they set up AMC. Get them some other way than the bundle: their website, your contract, or a signed trust list. Then run the same commands. You need only those two keys, not their systems:

amc bundle verify their-agent-evidence.amcbundle \
  --pubkey their-auditor.pub \
  --expect-monitor <their monitor key sha256>
amc bundle inspect their-agent-evidence.amcbundle

To pin keys for many senders at once, use a signed trust list (--trust-list and --trust-root); see the trust-list guide.

Check our releases too

You can check the installer too. It downloads one fixed GitHub Release, checks every archive against the published SHA256SUMS, and refuses anything that does not match.
