Minor changes

  • Publish strict, auditor-signed adapter capability receipts that separate declared and effective events/controls, runtime-version proof, hook state, and explicit lossiness. Legacy plugin metadata now fails closed, and the older adapter comparison API derives from the authoritative registry instead of a duplicate capability table.
  • Add fail-closed approval activity search to the existing approvals list command, authenticated API route, and Studio page. The shared read-only projection audits every signed approval artifact before applying privacy-safe filters and adds no activity database, index, daemon, raw-content search, or proof claim.
  • Add a capability-gated provider hook steer outcome for trusted ToolHub argument rejections. Claude blocks the current call with bounded corrective context and a signed effective-steer receipt; unsupported providers fail closed to deny without false steer claims. Preserve provider wire decisions, reject input rewrites and conflicting replays, expose the outcome in Watch lifecycle evidence, and keep version-1 control receipts verifiable.
  • Add fail-closed compound-command blast-radius review to existing provider hook control. AMC evaluates every bounded shell segment through existing signed controls, applies the most restrictive outcome, and seals only privacy-safe step metadata without retaining the raw command or arguments.
  • Add read-only, evaluator-backed control simulation for Runtime Firewall, Action Policy, and Approval Policy controls. Expose exact matched rules and structured conditions through amc policy simulate <controlId> [--json] and POST /api/v1/policy/simulate without persisting input or generating proof receipts; fail closed on missing, malformed, unsigned, or tampered control state.
  • Capture provider-native requested, completed, and failed tool hooks under one stable action ID. Add ambiguity-safe Gemini terminal correlation, signed multi-handler manifests with v1 migration, receipt-verified lifecycle inspection through CLI and Watch API, and fail-closed checks for missing, duplicate, conflicting, cross-agent, out-of-order, or tampered evidence without retaining raw tool input, output, or error content.
  • Add read-only provider hook health through CLI, Watch API, and on-demand Studio. The projection distinguishes not installed, awaiting first verified event, observed, and fail-closed integrity states without a heartbeat, daemon, second event store, raw provider content, or current-liveness claim. Unconfigured Integration Hub status now renders an empty setup state instead of HTTP 500 and keeps dispatch disabled until signed configuration exists.
  • Add fail-closed signed ToolHub context for native and MCP tools. Existing v1 configs remain compatible, while CLI, API, Studio, and CGX now share deterministic tool/server identities and explicit non-proof boundaries without an MCP registry or discovery service.
  • Add bounded nested Action Policy evidence logic with fail-closed runtime evaluation, blocker-only remediation, legacy-ID compatibility, deterministic preview, recoverable exact-confirm signed apply, CLI/API/Studio parity, and audit evidence.
  • Add a read-only, outcome-based first-run activation projection shared by amc connect --status, Studio, the Console, and OpenAPI. Distinguish signed connection readiness from verified runtime completion, expose bounded evidence references, and fail closed on metadata-only, cross-agent, missing-receipt, malformed, or tampered evidence without creating traffic or a second event store. Keep activation refresh live by excluding API GETs from the Console offline cache and delivering versioned static assets network-first with offline fallback.
  • Add deterministic, read-only policy regression suites through amc policy test <file> [--json]. Suites reuse AMC's production control simulator, fail closed on untrusted policy state, exclude raw inputs and paths, remain ineligible as runtime or maturity evidence, and run as a built-distribution CI gate with an uploadable report.
  • Unify CLI, Dashboard, diagnostics, and Studio on the canonical signed approval quorum chain. Deliver privacy-safe approval lifecycle notifications through the existing Vault-backed integration queue, bind queued rows with auditor signatures, resume retries after restart, and report pending attempts as QUEUED. Add workspace-aware authenticated review paths, explicit CLI reviewer identity, real EXPIRED and CONSUMED delivery, strict hosted RBAC/logout, SSE refresh, the actual approval API contract, terminal replay protection, and redacted persisted delivery evidence.
  • Add explicit loopback-only amc connect hooks install --mode control support for Claude Code and Gemini CLI. Reuse signed ToolHub, Action Policy, Approval Policy, budget, freeze, maturity, and assurance primitives; return capability-honest provider-native allow, deny, or ask responses; bind exact response bytes to signed ledger receipts; reject conflicting replays; and preserve observation as the default reversible mode.
  • Add a lease-scoped provider-neutral hook ingress for an AMC-owned observed subset of AEP 0.1 action events. Bind raw request digests into encrypted, redacted ledger projections and signed receipts; transactionally enforce signed request budgets; hash free-text errors; authenticate the retry target, verify its hash-chain commitment and every prefix writer signature, require signed archive and pruning proof when payload retention has expired, and recover original receipts for byte-identical retries; reject malformed, stale, future, oversized, unauthorized, rate-limited, conflicting, and tampered events; expose accepted evidence through existing Watch timelines; and publish the exact draft pin, strict-Ajv lifecycle rules, shared receipt schema, and explicit non-conformance boundary in OpenAPI and product documentation.
  • Add four reusable action-class scope templates that compile selected rules from existing built-in Policy Packs into the existing signed Action and Approval Policy schemas. Preview is deterministic and read-only; apply is exact-confirmed, locked, transactional, post-verified, and bound to existing transparency and ledger evidence without adding another policy language or template store.
  • Add reversible amc connect hooks install/status/remove setup for primary-source-pinned Claude Code and Gemini CLI project hooks. Preserve unrelated provider settings, add a managed .gitignore block for local hook credentials, keep a dedicated least-privilege observation lease out of provider config with mode 0600, sign the ownership manifest, detect drift and tampering, refuse duplicate-key JSON, symlink escape, unsupported providers, and remote plaintext delivery, and forward only privacy-minimal action.requested events to the existing signed Watch receipt path.
  • Make Enforce resource version activation and rollback fail closed. Add one signed active/previous/rollback status projection across CLI, API, Studio, and OpenAPI; canonical signed selectors; strict manifest identity and digest validation; per-agent lifecycle locking; staged snapshots; exact remote confirmation; transactional rollback recovery; post-write verification; signed success receipts; bounded relative-path responses; and an activate alias without adding another control store.
  • Add a deterministic, domain-separated signed metadata catalog for existing AMC deterministic metrics, LLM judges, and assurance packs. The read-only status command fails closed on drift, tamper, malformed manifests, and unverified runtime custom metrics; only an explicit refresh writes the derived snapshot.
  • Persist Guardrails and Runtime Firewall policy intent in signed immutable journals backed by separate host-local checkpoints, authenticated pending-publication recovery, and genesis signer pins, with domain-separated compatibility signatures and an OWNER-approved semantic legacy-policy migration receipt. Expose requested, committed, effective, and mirror status separately across CLI, API, Dashboard, and Console; serialize concurrent writers; fail closed on unexplained tails; bind supported controls additively to Runtime Firewall; require a same-origin Dashboard owner capability for mutations; and reject tampering, local rollback, workspace key-history replacement, stale status, malformed policy input, or unreviewed legacy signatures.
  • Bind Runtime Firewall candidate and actual actions to signed decision artifacts and expose fail-closed observe-only rollout counters through the existing CLI and API status surfaces.
  • Add one read-only verified control projection across the existing Runtime Firewall, Guardrails, Action Policy, and Approval Policy owners. Expose the same Scope, When, Then, and Status contract through amc policy controls [--json] and GET /api/v1/policy/controls; disclose catalog-only guardrails, keep all source paths relative, and project invalid Runtime or Guardrails evidence to block, invalid Action Policy to simulate, and invalid Approval Policy to deny without creating another evaluator, store, or policy language.
  • Fail closed when live-drift evidence references, provider-drift canary evidence, or provider-drift waivers are blank or malformed; publish public methodology 2026.07.29-r223 so the public and diagnostic OpenAI Simple Evals assurance hashes align while supported 2026.07.10-r222 and 2026.07.10-r221 question-set variants remain historically verifiable; and expose the existing OpenCompass live-drift primitive through the package root.
  • Fix a class of defects where commands reported success and stored nothing, and where scores were computed from evidence that could not apply.
