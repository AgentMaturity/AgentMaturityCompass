# ADR 010: MCP client for the 2026-07-28 specification

Status: implemented source candidate (P1-39); execution qualification is separate.
Date: 2026-10-07. Spec: <https://modelcontextprotocol.io/specification/2026-07-28>, pages read on 2026-10-07. Section names below are that revision's; re-read them before a release.

## Problem

AMC's native MCP client spoke only the initialize-handshake protocol (2025-11-25 and earlier) through the installed `@modelcontextprotocol/sdk` 1.32.1, whose `LATEST_PROTOCOL_VERSION` is `2025-11-25`. The 2026-07-28 revision removes sessions and the handshake, and HTTP servers that require OAuth were refused outright. No released SDK implements 2026-07-28, so AMC implements the client protocol itself and keeps the SDK only for JSON-RPC framing and the legacy handshake.

## Decision

- **Era negotiation.** A config may pin `protocolVersion`. With `2026-07-28` pinned, or with no pin, AMC sends `server/discover` first. A `DiscoverResult` that lists `2026-07-28` selects the stateless mode; a recognized modern error (`-32020`, `-32021`, `-32022`) or a `DiscoverResult` without `2026-07-28` is refused; anything else (another error, a result without `supportedVersions`, a stdio timeout, an HTTP 400/404/405 without a modern JSON-RPC error, or a broken probe stream) marks a legacy server, and AMC then sends `initialize` on the same connection, unless a version is pinned. A pinned legacy version is requested in `initialize` and any other answer is refused.
- **The negotiated version is reviewed.** The catalog digest is SHA-256 over the negotiated version and the tools, so an era change or a downgrade forced by an attacker who breaks the probe changes the digest and the mount is refused. Every existing pinned digest changes once and needs fresh review.
- **Receipt.** `discoverNativeMcpCatalog` returns `protocol: { negotiatedVersion, mode, serverInfo }`; `mountNativeMcpServer` returns `receipt: { serverId, catalogDigest, protocol, auth }` with `auth: { issuer, scopes, tokenExpiresAt }` and never a token. `serverInfo` is self-reported by the server and is never used for a decision.
- **Governance is unchanged.** Origin pinning, redirect refusal, header and size bounds, the per-call catalog re-read against the pinned digest, signed grants and approvals apply in both eras. The legacy path keeps its session pin and its bounded `Last-Event-ID` recovery.
- **No blind replay.** On a broken 2026-07-28 response stream AMC re-issues `server/discover` and `tools/list` once with a new request id (the transport also treats `resources/read` and `prompts/get` as idempotent; AMC sends neither today). It never re-issues `tools/call`: the call fails with `TOOL_OUTCOME_UNKNOWN`, the mount is disposed and the tool evidence row says the remote tool may have executed and was not replayed. The spec's "MUST re-issue" (Changelog, major change 9) is deliberately not applied to `tools/call`, because a remote side effect may already have happened; the operator decides.
- **OAuth.** HTTP servers may set `auth: { kind: "oauth2", clientId?, clientIdMetadataUrl?, allowDynamicRegistration?, scopes?, redirectPort? }`, exclusive with `headerRefs` and pinned by the config digest. Interactive authorization runs only from `amc agent-loop mcp-catalog --config <file> --authorize`, which prints the authorization URL and never opens a browser. Other runs use the stored grant (refreshing it when due) or fail with `AUTH_REQUIRED` and that command. The access token is placed in the transport's private header snapshot for the mount and is never refreshed mid-mount.

## Client requirements

"Implemented" names the code; "Not implemented" is a deliberate exception.

| Clients MAY call `server/discover`; stdio dual-era clients SHOULD probe it first (Versioning §Backward Compatibility; stdio §Backward Compatibility; Discovery) | Implemented for stdio and HTTP: `negotiate` in `nativeMcpClient.ts` |
| Fallback MUST NOT be keyed to one error code; a recognized modern error means retry, not fall back (stdio §Backward Compatibility) | Implemented: `classifyNativeMcpDiscover`. AMC speaks one modern version, so a modern error is a refusal rather than a retry |

| Sampling, Roots and Logging are deprecated (Changelog §Deprecated) | Not used: AMC declares none of them and never sets a log level; in the legacy era the SDK answers server requests for them with method-not-found |

| `ttlMs` and `cacheScope` caching hints (Caching) | Not used: AMC never serves a cached catalog |

The first listed authorization server is used |
| Try RFC 8414 and OpenID discovery URLs in the listed order; the document `issuer` MUST equal the issuer used to build the URL (Authorization Server Discovery §Authorization Server Metadata Discovery) | Implemented: `discoverNativeMcpAuthorizationServer` |
| PKCE with S256; refuse when `code_challenge_methods_supported` is absent (Security Considerations §Authorization Code Protection) | Implemented: the S256 check in `discoverNativeMcpAuthorizationServer`; verifier and challenge in `authorizeNativeMcpOAuth` |
| `resource` (RFC 8707) in authorization and token requests (Authorization §Resource Parameter Implementation) | Implemented: authorization, code exchange and refresh requests |
| Record the issuer with the verifier; validate `iss` per the RFC 9207 table; on mismatch never show `error` text (Authorization §Authorization Response Validation) | Implemented: `validateNativeMcpAuthorizationResponse`; no server error text is shown in any case |
| Use and verify `state` (Security Considerations §Open Redirection) | Implemented |
| Redirect URIs are localhost or HTTPS; authorization-server endpoints are HTTPS (Security Considerations §Communication Security) | Implemented: the redirect is `http://127.0.0.1:{port}/callback`; endpoints must be HTTPS, with literal loopback HTTP only beside a loopback development MCP endpoint |
| Registration priority: pre-registered, Client ID Metadata Documents, then dynamic registration (Client Registration) | Implemented: `clientIdFor`. Dynamic registration is used only when `allowDynamicRegistration` is true, sends `application_type: "native"`, and refuses a confidential client |

| Tokens only in the `Authorization` header, never in a query, and only to the server whose authorization server issued them (Authorization §Access Token Usage) | Implemented: the token joins the pinned endpoint's private header snapshot and the redaction set |

| Refresh tokens: keep them confidential; do not assume one is issued (Authorization §Refresh Tokens) | Implemented: stored in the AMC credential store; rotated when the server issues a new one |
| Client ID Metadata Documents SHOULD be supported (Authorization §Overview) | Implemented as an operator-hosted URL (`clientIdMetadataUrl`); AMC does not host the document |

## Consequences

- Operators re-run `amc agent-loop mcp-catalog` once to re-pin digests.
- A 2026-07-28 server whose tool schemas or results fall outside the installed SDK's validators (for example a non-object `structuredContent`) is refused rather than accepted unchecked.
- Executable tests on local fixtures (stateless, legacy and OAuth servers) and the two mutation checks named in P1-39 are paused under the current coding-only order and remain owed before release.
