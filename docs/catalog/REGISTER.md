# Register entry format (law as data)

Status: format v1 (P1-18), experimental content. Code: `src/catalog/register.ts`. JSON Schema:
`spec/schemas/v1/register-entry.schema.json` (generated by `npm run gen:schemas`). First register:
`catalog/registers/us.json`; the Wealth overlay and its US register are described in [WEALTH_US.md](WEALTH_US.md).

A register encodes one jurisdiction's law, clause by clause, as dated, sourced and hashed data. Each entry names the S5
register entry (`src/compliance/regulatory/register.json`) it belongs to, so the instrument's status and official
sources stay in one place, and controls cite entries by id. The format is jurisdiction-neutral: the EU register (P2-11),
later jurisdictions and watch lists (P3-09 to P3-12) and A4 Adapt (P3-23) reuse it. An entry is agent-drafted and
unreviewed until a named legal reviewer fills `legalReviewer`; nothing in a register is legal advice or a compliance
claim.

## Register file

`catalog/registers/<id>.json`; the file name is the register id. `loadCatalog` parses it with `registerFileSchema`
(strict: an unknown key fails), and `validateCatalog` adds the cross rules below.

| Field | Rule |
| --- | --- |
| `registerVersion` | `1`. A breaking change to the entry format becomes version 2. |
| `id`, `title`, `jurisdiction` | Register id (a term), a title, and the jurisdiction it covers. |
| `policy.litigationRules` | `[{ jurisdictionPrefix, s5RegisterId, reason }]`: an entry whose jurisdiction starts with the prefix carries `flags.litigationExposed: true` unless a legal reviewer cleared it. The US register sets `US-` with S5 `us-eo-14365`. |
| `entries` | At least one `RegisterEntry`. |

## RegisterEntry

| Field | Rule |
| --- | --- |
| `id` | A term, unique in the register. Controls cite an entry by using its id as the citation `key`. |
| `row` | The strategy register row the entry encodes. |
| `stations` | At least one of the seven stations, no duplicates; the S5 entry's stations must include them. |
| `meaning`, `keyDatesText`, `statusText` | The strategy's cells for the row, as text. |
| `scope` | Optional: who the clause binds, e.g. "Non-bank financial firms". |
| `clock` | Optional `{ duration, trigger?, threshold?, clockId? }`; a `clockId` must exist in the F4 table (`src/incidents/regulatoryClocksTable.ts`). |
| `citation.instrument`, `clause`, `edition` | The instrument, the clause in it, and the edition the url serves. |
| `citation.jurisdiction` | A `catalog/vocabulary.yaml` jurisdiction term: `US`, `US-NY`, `EU`, ... |
| `citation.statusType` | One of the seven P0-25 status types: `binding-now`, `binding-future`, `draft`, `supervisory-guidance`, `voluntary-standard`, `contractual`, `conformity-scheme`. |
| `citation.effectiveDate`, `complianceDueDate` | A real date as `YYYY-MM-DD`, or `YYYY-MM` / `YYYY` when the source gives no day; `null` when no source states it. The due date is never before the effective date. |
| `citation.dateQualifier` | Optional `"about"`, only with a date. |
| `citation.url` | https. |
| `citation.contentHash`, `retrievedAt` | `sha256:` plus 64 hex of the bytes fetched on `retrievedAt` (YYYY-MM-DD, never after the check date). A hash needs its `retrievedAt`. |
| `citation.legalReviewer` | `{ name, credential, reviewedAt }` or `null`. Only a named person fills it. |
| `dateNotes` | Required when a date is `null`: why. |
| `sourceKind` | `official` exactly when the url host is on S5's `policy.officialHosts`, else `secondary`. A secondary entry carries no legal reviewer. |
| `sourceNote` | Required when `contentHash` is `null`: why the entry is unverified, and what was read, if anything. |
| `flags` | `reverify` (a fact to re-check before publishing), `litigationExposed`, `litigationCleared` (a legal reviewer's rationale; needs `legalReviewer`), `applicationUncertain`, `pending` (draft instruments only). |
| `s5RegisterId` | An S5 register entry id. |

An entry is **verified** when it carries a `contentHash`: the bytes were fetched and hashed, and the clause was read
from them. Every other entry is **unverified**, with its reason in `sourceNote`. Verified is a statement about the
source, not a legal review.

## Issue codes

| Code | Meaning |
| --- | --- |
| `CAT_SCHEMA` | Shape: unknown key, empty stations, invalid date, due before effective, unknown status type, null date without `dateNotes`. |
| `CAT_REGISTER_SOURCE` | A hash without `retrievedAt`, or no hash and no `sourceNote`. |
| `CAT_REGISTER_HOST` | `sourceKind` disagrees with the host, a secondary entry names a legal reviewer, or the url is not https. |
| `CAT_REGISTER_S5` | The S5 entry (or a litigation rule's S5 entry) does not exist. |
| `CAT_REGISTER_STATIONS` | The S5 entry lacks one of the entry's stations. |
| `CAT_REGISTER_LITIGATION` | A litigation rule's entry lacks the flag, a profile hides it, or a non-reviewer cleared it. |
| `CAT_REGISTER_RETRIEVAL` | `retrievedAt` is after the check date. |
| `CAT_REGISTER_ENTRY` | A jurisdiction profile names an entry no register holds. |
| `CAT_CITATION_REGISTER_MISMATCH` | A control citation whose key is an entry id differs from the entry in S5 id, url, status type, jurisdiction, retrieval or legal review. |
| `CAT_SUPPORT_GATE` | A control citing an entry that awaits a legal reviewer reports an approved review. |

`CAT_DUPLICATE_ID`, `CAT_VOCAB` and `CAT_CLOCK_UNKNOWN` keep their control-record meanings.

## Status review

`statusReviewDue(entries, asOf)` lists the entries whose stated status should have changed by `asOf`: a `binding-future`
entry whose compliance date (or, without one, its effective date) has arrived. P1-34's currency review works the list;
nothing changes an entry's status by itself.

## Jurisdiction profiles

`catalog/jurisdictions/<folder>/profiles.json` is a list of `{ id, name, registerEntryIds, otherInstruments,
litigationExposed }`. `otherInstruments` are `{ name, s5RegisterId, ownerKey }`: instruments another plan issue owns,
with `s5RegisterId: null` where the S5 register has no entry yet. Every listed entry id must exist in a register, and a
profile that lists a litigation-exposed entry is itself litigation-exposed.

## Digests

The catalog digest covers each register and each jurisdiction profile file, so a register edit changes the catalog
lock of every compiled plan, as an S5 register edit already does.
