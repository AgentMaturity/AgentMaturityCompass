# Ops Hardening

AMC ships a signed operations policy that controls retention, encryption-at-rest, backups, and maintenance.

## Policy
- File: `.amc/ops-policy.yaml`
- Signature: `.amc/ops-policy.yaml.sig`
- Commands:
  - `amc ops init`
  - `amc ops verify`
  - `amc ops print`

If the ops policy signature is invalid, retention/backup/maintenance flows fail closed and Studio `/readyz` returns `503`.

## Retention Model
- Commands:
  - `amc retention status`
  - `amc retention run --dry-run`
  - `amc retention run`
  - `amc retention verify`
- AMC never deletes ledger rows. It archives event payload history into signed segments and prunes payload fields with tombstones.
- Hash-chain integrity remains verifiable after archival/prune.

## Archive Segments
- Path: `.amc/archive/ledger/`
- Each segment has:
  - `segment_*.jsonl.gz`
  - `segment_*.manifest.json`
  - `segment_*.manifest.sig`
- `amc retention verify` checks segment signatures, segment hashes, and chain continuity.

## Why Rows Aren’t Deleted
- Evidence rows are hash-chained and signed.
- Deleting rows would break deterministic continuity and invalidate anti-tamper guarantees.
- AMC prunes payload columns only, while preserving event hashes and verification metadata.

## Residency routing (P2-01 source slice)

The residency gate is implemented in `src/residency/checkEgress.ts`. Its destination declarations live in `.amc/residency/destinations.yaml`, with an auditor signature in `destinations.yaml.sig`. The verifier parses the same bounded byte snapshot whose SHA-256 and signature it verifies. A registry edit requires a new signature. No registry is created automatically and no jurisdiction is inferred from DNS, IP addresses, a URL, or a filesystem path.

An active, verified compiled control plan makes a workspace regulated. The signed registry identifies the deployment profile used to compile that plan. AMC parses and normalizes the profile, then compares its canonical digest with the profile digest inside the verified plan. Data classes and source jurisdictions come from that profile's facts; network tools can additionally carry trusted authorization-record resource classes. Missing or unknown facts are evaluated conservatively. Model arguments and webhook payloads cannot choose their own data classification or policy workspace.

For protected traffic, an unavailable or invalid registry/profile, an ambiguous or unregistered destination, an unknown destination region, or a disallowed region blocks the request. Every applicable rule must be satisfied. A declared transfer basis can satisfy only rules that explicitly accept it; this metadata records an operator declaration, not a legal opinion or proof of the processor's physical location. A regulated registry without rules is refused. An unregulated workspace without a registry preserves the legacy path and returns `no_rule`; that is not a successful residency assessment.

The released wiring covers LLM runtime dispatch (including a supplied transport), native MCP HTTP requests and termination, the bridge's gateway hop, asynchronous callbacks, and the network-tool pipeline guard after the host allowlist. Automatic redirects are refused or returned without following them. Both final gateway HTTP routes recheck their trusted workspace before every attempt; a residency refusal is terminal, returns HTTP 403 with `AMC_RESIDENCY_EGRESS_BLOCKED`, and does not charge the upstream circuit breaker. Direct ToolHub HTTP dispatch and the shared native HTTP executor also check before creating a socket, using workspace values supplied by their callers. These preflight refusals use the existing definite-failure contract; a subsequent network failure retains its existing uncertainty.

Gateway CONNECT validates authority form, preserving the host-only default of port 443 and accepting bracketed IPv6. Malformed authorities, user information, paths and query carriers are refused. After lease and DNS/allowlist admission, the final synchronous residency check uses the captured workspace and verified agent before opening a socket. A typed refusal returns fixed HTTP 403 and `AMC_RESIDENCY_EGRESS_BLOCKED`. The opaque payload has unknown classes; its canonical authority/root locator matches only host-wide or root-path registry declarations. It proves no TLS, HTTP path, payload classification or physical region. Header lease carriers remain supported.

Native `web_fetch` and every `web_search` GET carry captured execution workspace/agent and authorization-record resource classes and purpose into their shared transport. The transport snapshots context and policy before DNS, then synchronously checks residency immediately before its pinned socket. DNS pinning, fixed headers, response caps and redirect refusal remain. A typed residency refusal records a native denial and propagates unchanged; a later search refusal can follow an earlier completed GET, so it does not establish no effect for the entire search. Legacy direct-helper calls retain the scoped fallback limits. This gate does not independently establish payload classification or physical destination region.

Assurance/red-team responder transport captures explicit workspace, caller attribution and environment endpoint before probing. It prepares each POST, then checks the same endpoint immediately before the injected fetch, using `provider` for direct requests and `bridge` for gateway traffic. The gateway probe checks and fetches the same full endpoint later used for POST, preserving restrictive path-prefix registrations without widening them to `/`. Typed refusal escapes both catches and cannot trigger direct-provider fallback; ordinary availability errors retain that fallback. Redirects return without following, and a 3xx is an already-dispatched response rather than a no-send policy denial. Prompts/probes have unknown resource classes and purpose, while the verified residency profile supplies jurisdiction facts. Parsed agent/gateway configs alone do not verify signatures. Injected fetch must honor the checked URL and redirect mode; DNS is not pinned, response bodies remain uncapped and the legacy timeout ends after headers. No scan or evaluation was run for this source change.

The `shield red-team` CLI evaluator rethrows typed residency refusals; its local error-event listener forwards the original error through ContinuousRedTeam's reporting catch to the existing outer handler. A blocked invocation cannot become a defended-attack statistic or a green success summary. The pre-existing handling of other invocation failures in ContinuousRedTeam remains separate debt; no scan was run. A GET on the full gateway route can produce an unauthenticated entry in gateway logs. A dedicated health route, if needed later, must be registered separately rather than checked under another endpoint's permission.

Industry Packs online activation captures its explicit or asynchronous workspace scope separately from the local persistence fallback, along with its key, expiry fallback, verification endpoint and injected fetch. The prepared POST checks `network-tool` residency immediately before sending to that same endpoint and rejects redirects with a clear endpoint error before parsing their body. Unknown scope remains unknown to the gate; an active or unverifiable regulated cwd cannot be promoted into explicit authority. License payload classes and purpose are unknown, and no public-service exemption is assumed. Typed refusal propagates without writing an entitlement. The locally valid license shortcut still makes no request, and license verification and the undecided commercial model are unchanged. Injected fetch behavior, unpinned DNS, response parsing/caps, post-dispatch persistence failure and environment changes during final entitlement evaluation remain separate limits.

Storage admission runs before `SessionService.open` starts a regulated session. The storage URL names an operator-declared destination and does not prove where a local disk, injected store, or remote backend actually resides.

A blocked request emits `RESIDENCY_ROUTE_BLOCKED`, carries a typed `EgressBlocked` decision, and records the affected control result as `not_evaluated`. A route decision never produces a legal approval or maturity pass. Experimental legal-rule content, named expert review, processor contracts, and validation of actual deployment regions remain separate work. This slice adds no approved legal rules.

## Workspace-scoped guard evidence

`emitGuardEvent` accepts `workspace`; otherwise it uses the workspace held by `withWorkspaceScope(workspace, fn)` through `AsyncLocalStorage`. Explicit and scoped calls select that workspace's `.amc/guard_events.sqlite` (or its existing CUTOVER evidence store), irrespective of a process-global database override. Receipts propagate their signing workspace to the event writer. Read and chain-verification APIs also accept a workspace. Retention passes its own workspace to `pruneGuardEvents(workspace, beforeIso)`.

The unscoped compatibility path is available only outside a regulated profile and labels event metadata with `workspaceResolution: "cwd-fallback"`. It preserves the legacy database environment override there. An unscoped regulated or unverifiable profile cannot write or prune another workspace through this fallback. The emitter's existing best-effort, never-throw contract remains: a missing scope can therefore lose an event rather than misfile it. Hosts must provide explicit workspace values or install the asynchronous scope at their entrypoints.

The DUAL_WRITE and CUTOVER stages keep their existing behavior; this change selects the workspace, not the rollout stage. The complete asynchronous tool pipeline carries its trusted workspace through approvals, guards, bodies, recording and nested Code Mode calls. Native session composition and every later prompt install the session's captured workspace scope; its lifetime callbacks also use that scope. Native HTTP MCP discovery and mounting pass their trusted workspace directly to the transport.

CLI `score collect-evidence` and `score operational-independence` scope their guard reads to the current workspace. Their command paths and output contracts are unchanged. Other CLI assessment paths, legacy Studio entrypoints, and external callers of the scoring APIs still need explicit workspace/scope integration before complete multi-workspace coverage can be claimed.

Drift-alert delivery captures workspace and agent attribution before its sequential channel loop. Each prepared webhook request checks callback residency immediately before native HTTP dispatch; resource classes and purpose remain unknown. Typed refusal rejects that channel without opening its request. An earlier channel may already have completed, and some monitor callers suppress or stringify failures, so neither whole-operation no-effect nor successful delivery is implied. Native HTTP still follows no redirects. DNS pinning, timeouts, response handling and an atomic verified config snapshot are not added by this source slice.

Benchmark registry index and artifact GETs carry captured operation scope into their private readers and check network-tool residency immediately before each prepared manual-redirect request. API and CLI browsing install their trusted workspace scope; import snapshots its explicit workspace and reference for later cache and persistence work. Local file reads stay local. Empty request bodies do not justify an exemption. Concurrent index requests or an earlier index retrieval can precede a later denial, so no whole-operation no-effect claim is made. Browse verifies integrity with a registry-supplied key; import additionally retains pinned admission. Global trust/environment timing, DNS pinning, timeout/body caps and existing cache/temp-file behavior remain outside this slice.

Queued webhook delivery captures workspace scope and immutable request inputs before waits. Prepared native POSTs check callback residency immediately before request construction, and each supplied-client attempt is admitted before invoking the captured method. The queue installs its trusted workspace scope; typed denial bypasses retry and queue-round accounting and leaves the head pending. Later drains retry that head, while ordered followers wait. ALS carries workspace only, so audit actor stays system/unknown and classes/purpose stay unknown. Ordinary HMAC, header precedence, backoff and socket timeout behavior remain. Native HTTP follows no redirects; supplied clients are trusted to honor the checked endpoint and may conceal secondary hops. Earlier attempts, earlier completed rows or a callback failure after a 2xx can already have effects, and typed refusal can discard the current partial receipt. Durable blocked status/backoff, actor propagation, complete partial accounting, DNS pinning and response caps remain separate work.

## Legal-hold registry and deletion admission

Holds live under `.amc/residency/legal-holds/`. Each record and `HEAD.json` carries a domain-separated `legal-hold` artifact signature through the existing BUNDLE signing policy. HEAD binds the physical workspace path, verified tenant/workspace identity pair, total record count and digest of every modern and legacy record. Profile revisions do not change that identity pair. The loader verifies bounded snapshots before parsing and never skips a hold. Tenant mapping comes from the active plan's pinned deployment profile, or a strictly verified legacy tenant boundary. Active holds with missing or mismatched mapping are unknown.

The register has three outcomes: `clear`, `held`, and `unknown`. A missing HEAD is unknown in a regulated workspace. Outside regulated profiles, a headless register can be considered only when its journal is uninitialized and legacy rows are authenticated or explicitly acknowledged; a clear result emits a warning. Modern records without HEAD, invalid modern signatures, count/digest mismatches and incomplete publication always refuse admission. HEAD must match the existing `legal-hold-head` signed control journal, whose signer pin and latest checkpoint live outside the workspace. Pending publication is not recovered during admission. Restoring an older HEAD or replacing the local auditor key cannot silently narrow an anchored register.

Owner-only issue/release operations are synchronous and share a file lock with deletion effects. Publication prepares and verifies signatures for the exact record and HEAD buffers before committing the journal; it then writes the record, record signature, HEAD and HEAD signature. The next HEAD comes from verified prior descriptors plus the new row, never an unchecked directory reread. Signing, signature-verification and normal journal pin failures leave registry artifacts unchanged. No-sign mode refuses registry writes. Local I/O or power loss can still interrupt the subsequent per-file publication and deny deletion; the files and journal are not one filesystem transaction. Releasing a verifiable legacy hold writes a signed inactive override bound to its original bytes. Bounded corrupt or unreconstructible legacy envelopes remain counted by raw SHA-256 as unverified descriptors; they block admission until an owner explicitly accepts a signed release-only override for that exact ID and digest. Original legacy bytes are never discarded or resealed, and untrusted fields never become verified hold DTOs.

The existing `legal-hold` command adds `--init`, `--init --rebind`, and `--release <id> --accept-unverified-legacy`. First regulated use and adoption of an older unanchored HEAD require explicit initialization. Rebinding verifies signatures, timestamps, count and digest before allowing only a path change, the same tenant/workspace pair, or a null-to-known pair. Initialization, rebind and legacy acknowledgement require acknowledged audit before publication. Only locked owner initialization may recover an authenticated pending journal publication; admission, listing, issue and release do not perform recovery. If complete verified disk rows match the trusted journal's count and digest and its identity is compatible, owner initialization can acknowledge `LEGAL_HOLD_REGISTRY_HEAD_REPUBLISHED` and republish HEAD from that authority without appending a new journal revision. It never advances the journal to match HEAD. A committed journal with an incomplete record pair remains unknown because the journal stores no record bytes. Initialization invents no hold and reports unresolved legacy IDs and raw SHA-256 digests as still blocking deletion. A changed tenant/workspace pair or a second-tenant mapping remains unknown. A moved register with inaccessible existing checkpoints remains unknown; explicit bootstrap of an old unanchored HEAD does not recover a checkpoint. Journal signer rotation is a separate shared-journal gap.

Listing is a verified view rather than admission. Known holds remain listable without a tenant mapping; `holdVerdict` still returns unknown for deletion in that state. Explicit-workspace compatibility reads reject unresolved legacy descriptors so they cannot report an unverified register as having no active holds. Unscoped in-memory compatibility remains separate, and the repair adapter propagates all three admission outcomes.

`withDeletionGate` keeps the shared writer lock through the actual synchronous effect and rechecks nested scopes. It acknowledges `DELETION_ALLOWED` before invoking a delete. Held and unknown state produce `DELETION_DENIED_HELD` or `DELETION_DENIED_HOLD_UNKNOWN`; audit failure never permits an effect. Retention and spill targets use complete SHA-256 session hashes without truncation or a 1,024-target limit. Malformed targets emit a sanitized unknown-denial audit when a trusted workspace is available; no trusted scope means refusal without a cwd guess. Native async callbacks and PromiseLike results are refused, and callers must supply genuinely synchronous effects. These rows record AMC enforcement bookkeeping, not legal approval or maturity success.

The released hooks cover retention payload groups by session, blob unlinking with all current reference sessions, guard-event pruning, cache/log unlinking, scoped spill erasure, and direct spill-store purge/removal. A hold denial retains the data while other eligible groups or steps continue. Spill erasure reports `held` or `hold_unknown` as incomplete outcomes; they never count as successful removal. Guard pruning preserves its best-effort zero-return contract, so zero does not prove that hold evaluation succeeded.

Console cache pruning touches only `.amc/studio/console-snapshot.json` and its `.sig`; it does not recurse through Studio seal, lease or session data. Doctor's stale-cache cleanup also gates each `.amc/cache` unlink using its trusted workspace. A denial reaches the existing `FAILED` action report instead of being swallowed as an empty cache. Dry-run still skips the fix, and ordinary filesystem errors keep their previous best-effort handling. A denial on a later file can follow earlier admitted removals. Broken-symlink cleanup remains deferred.

Direct spill APIs cannot establish every signed reference from an object's owning session alone. They therefore check workspace-wide spill holds, even when a lifecycle caller also checked its authenticated session list. This can retain additional unrelated spill objects. Other destructive routes are explicitly deferred in `scripts/deletion-executors.json`; an inventory row is not an executed acceptance result.

For retention blobs, admission is acknowledged before the evidence database's immediate transaction. Inside that transaction, the executor rereads the complete ordered reference snapshot and retains the blob if it differs from the admitted snapshot or is no longer eligible. Only a matching snapshot proceeds to unlink while both the hold lock and database write lock remain held. A skipped transaction writes `RETENTION_BLOB_DELETE_SKIPPED` afterward, with `removed: false` and its reason; the admission row does not establish deletion. This avoids calling the audit's separate database connection while holding the write transaction. Filesystem publication outside that transaction, uncoordinated imports, rollback after unlink and concurrent-reference qualification remain open; SQLite rollback cannot restore deleted bytes.

The current register allows 1,024 total modern/legacy rows, with 64 KiB records and 16 KiB signature snapshots. Writers require POSIX ownership. Host-local checkpoints do not establish portable legal trust, and the same OS user can still tamper with that external checkpoint store. Retention minimums, physical-region validation, a legal reviewer, portable checkpoint migration and executable qualification remain separate work.
