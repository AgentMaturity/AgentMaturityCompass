### Why this matters

Citations drift faster than reviewers can check them: superseded instruments, mislabelled framework IDs and mappings that name packs which do not exist all shipped. P0-24 fixes today's errors once; this check stops new ones from merging. It also makes the strategy's "law as data" rule enforceable, so P1-09's control records start from a validated format.

### Goal

`npm run check:citations` runs in CI and the release gate. It fails on any broken pack reference, malformed framework ID or invalid status type, and on any new citation that is superseded, unresolvable or incomplete. Existing gaps sit in a committed baseline that can only shrink.

### Scope

**In:** the citation record type, one shared host list, the rules, a ratchet baseline, the CLI script, CI and release-gate wiring, the 11 pack-id fixes and 3 `related.packs` fixes, tests. **Out:** correcting citation text (P0-24); full control records and law-as-data migration of every citation (P1-09); currency review windows (S5's check stays as is); expert review of content (D-08).

New `src/compliance/citations/` (`citationRecord.ts`, `officialHosts.ts`, `supersededInstruments.ts`, `frameworkIds.ts`, `lint.ts`, `reference/*.json`); `src/domains/packs/regulatorySchema.ts` (re-export the shared host list; add optional citation fields to `RegulatoryInstrument`); `src/domains/industryPackAudit.ts` (export `INDUSTRY_PACK_AUDIT_ANCHORS` read-only, no value changes); `src/compliance/builtInMappings.ts` (pack-id lines only); new `scripts/check-citations.mjs` and `scripts/citations-baseline.json`; `package.json` scripts; `.github/workflows/ci.yml` (`build-test` job); `scripts/release-gate.mjs`; `docs/COMPLIANCE_MAPS.md` or a new `docs/CITATIONS.md`; tests.

### Step-by-step

1. Branch `rtd/p0-25-citation-lint` from `origin/main` after P0-12 (and P0-02, which lands the dirty `ci.yml`, `release-gate.mjs` and `package.json`).
2. Write the fixture tests first (below).
3. `citationRecord.ts`: export `CITATION_STATUS_TYPES = ["binding-now", "binding-future", "draft", "supervisory-guidance", "voluntary-standard", "contractual", "conformity-scheme"] as const` and a zod `citationRecordSchema` with `instrument`, `clause`, `edition`, `jurisdiction`, `statusType`, `effectiveDate` and `complianceDueDate` (ISO date or `null` with `dateNote`), `url`, and `retrievedAt` or `contentSha256` (at least one). Add the same fields as optional properties of `RegulatoryInstrument`. Do not derive `statusType` from S3's `status`; whoever writes a record sets it.
4. `officialHosts.ts`: one list, the union of S3's `OFFICIAL_SOURCE_HOSTS` and the register's `policy.officialHosts`. `regulatorySchema.ts` re-exports it. A test asserts the register's `policy.officialHosts` is a subset.
5. `supersededInstruments.ts`: entries `{ id, pattern, replacement, note }` for OMB M-24-10 (M-25-21), SR 11-7 (SR 26-2), EO 14110 (revoked), EEOC AI technical assistance (withdrawn; re-verify), 21 CFR 820.30 (21 CFR 820.10, QMSR), ICH E6(R2) (E6(R3)), Directive 2003/98 (Directive 2019/1024). These come from the strategy and the F5 review; add nothing else without a source.
6. `frameworkIds.ts`: formats `^AML\.T\d{4}(\.\d{3})?$` (ATLAS), `^(GOVERN|MAP|MEASURE|MANAGE) \d+\.\d+$` (NIST AI RMF) and `^A\.\d+(\.\d+)?$` (ISO/IEC 42001 Annex A). Reference tables: `reference/nistAiRmf.json` (every subcategory id and title, extracted by the agent from the official NIST AI 100-1 PDF, with `url`, `retrievedAt`, `sha256`); `reference/atlas.json` (technique ids and names from the official ATLAS data release, same fields); `reference/iso42001AnnexA.json` (empty until the expert supplies clause ids and labels; the standard is paywalled). Pair rules from the strategy: prompt injection must be `AML.T0051`; an ISO/IEC 42001 `A.5` anchor must not be labelled as AI policy.
7. `lint.ts`: pure `lintCitations(input): CitationFinding[]`, where a finding is `{ rule, file, location, message, zeroTolerance: boolean }`. Rules:
  - `CIT001 superseded-as-live`: a pack `regulatoryRef`, rubric `regulatoryRef`, registry basis, mapping description or anchor matches a superseded pattern, and its record is not `repealed` or superseded with `supersededBy`. Ratcheted until P0-24 flips it to zero tolerance.
  - `CIT002 framework-id`: a malformed ID is zero tolerance; an ID missing from a filled reference table, or a broken pair rule, is ratcheted until P0-24 and the expert finish.
  - `CIT003 pack-reference`: every `requires_assurance_pack.packId` resolves exactly in `listAssurancePacks()`; every `related.packs` entry resolves after lower-casing and removing `-` and `_`; every `assurancePacks` id in the domain registry and every unprefixed register `affectedPacks` id resolves. Zero tolerance.
  - `CIT004 record-incomplete`: a reference that does not resolve to a catalogue record, or a record missing a required field, or a URL off the shared host list. Ratcheted.
  - `CIT005 status-type`: a `statusType` outside the seven values, or a superseded or repealed record without `supersededBy`. Zero tolerance.
8. Fix the data so zero-tolerance rules pass: copy the 11 `packId` corrections exactly from `git show de349beed -- src/compliance/builtInMappings.ts` (only the `packId` lines); fix `compound_threats` to the registered `compoundThreat`; remove `host_hardening` and `mcp_security_resilience` from `related.packs` (registering a pack is out of scope under the freeze) and list both in the PR as a follow-up.
9. `scripts/check-citations.mjs` loads the built `dist/` modules (as `scripts/gen-counts.mjs` does), runs `lintCitations`, compares with `scripts/citations-baseline.json` (`{ rules: { CIT001: { zeroTolerance: false, counts: { "<file>": n } } }, reason, updatedAt }`) and prints `citations: errors=<n> ratcheted=<n> baseline=<n>`. Flags: `--json`, `--update-baseline --reason "<text>"`. It exits 1 on any zero-tolerance finding, on a ratcheted count above its baseline, or on an unknown flag (match S5's strict `parseArgs`).
10. Add `"check:citations": "node scripts/check-citations.mjs"`; run it after the build in the `build-test` job of `.github/workflows/ci.yml`; add `builtStep("citations", "npm", ["run", "check:citations"], { remediation: "Fix citation findings, or update scripts/citations-baseline.json with a reviewed reason." })` after the build in `scripts/release-gate.mjs`.
11. Document the rules, the baseline policy and how to add a record in `docs/CITATIONS.md`; add a changeset.

### Risks and gotchas

- A ratchet can hide debt. Keep `--update-baseline` behind a required reason and make the CLI print the per-rule totals on every run.
- Do not invent reference data. The NIST and ATLAS tables must record the URL, retrieval date and file hash they came from; the ISO table stays empty until an expert fills it.
- The checker reads `dist/`, so it must run after `pnpm run build` (in the release gate, use `builtStep`).
- `builtInMappings.ts` also changes in S6 (P1-45). Touch only the pack-id lines to keep that rebase small.
