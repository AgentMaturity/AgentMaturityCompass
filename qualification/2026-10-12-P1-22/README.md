# P1-22 qualification: AMC Pi extension at Pi's tool_call hook

Recorded on a local macOS arm64 machine, not in CI, after merging `int` (P1-08 purpose keys), the independent review fixes and the per-call disk recheck (no-follow descriptors, fail closed). AMC commit `d57b730575ccbfc6713dc935e5cb1b4722ac2a10`.

- Qualified: the `pi` CLI of `@earendil-works/pi-coding-agent` 1.0.2 (gitHead `cd32f772`) and 1.0.4 (gitHead `7c10bd43`), installed from the public npm registry with `--ignore-scripts` into scratch prefixes outside the repository; tarball integrity and the resolved `@earendil-works/*` dependencies are in `pi-conformance.json`, which `receipt.json` hashes. Not qualified: 1.1.0 (AMC denies it) and Pi embedded through its SDK.
- Conformance: `tests/conformance/piToolCall.conformance.test.ts`, 22/22, driven by a local scripted model endpoint on loopback (no live model). Each installation bound the Pi install under test, each Pi session registered with AMC before its first call (checked against that install on disk), and the claim `amc connect hooks status` reported read `enforced_at_pi_tool_call`. An `@`-prefixed `read` ran, a `read` through a symlink into `.amc` was denied, and an extension tool registered under the built-in name `find` was denied before it ran. The untrusted-project run registered nothing. Per-case results per version are in `pi-conformance.json` and rendered into `docs/adapters/pi.md`.
- Focused suites 229/229 and suites covering the other changed modules 185/185 at the same commit.
- Mutation checks: 32. Twenty from the earlier rounds, one per guard (request binding, receipt signature, input freeze, version gate, server-derived action id, single-use nonce, ask denial, mapping table and its prototype-name guard, event shape, record binding, fail closed, mint/parse kind agreement, receipt purpose key pin, five on session registration). Ten from the review round (Pi's `@` prefix, symlink following, Pi install and extension file measured at registration, stale claims after drift or reinstall, freezing before sending, built-in detection on both sides, the ops receipt key pin), and two on the per-call recheck of the extension and Pi on disk (no recheck; a reader that follows a final symlink). Each failed at least one test, then the code was restored.
- Decision latency (extension handler to result through the loopback Bridge), full run: p50 204.7 ms (1.0.2) and 197.5 ms (1.0.4), p95 293.1 ms and 303.2 ms (n = 100 each), far above the 50 ms p95 overhead target, on a heavily loaded machine (load average 7 to 14). The latency case alone on Pi 1.0.4 in the same session gave p50 111.7 / p95 154.9 ms with the previous recheck and p50 92.9 / p95 161.8 ms with this one: the rise is load, not the code. The per-call disk recheck alone measured p50 1.49 ms and p95 2.81 ms warm.

What this supports: AMC's decisions at Pi's `tool_call` hook were honoured by these two Pi releases in these cases, for sessions that registered with AMC. Every call rechecks the installed extension file, AMC's module and the Pi install against the registration (each file read from a descriptor opened without following symlinks; a per-process digest cache keyed on that descriptor's dev, inode, size, mtime and ctime). A changed, renamed, deleted, unreadable or symlinked file, or any stat or read error, denies the call as not governed. A registration is a lease-holder attestation: registration made with the session lease and matching on-disk extension and Pi digests. A process holding the lease can still attest without Pi. AMC cannot prove Pi executed the hook; it can prove only that every allowed call went through AMC with a signed receipt. This does not cover OS containment, effects outside `tool_call`, an extension that rewrites Pi's tool registry, or a Pi that does not load the extension: AMC cannot see sessions where Pi did not load the extension; they are reported as not governed (the untrusted-project case shows a write running with no AMC decision and no registration). Pi ask is always denied until an AMC approval path exists. Decision and registration receipts are signed with the workspace's own receipt purpose key: a local audit trail, not a portable verdict.
