# P1-22 qualification: AMC Pi extension at Pi's tool_call hook

Recorded on a local macOS arm64 machine, not in CI, after merging `int` (P1-08 purpose keys). AMC commit `faac56b00c66198c2832125a8b0270902d21c40d`.

- Qualified: the `pi` CLI of `@earendil-works/pi-coding-agent` 1.0.2 (gitHead `cd32f772`) and 1.0.4 (gitHead `7c10bd43`), installed from the public npm registry with `--ignore-scripts` into scratch prefixes outside the repository; tarball integrity and the resolved `@earendil-works/*` dependencies are in `pi-conformance.json`, which `receipt.json` hashes. Not qualified: 1.1.0 (AMC denies it) and Pi embedded through its SDK.
- Conformance: `tests/conformance/piToolCall.conformance.test.ts`, 18/18, driven by a local scripted model endpoint on loopback (no live model). Each Pi session registered with AMC before its first call, and AMC's claim for it read `enforced_at_pi_tool_call`; the untrusted-project run registered nothing. Per-case results per version are in `pi-conformance.json` and rendered into `docs/adapters/pi.md`.
- Focused suites 214/214 and suites covering the other changed modules 159/159 at the same commit.
- Mutation checks: 20, one per guard (request binding, receipt signature, input freeze, version gate, server-derived action id, single-use nonce, ask denial, mapping table and its prototype-name guard, event shape, record binding, fail closed, mint/parse kind agreement, receipt purpose key pin, and five on session registration); each failed at least one test, then the code was restored.
- Decision latency (extension handler to result through the loopback Bridge): p50 46.2 ms (1.0.2) and 55.9 ms (1.0.4), p95 62.2 ms and 76.1 ms (n = 100 each), above the 50 ms p95 overhead target. Another worktree's test runs were active on the machine.

What this supports: AMC's decisions at Pi's `tool_call` hook were honoured by these two Pi releases in these cases, for sessions that registered with AMC. It does not cover OS containment, effects outside `tool_call`, or a Pi that does not load the extension: AMC cannot see sessions where Pi did not load the extension; they are reported as not governed (the untrusted-project case shows a write running with no AMC decision and no registration). Pi's ask is always denied until an AMC approval path exists. Decision and registration receipts are signed with the workspace's own receipt purpose key: a local audit trail, not a portable verdict.
