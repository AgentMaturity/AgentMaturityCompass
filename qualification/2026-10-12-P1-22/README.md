# P1-22 qualification: AMC Pi extension at Pi's tool_call hook

Recorded on a local macOS arm64 machine, not in CI, after merging `int` (P1-08 purpose keys) and the independent review fixes. AMC commit `7b0978ca7a7dd9c51845e9a1ce49674e1362542e`.

- Qualified: the `pi` CLI of `@earendil-works/pi-coding-agent` 1.0.2 (gitHead `cd32f772`) and 1.0.4 (gitHead `7c10bd43`), installed from the public npm registry with `--ignore-scripts` into scratch prefixes outside the repository; tarball integrity and the resolved `@earendil-works/*` dependencies are in `pi-conformance.json`, which `receipt.json` hashes. Not qualified: 1.1.0 (AMC denies it) and Pi embedded through its SDK.
- Conformance: `tests/conformance/piToolCall.conformance.test.ts`, 22/22, driven by a local scripted model endpoint on loopback (no live model). Each installation bound the Pi install under test, each Pi session registered with AMC before its first call (checked against that install on disk), and the claim `amc connect hooks status` reported read `enforced_at_pi_tool_call`. An `@`-prefixed `read` ran, a `read` through a symlink into `.amc` was denied, and an extension tool registered under the built-in name `find` was denied before it ran. The untrusted-project run registered nothing. Per-case results per version are in `pi-conformance.json` and rendered into `docs/adapters/pi.md`.
- Focused suites 227/227 and suites covering the other changed modules 185/185 at the same commit.
- Mutation checks: 30. Twenty from the earlier rounds, one per guard (request binding, receipt signature, input freeze, version gate, server-derived action id, single-use nonce, ask denial, mapping table and its prototype-name guard, event shape, record binding, fail closed, mint/parse kind agreement, receipt purpose key pin, five on session registration). Ten from the review round (Pi's `@` prefix, symlink following, Pi install and extension file measured at registration, stale claims after drift or reinstall, freezing before sending, built-in detection on both sides, the ops receipt key pin). Each failed at least one test, then the code was restored.
- Decision latency (extension handler to result through the loopback Bridge): p50 60.3 ms (1.0.2) and 60.8 ms (1.0.4), p95 81.9 ms and 74.5 ms (n = 100 each), above the 50 ms p95 overhead target. Another worktree's test runs were active on the machine.

What this supports: AMC's decisions at Pi's `tool_call` hook were honoured by these two Pi releases in these cases, for sessions that registered with AMC. A registration is a lease-holder attestation: registration made with the session lease and matching on-disk extension and Pi digests. A process holding the lease can still attest without Pi. AMC cannot prove Pi executed the hook; it can prove only that every allowed call went through AMC with a signed receipt. This does not cover OS containment, effects outside `tool_call`, an extension that rewrites Pi's tool registry, or a Pi that does not load the extension: AMC cannot see sessions where Pi did not load the extension; they are reported as not governed (the untrusted-project case shows a write running with no AMC decision and no registration). Pi ask is always denied until an AMC approval path exists. Decision and registration receipts are signed with the workspace's own receipt purpose key: a local audit trail, not a portable verdict.
