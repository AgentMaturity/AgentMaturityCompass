# P1-23 qualification: Claude Code hooks govern sessions (Claude Code 2.1.296)

Recorded on a local macOS arm64 machine (Darwin 25.6.0, macOS 26.6.2, Node v22.23.3), not in CI, at AMC commit `8f11b73fa144e3d58df744409e7236d0b962968a` (branch `rtd/p1-23-claude-code-hooks` after the independent review and merging `int` at `8d6c9b744`). The machine was heavily loaded by other work (load average 17 to 21 during the final runs).

- **Qualified:** Claude Code 2.1.296, installed from the public npm registry into a scratch prefix outside the repository (`@anthropic-ai/claude-code` and `@anthropic-ai/claude-code-darwin-arm64`; integrity and the native binary's SHA-256 are in `claude-code-conformance.json`). The hooks reference and settings pages it relies on are pinned by SHA-256 in `docs/source-reviews/P1-23-claude-code-hooks.md`. Linux packages are pinned, not run against AMC; Windows is not verified.
- **Conformance** (`tests/conformance/claudeCodeHooks.conformance.test.ts`, 7/7): the real `claude` binary in `-p` mode, model replies from a scripted loopback endpoint, outbound network denied by `sandbox-exec`. An allowed Read ran after AMC's verified allow, answered as an empty response so Claude Code's own permissions still applied (claim `enforced_at_claude_code_pretooluse`, lifecycle completed, no authorization mismatch). A non-pure Bash command, a Write needing approval (no ask), an MCP tool and a Write of `.claude/settings.json` were denied and had no effect. A foreign PreToolUse hook that could rewrite input left the session unregistered, so its Read was denied. A frozen workspace blocked the prompt before any model request. With the Bridge stopped the call was blocked. 217 decision and observation rows verified cold, 0 failures.
- **Latency**: the installed PreToolUse handler spawned 200 times against a loopback Bridge. Conformance run at the final commit: p50 1,198.4 ms, p95 2,066.5 ms. Dist-only script (`latency.json`) at the earlier commit `c8a9907b4`: macOS arm64 p50 681.5 / p95 1,249.3 ms; Linux arm64 (offline container in a colima VM on the same loaded host) p50 1,322.2 / p95 2,727.4 ms. At lower load on an earlier commit: macOS 566 / 680 ms, Linux 670 / 768 ms. All far above the 50 ms target; most of it is starting Node and AMC's modules per call.
- **Fixtures** (`fixtures.json`): SHA-256 of the 17 payloads recorded from the 2.1.296 binary under `tests/fixtures/harness-hooks/claude-code/2.1.296/`.
- **Focused suites:** 72 files at this commit, 841 passed, 3 failed and 4 skipped, all on load timing (10 s hook set-up timeouts and P0-42's 9 s wall-clock bound); rerun with two workers, 29/30, the one left at 9,253 ms against the 9 s bound. Commands and totals are in `receipt.json`.
- **Mutation checks:** 25 for the review rounds, each failing at least one test before the code was restored: no pure-form Bash refusal; release schema skipped; latch never read; replayed observation accepted; glob containment by segment only; unbound observation accepted; conflicting observation dropped; narrowed matcher accepted; forwarder ignores its event; byte-order mark accepted; non-NFC Bash accepted; memory-only latch; latch tripped outside a registration; no intake backpressure; eviction of counters that hold state; an allow answered without `claudeAllow`; and, from the independent review, a search root holding `.amc`, an allow carrying a permission decision, enabled plugins ignored, Bash words naming `.amc`, a refusal episode keyed on the pending shed, an unbound configuration directory, skills and agents not rechecked at decisions, path folding removed, and a PreToolUse payload answered by its handler's event alone.

What this supports: for these cases, Claude Code 2.1.296 honoured AMC's PreToolUse answers, and AMC's forwarder answered allow only for a signed decision bound to the exact payload bytes, nonce, session and `tool_use_id` of a registered session. A registration is a lease-holder attestation; AMC cannot prove Claude Code ran a hook, and sessions without one are not governed. Decision and observation receipts are signed with the workspace's own receipt key: a local audit trail, not a portable verdict.

Reproduce: install Claude Code 2.1.296 into a scratch prefix with `npm install --ignore-scripts @anthropic-ai/claude-code@2.1.296 @anthropic-ai/claude-code-darwin-arm64@2.1.296`, `npm run build`, then `AMC_CLAUDE_CODE_CONFORMANCE=1 AMC_CLAUDE_CODE_PREFIX=<prefix> AMC_CLAUDE_CODE_CONFORMANCE_OUT=<file> npx vitest run tests/conformance/claudeCodeHooks.conformance.test.ts`.
