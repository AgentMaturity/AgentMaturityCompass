# P1-22 follow-up qualification: Pi's evidence latch, repeat and intake rules

Recorded on a local macOS arm64 machine, not in CI, at AMC commit `86da8c341c9c750578c74b6a50d0eef4b30528b0` (branch `rtd/p1-22f-pi-audit-latch` after merging `int` 67d0eef0a), Node 22. Other worktrees' test runs were active (load average about 20).

- Pi: the `pi` CLI of `@earendil-works/pi-coding-agent` 1.0.2 and 1.0.4, from the install recorded in `qualification/2026-10-12-P1-22` (tarball integrity and resolved `@earendil-works/*` dependencies are repeated in `pi-conformance.json`, which `receipt.json` hashes).
- Conformance: `tests/conformance/piToolCall.conformance.test.ts`, 24/24 (12 cases per version), local scripted model endpoint on loopback. New for this follow-up, per version: an allowed `read`'s `tool_result` reached the control route and was recorded bound to its decision (`authorizationMismatch: false`, no conflict); a fault of AMC's writer on that outcome row latched the workspace, the next real Pi call was blocked (`AMC control unavailable; action denied.`), and after the owner's recovery with the vault passphrase a call ran again. All earlier cases still hold; 124 Pi rows per version verified cold.
- Focused and covering suites: 250/250 in 20 files, `tests/piAuditLatch.test.ts` included.
- Mutation checks: 7, run before merging `int` on the same Pi and hook sources, each killed by `tests/piAuditLatch.test.ts` and then restored (listed in `pi-conformance.json`): an outcome writer fault never or always counted as under a registration (rules 1 and 5), control mode recording outcomes at the observed ingress only (rule 2, the original gap), the client counting a 409 as recorded and the server answering any repeat as the same observation (rule 3), Pi decisions ignoring intake backpressure and Pi registrations escaping the cap (rule 4).
- Decision latency (extension `tool_call` handler to its result): p50 57.5 / p95 77.1 ms (1.0.2) and p50 59.1 / p95 101.2 ms (1.0.4), n = 100 each, above the 50 ms p95 target, on a loaded machine.

What this supports: with these two Pi releases, a fault of AMC's own writer while recording a registered session's outcome or registration latches the workspace in AMC home, and every later Pi call is blocked until the owner recovers; a 409 never counts as recorded; outcomes over a cap deny decisions instead of being dropped. It does not cover an outcome the Bridge never received (an unreachable Bridge latches nothing), OS containment, or anything P1-22's record already excludes. Receipts are signed with the workspace's own receipt purpose key: a local audit trail, not a portable verdict.
