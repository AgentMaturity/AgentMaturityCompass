## P0-21 · Use typed score units and one methodology; no certification from self-assessment

**Gate** G0 · **Epic** E02 Truth reset: claims, scoring and citations · **Priority** High · **Due** 2026-10-22 · **Effort** M (1–3 person-weeks) · **Route** Agent-Doable · **Tags** Bug

**Blocked by** P0-08, P0-12, P0-15 · **Blocks** P0-22, P0-23, P1-16, P1-42, GATE-G0 · **Old Linear issues** none · **Plan refs** gap G22 (High: packs certify by arithmetic and score units disagree); design rule 1 "Evidence beats answers" (self-declared answers cap at L1; today's core bank accepts self-reported evidence up to L3); contract truth rule 4 (no "certified" outside a registry-issued attestation)

### Why this matters

Answering 5 to every question of an industry pack sets `certified: true`, and MCP prints "Certified: ✅ Yes" (G22). The domain engine reads a raw 5 as 100% but a raw 6 as 6%. Six more modules derive "certified", "certification readiness" or a certified badge from arithmetic, and the diagnostic bank lets self-reported evidence reach L3. P0-22 and P0-23 can only label surfaces honestly once these fields stop claiming certification and every number has one unit.

### Goal

Every score is a typed unit with explicit conversions and one level table; no field or string says "certified", "certification ready" or "MCP-Certified" for a self-computed result; self-declared answers are `self_reported`, cap at L1 and never yield a positive regulated status; one methodology section states all of this.

### Scope

**In:** branded units and converters; the domain engine, pack scoring, pack audit and `--score` parsing; replacing every certification field above, including the minimum MCP and transparency rendering changes needed to compile; the L1 cap for self-reported evidence in the diagnostic gates; docs and tests. **Out:** claim labels on surfaces (P0-22, P0-23); signing pack audits (P0-20); rebuilding gates from runtime evidence and cumulative levels (P1-07); fabricated domain inputs (P0-15); the O17 tools (P1-44).

### Step-by-step

Target unit API for `src/score/units.ts` (step 3):

```ts
declare const brand: unique symbol;
type Brand<T, B extends string> = T & { readonly [brand]: B };
export type Likert1to5 = Brand<number, "Likert1to5">;
export type Percent0to100 = Brand<number, "Percent0to100">;
export type Level0to5 = Brand<number, "Level0to5">;
export type Fraction0to1 = Brand<number, "Fraction0to1">;
export function likert(n: number): Likert1to5;          // integer 1-5, else RangeError
export function percent(n: number): Percent0to100;       // 0-100, else RangeError
export function level(n: number): Level0to5;             // integer 0-5, else RangeError
export function fraction(n: number): Fraction0to1;       // 0-1, else RangeError
export function likertToPercent(x: Likert1to5): Percent0to100;   // (x - 1) / 4 * 100
export function percentToLevel(p: Percent0to100): Level0to5;     // the one level table
```
