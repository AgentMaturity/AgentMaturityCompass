# P1-19 independent oracle source proposal

These two files are a private, unexecuted source proposal. No repository file, product process, SQL connection, test, parser, compiler, server or CLI was run while authoring them. The root must review, admit and apply the exact files after the tests-only missing-oracle baseline. Both files are below 800 lines.

The wire contract is the preserved `interface-proposal.json` with the separate `interface-clarification.json`. The four positional arguments remain `<cli> <workspace> <case-file> <provider-run-dir>`. Stdin selects a unique case through the existing `2026-09-08` comparison envelope. Adapter stdout, success strings, claimed monitor fingerprints and `verified:true` values are not authority. An operator-owned manifest outside both verified roots supplies pre-recorded public keys, exact Node/CLI/case byte pins, real workspace/provider paths, explicit fixture identity, the reviewed tools-config hash and the actual approval/preimage directories. Approval and preimage paths must stay strictly beneath the real workspace.

`providerRunDir` may be the actual closed provider directory or a byte-exact public log/checkpoint copy made by the trusted test launcher only after provider streams and PID close. The test evidence must distinguish those paths and preserve original/copy hashes. The oracle reads neither tokens nor admin endpoints. Provider logs are locally written SHA chains, not external signatures or protection against a same-UID attacker rewriting both the history and checkpoint.

`oracle.mjs` always emits all 16 fixed check IDs and a pass only if each is true. It checks provider canonical JSON, strict UTF-8, final newline, sequence, predecessor, row hash and checkpoint; exact POST/commit totals; duplicate tenant/reference or tenant/key groups; actual normalized bodies and field lists; and the complete set of effects. A missing, ambiguous or unsupported proof fails explicitly. It refuses the older normative generic/provider hash-equality strings instead of silently rewriting their meaning. Expected compliance dimensions fail until a real evaluator exists; cases without such expectations receive an explicitly not-requested check, not a compliance status.

The oracle launches the exact pinned `session verify --expect-monitor … --json` command itself. The child inherits the frozen outer process group, receives only explicit PATH, HOME, TMPDIR, AMC_HOME and NO_COLOR values, and is never detached or signalled. Natural `close` includes both streams. Output capture is bounded at 1 MiB per stream while excess output is drained; overflow, stream errors, invalid JSON/UTF-8, nonzero/signal exit, known late-error banners or absent PID-ESRCH evidence fail the check. A five-second bounded signal-0 probe checks the child PID only. The outer root wrapper separately owns and proves its PGID. A child that never closes remains unresolved; there is no early success, retry, timeout kill or cleanup claim. The returned check contains bounded structured process/verifier facts and capture hashes; it does not claim separately retained full raw nested CLI streams.

The cold CLI checks all ledger event hash/signature/payload links, signed receipt integrity and session seals against the pinned current monitor plus its authenticated history. The oracle binds that result to exact DB/WAL presence, file identity, size and SHA before the CLI and after independent action extraction, together with the same public key/history files. SHM is reported as coordination evidence and may change. This relies on the fixture's independently demonstrated producer/pool closure and a trusted pinned CLI runtime; it is not an atomic hostile-filesystem snapshot or a proof against deliberate same-UID ABA mutation. The root's source/dependency preservation supplies the CLI build context, not an untrusted driver-selected executable.

`oracleEvidence.mjs` imports only Node built-ins and the existing `better-sqlite3` dependency. It opens the actual existing SQLite database read-only, begins one read transaction, selects bounded action/index/evidence rows, then rolls back the read transaction and closes the connection. It never imports AMC or provider code, initializes a store, uses `openActionJournal`, performs recovery or mutates a journal. It independently verifies canonical action receipt bytes and zero-based chain links, allowed transitions, index head, complete inline payloads, action-specific v2 members, reconciliation predecessor and durable intent. It deliberately delegates writer/v2/session-seal cryptography to the actual cold verifier bound to those same raw bytes. Pruned, archived or non-inline ACTION_STATE proof is refused rather than reconstructed permissively.

Authorization preimages are untrusted until the canonical full record hashes to the genuine receipt's `AMC_AUTHZ_V1` plus NUL digest and the generic normalized-envelope digest matches its action/intent. The fixed flat finance envelope independently projects to the strict provider payment body; both digests are recomputed separately. Integer cents map exactly to canonical decimal strings using BigInt. The provider body strips only the extra bound amount/resource facts. The reviewed signed tools-config hash fixes the binding-field interpretation without importing a YAML parser or a second general-purpose normalizer.

Auditor signatures over exact config, request, decision and consumption bytes are independently verified with the external auditor key. The oracle recounts actual execute decisions with allowed roles, required quorum, distinct users, stable request binding, time bounds and consumed execution ID. It never accepts the current `CONSUMED` status as a shortcut for quorum. Principal IDs, policy digests, intent bindings, session/call/execution/key and provider payment ID must agree. Those are genuine locally signed fixture identities, not authentication of external people or legal authority.

The first positive is deliberately narrow: ordinary EXECUTE, a scoped single agent, native adapter ID, real default-P102 grant, depth zero, no lease/delegation/exception or compiled-policy substitution, canonical USD finance envelope, full recorder evidence and a naturally closed provider. Other shapes fail closed. This proposal is not a general authority-store verifier. A signed `outcome_unknown` can contribute explicitly qualified coverage, but it cannot clear the matching-completed-receipt check. Every actual provider commit is counted; missing proof never becomes zero unauthorized effects by omission. For denied, no-effect cases a genuine denied chain is still required.

Tests must prove that the positive passes every check and each negative fails its intended check. In particular, a provider-only/missing-receipt fixture must still have valid owned empty preimage/approval directories, and must pass input/provider/count/minimal-payload checks before failing receipt/authorization/effect checks. Rehashed duplicate or mismatched histories are deliberate semantic negative data; original provider logs stay immutable. The test producer shares only this documented wire, never the oracle's verification functions.
